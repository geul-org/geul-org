# 목표

*인류의 캐시 인프라를 4단계까지 끌어올린다.*

---

## 현재 상태: 0%

캐시가 실제로 히트를 서빙한 적은 한 번도 없다.
아직 아무것도 작동하지 않는다.
존재하는 것은 설계 의도와 부분적 명세뿐이다.

### 존재하는 것

- geul.org 사이트 (Hugo, 퍼블릭)
- /why 시리즈 18편 (왜 필요한가에 대한 논증)
- 동사 코드북 초안 (verb qualifier 체계)
- SIDX 코드북 초안 (위키데이터 P31/P279 기반 비트 할당)
- DFC 논문 초안 (부동시간점 비트마스크 시간 검색)
- 두 개의 세계 선언문 (SSOT-present / SSOT-absent 철학)
- MASON 기존 구현 (XML → Go 코드 생성, 작동 확인됨)

### 존재하지 않는 것

- GEUL 인코더 (자연어 → GEUL)
- GEUL 디코더 (GEUL → 자연어)
- SIDX 완성 코드북 (현재 상위 타입만)
- DFC 참조 구현 및 벤치마크
- Faber Edge 구현
- MASON-GEUL 통합
- 실제 작동하는 캐시 시스템
- 캐시 미스 감지 및 해결 메커니즘
- 메타규칙 추출 엔진

---

## 4단계 정의

```
1단계  추론한다           매번 처음부터. 매번 휘발.
2단계  결과를 캐시한다     지식의 영구화. 같은 것을 두 번 추론하지 않는다.
3단계  방법을 캐시한다     규칙의 영구화. 같은 유형을 두 번 판단하지 않는다.
4단계  방법의 방법을       메타규칙의 영구화. 규칙 자체가 스스로 개선된다.
       캐시한다
```

현재 인류의 캐시 인프라: 구글 (2단계, 키워드 매칭)
목표: 4단계 (메타규칙 자동 생성 및 축적)

---

## 누가 하는가

| 구간 | 주체 | 성격 |
|------|------|------|
| 0 → 70% | 박준우 (1인) | 설계. 전체 구조가 한 사람 머릿속에 있어야 한다. |
| 70 → 99% | 표준화 재단 | 확장. 문법 확장, 코드북 채움, 다국어, 엣지 케이스. |
| 99 → 99.999999% | AI | 자동화. 캐시 미스 감지/해결/규칙 생성을 자동으로. |
| 99.999999% → | S1+ | 미해결. 남은 빈칸의 난이도가 우주적. |

## 0 → 70% 로드맵: 박준우가 해야 하는 일

### Phase 1: 증명 (0 → 15%)

목표: GEUL이 작동한다는 것을 증명한다.

**1-1. GEUL 문법 완성**
- 동사 코드북 확정 (verb qualifier 전체 체계)
- Triple Edge 문법 확정 (주어-술어-목적어 + 메타데이터)
- Event6 Edge 문법 확정 (6하원칙 이벤트)
- Verb Edge 문법 확정 (동사 한정자 기반 주장)
- 문법 명세서 작성 (geul.org/grammar)

**1-2. SIDX v1**
- 위키데이터 P31 상위 500 타입 비트 할당 완료
- P279 계층 트리 변환 완료
- 16비트 엔티티 식별자 인코딩/디코딩 구현
- 비트마스크 검색 구현 및 벤치마크
- 논문: SIDX 코드북 설계 및 비트마스크 검색 성능

**1-3. DFC v1**
- 참조 구현 (인코딩/디코딩)
- DFC vs Unix timestamp 벤치마크
- SIDX + DFC 결합 비트마스크 검색 벤치마크
- 논문: 부동시간점 비트마스크 기반 다해상도 시간 검색

**1-4. 인코더 프로토타입**
- 제한된 도메인 (예: 위키피디아 인물 정보)
- 자연어 문장 → GEUL 표현 변환
- 정확도 측정 및 오류 분석
- 논문: 자연어에서 구조화된 인공 언어로의 인코딩

**Phase 1 완료 기준**: 자연어 문장을 넣으면 GEUL로 인코딩되고, 비트마스크로 검색되고, 다시 자연어로 디코딩된다. 엔드투엔드 작동.

---

### Phase 2: 파이프라인 (15 → 35%)

목표: 컨텍스트 엔지니어링 파이프라인이 작동한다.

**2-1. 검증기 (Verifier)**
- 구조적 완전성 검사 (필수 필드 존재)
- 식별자 유효성 검사 (SIDX 코드북 대조)
- 타입 적합성 검사 (술어-목적어 타입 매칭)
- 참조 무결성 검사 (엔티티 간 참조 유효성)

**2-2. 필터 (Filter)**
- 관련성 판단 (쿼리 대비 정보 필요도)
- 신뢰도 필터 (출처/확신도 기반)
- 시간 필터 (DFC 비트마스크 기반 범위 필터)
- 필터 정책 정의 언어

**2-3. 정합성 검사기 (Coherence Checker)**
- 시간적 모순 감지 (같은 엔티티, 다른 시점, 충돌 값)
- 출처 간 모순 감지 (같은 속성, 다른 출처, 다른 값)
- 추론적 모순 감지 (합산 불일치 등)
- 모순 해결 전략 (시간 우선, 출처 신뢰도 우선 등)

**2-4. 탐색기 (Navigator) 프로토타입**
- 계층적 인덱스 맵 생성
- 맵 레이어별 윈도우 적합성 보장
- 에이전트 기반 다단계 탐색
- B-tree 원리의 지식 탐색 적용

**Phase 2 완료 기준**: 대량의 GEUL 데이터에서 쿼리를 넣으면, 검증 → 필터 → 정합성 검사 → 탐색을 거쳐 정제된 컨텍스트가 나온다. RAG 대비 품질 비교 벤치마크.

---

### Phase 3: Faber Edge (35 → 50%)

목표: 캐시 미스 해결 방법을 코드로 캐시한다.

**3-1. Faber Edge 타입 시스템**
- Triple/Event6/Verb Edge = 세계에 대한 주장 (Claim)
- Faber Edge = 주장에서 추출한 실행 가능한 규칙 (Fact/SSOT)
- 그래프 내 선언과 실행의 공존

**3-2. MASON 통합**
- GEUL 그래프에서 패턴 감지
- 패턴 → MASON XML 규칙 자동 생성
- XML 규칙 → Go 코드 생성
- 생성된 코드의 GEUL 그래프 내 저장 (Faber Edge)

**3-3. 캐시 미스 해결 루프**
- 캐시 미스 감지 (쿼리 결과 없음 / 저확신)
- 미스 원인 분류 (데이터 부재 / 규칙 부재 / 연결 부재)
- 원인별 해결 전략 실행
- 해결 결과를 캐시에 등록 (데이터 또는 규칙)
- 해결 이력 기록

**Phase 3 완료 기준**: 캐시 미스가 나면 자동으로 원인을 분류하고, 해결하고, 해결 방법을 Faber Edge로 캐시한다. 같은 유형의 미스가 다시 나면 규칙이 즉시 처리한다.

---

### Phase 4: 증명 + 공개 (50 → 70%)

목표: 인류 캐시 인프라로서의 가치를 증명하고, 표준화 가능한 상태로 공개한다.

**4-1. 벤치마크 스위트**
- GEUL 컨텍스트 vs 자연어 RAG 품질 비교
- SIDX + DFC 비트마스크 vs 기존 DB 인덱스 성능 비교
- 캐시 히트율 추이 (시간에 따른 미스 감소율)
- Faber Edge 규칙 생성 후 동일 유형 미스 재발율

**4-2. 논문 시리즈**
- SIDX: 코드북 설계 + 비트마스크 검색
- DFC: 다해상도 시간 검색
- 인코더: 자연어 → GEUL 변환
- 파이프라인: 검증-필터-정합성-탐색 통합 성능
- Faber Edge: 캐시 미스 자동 해결 메커니즘
- 비교: GEUL 컨텍스트 품질 vs RAG 컨텍스트 품질

**4-3. 공개 및 문서화**
- GEUL 문법 명세 (geul.org/grammar)
- SIDX 코드북 명세 (geul.org/dictionary)
- 파이프라인 API 명세
- Faber Edge + MASON 통합 명세
- 기여 가이드 (표준화 재단 준비)

**4-4. 4단계 설계 문서**
- 캐시 미스 해결 이력 분석 메커니즘
- 미스 패턴의 패턴 추출 알고리즘
- 선제적 규칙 생성 메커니즘
- GEUL 자기 문법 확장 프로토콜
- MASON 자기 규칙 개선 프로토콜
- 4단계 구현은 하지 않는다. 설계만 한다. 구현은 AI와 재단의 일이다.

**Phase 4 완료 기준**: 논문이 인용되고, 코드가 공개되고, 명세가 문서화되어 있고, 기여 가이드가 있어서 다른 사람들이 이어받을 수 있다. 4단계 설계가 존재하여 AI가 자동화할 방향이 보인다.

## 70% 이후: 박준우의 역할 변화

70%까지는 설계자.
70% 이후는 캐시 미스 생성기.

표준화 재단이 코드북을 채우고 문법을 확장할 때, "이 방향은 막다른 길이다" "이 영역이 비어있다"를 짚어주는 역할. AI가 자동화를 돌릴 때, AI가 구조적으로 못 보는 방향에서 질문을 던지는 역할.

설계자에서 S0로.
구축하는 사람에서 질문하는 사람으로.

## 최종 비전

```
인간이 질문한다
  → GEUL이 인류 캐시를 탐색한다 (O(log n))
  → 히트: 즉시 구조화된 답을 돌려준다
  → 미스: AI가 추론하고, 결과를 캐시에 등록한다
  → 미스 해결 방법을 규칙으로 캐시한다 (Faber Edge)
  → 미스 패턴에서 메타규칙을 추출한다 (4단계)
  → 캐시가 성장한다
  → 다음 질문에 더 빠르게 답한다
  → 반복
  → 복리
```

인류의 모든 질문이 캐시를 키우고,
캐시의 성장이 다음 질문의 품질을 높이고,
높아진 질문이 또 캐시를 키우는 순환.

이 순환이 영구적으로 돌 때,
그것이 4단계 인류 캐시 인프라다.
