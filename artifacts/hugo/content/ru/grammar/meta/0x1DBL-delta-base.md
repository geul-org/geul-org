## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `version` | #2 | простое значение 2 WORD | `0620` UNSIGNED-INTEGER |  |

Маркер того, что этот файл версии является не снимком, а **diff** относительно базовой версии того же документа (delta в git packfile). Сама версия по-прежнему определяется как снимок. Хеш содержимого, список версий и подписи — всё это относится к снимку, восстановленному применением diff ([Хранение diff](../document.md#diff-저장)).

## Раскладка {#레이아웃}

```
TAG WORD          0001 1101 1011 LLLL      Codec 0x1DBL
ID версии         2 WORD unsigned (базовая версия того же документа)
```

- Codec: Meta `0x1DBL`, класс родословной
- Payload: ID версии 2 WORD (простое значение)
- Количество: не более одного

## Интерпретация и валидность {#해석과-유효성}

- Используется только в документах с [DOC-ID](0x1C7L-doc-id.md). В списке версий `versions.geul`, документах-списках (версии `issuers/`) и безымянных документах, где `DOC-ID` не ставится, diff не используется.
- Базовая версия — опубликованная версия с тем же `DOC-ID`, предшествующая этой версии. `0` (нет версии) — invalid.
- Хеш содержимого восстановленного снимка должен совпадать с хешем этой версии в списке версий ([PUBLICATION](../edge/0x0B8L-publication.md)). Если не совпадает, этот diff invalid. Поэтому итоговый хеш внутри diff отдельно не записывается.
- В виде diff может храниться только документ, у которого все записи BODY являются Edge (записями с Edge Id). Это потому, что единица diff — LOCAL ID (Edge Id).
- Правила восстановления снимка следуют [Хранению diff](../document.md#diff-저장). Удаление берёт на себя [DELTA-REMOVE](0x1DCL-delta-remove.md).
- Отдельных маркеров добавления и редакции нет. Если Edge Id из BODY diff есть в базе, это редакция, если нет — добавление. Добавление получает номер, начиная с [NEXT-LOCAL-ID](0x1DDL-next-local-id.md) списка версий. Повторное использование удалённого LOCAL ID — invalid ([Редакция](../document.md#개정)).

## Пример {#예시}

diff относительно базовой версии 3:

```
1DB2 0000 0003
```

- TAG `1DB2` (Meta `0x1DBL`, `LLLL=0010`, 3 WORD), ID версии `0000 0003`.

## Открытые проблемы {#열린-문제}

1. Интервал снимков: через сколько версий ставить полный снимок (длина цепочки diff и стоимость восстановления).
2. Ограничивать ли базовую версию непосредственно предыдущей.
3. Место хранения файла diff: класть ли его на место файла версии (`<ID версии>.geul`); связь с адресом по хешу содержимого `<Issuer>/hashes/` (`hashes/` ищется по хешу содержимого снимка).

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001DB0/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001DB000000000
BODY
#1 DECLARE 0x1DB0
#2 FIELD #1 0x0002
#3 BIND #1 "DELTA-BASE"
#4 BIND #2 "version"
#5 CODEC #2 0x0620
```
