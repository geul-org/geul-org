## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `digest` | #2 | запись | `07C0` SHA-256-DIGEST |  |

Указывает хеш содержимого предыдущей версии (git parent).

## Раскладка {#레이아웃}

```
TAG WORD          0001 1101 0001 LLLL      Codec 0x1D1L
[Length — расширяющий TAG]
Payload           один SHA-256-DIGEST Value (16 WORD)
```

- Codec: Meta `0x1D1L`, класс родословной
- Payload: встроенный Value ([SHA-256-DIGEST](../value/0x07CL-sha-256-digest.md))
- Количество: может быть несколько (слияние)

## Интерпретация и валидность {#해석과-유효성}

- Если записи нет, это первая версия, если их несколько — слияние (git merge commit).
- Входит в [хеш содержимого](../document.md#내용-해시), поэтому вся история образует цепочку хешей.
- Документ списка версий указывает на предыдущий документ списка ([PUBLICATION](../edge/0x0B8L-publication.md)).
- Формат дайджеста встроен как Value, что оставляет возможность сменить алгоритм хеширования. Сейчас хеш содержимого — только SHA-256.

## Пример {#예시}

- `0x1D1E 0x0014 0x07CE 0x0012 <16 WORD>` (Meta 20 WORD = TAG + расширение Length + встроенный Value 18 WORD)

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001D10/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001D1000000000
BODY
#1 DECLARE 0x1D10
#2 FIELD #1 record
#5 CODEC #2 0x07C0
#3 BIND #1 "PARENT"
#4 BIND #2 "digest"
```
