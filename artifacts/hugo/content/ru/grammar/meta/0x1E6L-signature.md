## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `algorithm` | #2 | простое значение 1 WORD |  | `0x0001` ed25519 |
| 2 | `signer` | #3 | запись | `0400` ISSUER-POINTER |  |
| 3 | `signature` | #4 | остаток, простое значение (`0xFFFF`) |  |  |

Подпись хеша содержимого документа (подписанные коммиты и теги git).

## Раскладка {#레이아웃}

```
TAG WORD          0001 1110 0110 LLLL      Codec 0x1E6L
[Length — расширяющий TAG]
ID алгоритма      1 WORD (0x0001 = Ed25519)
Подписывающий     запись Reference ISSUER-POINTER (Issuer)
Подпись           всё оставшееся. Ширину задаёт алгоритм (Ed25519 32 WORD)
```

- Codec: Meta `0x1E6L`, класс проверки
- Payload: ID алгоритма (простое значение 1 WORD) + подписывающий (встроенный Reference) + подпись (простое значение, остаток)
- Количество: может быть несколько

## Интерпретация и валидность {#해석과-유효성}

- Подписывается хеш содержимого. Один только BODY не подписывается ([Подпись](../issuer.md#서명)).
- Поскольку это класс проверки, она исключается из хеша содержимого. Добавление подписи хеш не меняет.
- Проверка устроена не как «если подпись есть, проверить», а как «подпись заданного ключа обязана быть».
- Документ списка версий подписывает публикующая сторона.
- Подписывающий — [ISSUER-POINTER](../reference/0x040L-issuer-pointer.md) (Issuer), указывающий на самого Issuer. Поскольку это запись Reference, заканчивающаяся своим Length, раскладка однозначна, даже если ширина подписи у разных алгоритмов разная (остаточное поле [DECLARE](../edge/0x0BBL-declare.md)).
- Если число WORD подписи отличается от ширины, заданной алгоритмом, это invalid.

## Открытые проблемы {#열린-문제}

- Подписывать ли вместе с этим момент подписания.

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001E60/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001E6000000000
BODY
#1 DECLARE 0x1E60
#2 FIELD #1 0x0001
#3 FIELD #1 record
#11 CODEC #3 0x0400
#4 FIELD #1 rest
#5 ENUM #2 0x0001
#6 BIND #1 "SIGNATURE"
#7 BIND #2 "algorithm"
#8 BIND #3 "signer"
#9 BIND #4 "signature"
#10 BIND #5 "ed25519"
```
