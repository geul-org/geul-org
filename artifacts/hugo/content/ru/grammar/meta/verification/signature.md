Подпись хеша содержимого документа (подписанные коммиты и теги git).

## Раскладка

```
TAG WORD          0001 1LLL L100 0001      Codec 0x41
[Length-расширенный TAG]
ID алгоритма      1 WORD (0x0001 = Ed25519)
Подписант         запись Reference ISSUER-POINTER(Issuer)
Подпись           весь остаток. Ширину определяет алгоритм (Ed25519: 32 WORD)
```

- Codec: Meta `0x41`, класс проверки (`100`)
- Payload: ID алгоритма (сырое значение, 1 WORD) + подписант (встроенный Reference) + подпись (сырое значение, остаток)
- Количество: может быть несколько

## Интерпретация и валидность

- Подписывается хеш содержимого. Подписывается не только BODY ([Подпись](/ru/grammar/issuer/#подпись)).
- Это класс проверки, поэтому он исключается из хеша содержимого. При добавлении подписи хеш остаётся прежним.
- Проверка идёт не по принципу «если подпись есть, проверить», а по принципу «должна быть подпись с заданным ключом».
- Документ списка версий подписывает публикующая сторона.
- Подписант -- [ISSUER-POINTER](/ru/grammar/reference/issuer-pointer/) (Issuer), указывающий на самого Issuer. Это запись Reference, она заканчивается по собственной Length, поэтому раскладка определяется однозначно, даже если ширина подписи у разных алгоритмов разная (остаточное поле [DECLARE](/ru/grammar/edge/declare/)).
- Если число WORD подписи не совпадает с шириной, заданной алгоритмом, это invalid.
