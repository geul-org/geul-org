## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `profile` | #2 | запись | `0720` UTF8-TEXT-EVEN, `0730` UTF8-TEXT-ODD |  |

Объявляет профиль, применённый к документу. Те же записи интерпретируются по документам Codec, заданным профилем (например, для `tangeul-1.0` — [TOULMIN](../toulmin/_index.md)).

## Раскладка {#레이아웃}

```
TAG WORD          0001 1100 0110 LLLL      Codec 0x1C6L
[Length — расширяющий TAG]
Payload           UTF8-TEXT Value "<имя>-<major>.<minor>"
```

- Codec: Meta `0x1C6L`, класс объявления
- Payload: встроенный Value ([UTF8-TEXT](../value/0x072L-utf8-text.md))
- Количество: не более одного

## Интерпретация и валидность {#해석과-유효성}

- Профиль с другим major отвергается. Различие в minor допускается (только добавочные изменения).
- Если профиля нет, документ читается только по базовой грамматике GEUL и спецификациям прямых кодов.

## Пример {#예시}

- `tangeul-1.0`: `0x1C67 0x0736 7461 6E67 6575 6C2D 312E 3000`

## Открытые проблемы {#열린-문제}

- Реестр имён профилей (geul.org) и правила именования.
- Указывать ли профиль по ID документа (IMPORT) или хранить текстом.

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001C60/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001C6000000000
BODY
#1 DECLARE 0x1C60
#2 FIELD #1 record
#3 BIND #1 "PROFILE"
#4 BIND #2 "profile"
#5 CODEC #2 0x0720
#6 CODEC #2 0x0730
```
