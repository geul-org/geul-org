## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `name` | #2 | запись | `0720` UTF8-TEXT-EVEN, `0730` UTF8-TEXT-ODD |  |
| 2 | `target` | #7 | запись | `07C0` SHA-256-DIGEST, `0000` ABSENT (необязательное поле) |  |

Указывает неизменяемое имя, присвоенное версии (git annotated tag).

## Раскладка {#레이아웃}

```
TAG WORD          0001 1101 1010 LLLL      Codec 0x1DAL
[Length — расширяющий TAG]
Имя               UTF8-TEXT-* Value
Цель              SHA-256-DIGEST Value либо маркер пропуска 0x0000 (необязательное поле). Если пропущена — эта версия
```

- Codec: Meta `0x1DAL`, класс родословной
- Payload: встроенный Value (текст + необязательный хеш содержимого)
- Количество: может быть несколько

## Интерпретация и валидность {#해석과-유효성}

- Имя — [UTF8-TEXT](../value/0x072L-utf8-text.md), цель — [SHA-256-DIGEST](../value/0x07CL-sha-256-digest.md).
- Если цель пропущена (ABSENT `0x0000`, необязательное поле [CODEC](../edge/0x0BEL-codec.md)), имя присвоено самому этому документу. Собственный хеш содержимого внутри себя записать нельзя. Спецификация geul.org `0x1DA0` — это два поля-записи: name (`0720`, `0730`) и target (`07C0`, `0000`).
- Одно и то же имя повторно для другой версии не используется.

## Пример {#예시}

- Имя `v1`, эта версия: `1DA3 0721 7631 0000`

## Открытые проблемы {#열린-문제}

- Нужен ли TAG при наличии ID версии (порядкового номера).

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001DA0/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001DA000000000
BODY
#1 DECLARE 0x1DA0
#2 FIELD #1 record
#3 BIND #1 "TAG"
#4 BIND #2 "name"
#5 CODEC #2 0x0720
#6 CODEC #2 0x0730
#7 FIELD #1 record
#8 BIND #7 "target"
#9 CODEC #7 0x07C0
#10 CODEC #7 0x0000
```
