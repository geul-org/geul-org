DOC-1WORD, DOC-2WORD и DOC-4WORD — структурные Meta, которые открывают документ, задавая общее число WORD документа.

| Пункт | Значение |
|---|---|
| Имя | `DOC-4WORD` (BIND документа спецификации `DOC-4WORD`) |
| TAG ID | `0x1C2L` |
| Codec ID | `0x00001C20` |
| Документ спецификации | `0x00000000/codecs/0x00001C20/` (цель DECLARE `1C20`) |
| Раздел | 14 `1110` (Meta), смещение в разделе C = 2 |
| Kind | Meta · класс: структура |
| TAG WORD | `0001 1100 0010 LLLL` (`000K KKKC CCCC LLLL`) |
| Описание в индексе | начало документа, общая длина которого задана в Payload в 4 WORD |
| Сторона Hugo | `meta/structure/doc.md` (там также описаны [DOC-1WORD](0x1C0L-doc-1word.md), [DOC-2WORD](0x1C1L-doc-2word.md)) |

## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `count` | #2 | простое значение 4 WORD |  |  |

Запись, открывающая документ. В Payload задаётся общее число WORD документа. На этой странице вместе описаны `DOC-1WORD` (`0x1C0L`), `DOC-2WORD` (`0x1C1L`) и `DOC-4WORD` (`0x1C2L`).

## Раскладка {#레이아웃}

```
TAG WORD          0001 1100 0000 LLLL      Codec 0x1C0L
[Length — расширяющий TAG]
Payload           общее число WORD. Ширину задаёт Codec: DOC-1WORD 1, DOC-2WORD 2, DOC-4WORD 4
```

- Codec: Meta `0x1C0L~0x1C2L`, класс структуры
- Payload: простое значение (общее число WORD документа, unsigned)
- Количество: по одному на документ, в самом начале

## Интерпретация и валидность {#해석과-유효성}

- Длина отсчитывается от начала открывающей записи до конца [END](0x1C4L-end.md).
- Используется самая узкая ширина, в которую помещается значение. Кодирование более широким полем отвергается как неканоническое.
- Длина должна совпадать с длиной всего входа. Один документ — один вход.
- По этой длине декодер может пропустить весь документ. Codec, открывающего документ без известной длины, нет.
- При вычислении хеша содержимого запись переписывается с длиной без Meta класса проверки и с соответствующей ей шириной ([Хеш содержимого](../document.md#내용-해시)).

## Пример {#예시}

- `0x1C01 0x0017`: DOC-1WORD, всего 23 WORD

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001C20/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001C2000000000
BODY
#1 DECLARE 0x1C20
#2 FIELD #1 0x0004
#3 BIND #1 "DOC-4WORD"
#4 BIND #2 "count"
```
