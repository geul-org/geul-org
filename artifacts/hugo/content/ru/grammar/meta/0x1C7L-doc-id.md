## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `doc` | #2 | запись | `0410` DOC-POINTER, `0420` CODEC-POINTER |  |

Объявляет идентификатор этого документа. Он нужен, чтобы другие документы могли указывать на этот документ и на объекты в нём.

## Раскладка {#레이아웃}

```
TAG WORD          0001 1100 0111 LLLL      Codec 0x1C7L
[Length — расширяющий TAG]
Документ          запись Reference DOC-POINTER. (Issuer, ID документа, версия 0). Для документа Codec — CODEC-POINTER
```

- Codec: Meta `0x1C7L`, класс объявления
- Payload: один встроенный Reference [DOC-POINTER](../reference/0x041L-doc-pointer.md) (Issuer, ID документа, версия 0)
- Количество: не более одного. Для документов версий под `docs/<ID документа>/` и `codecs/<Codec ID>/` обязателен

## Интерпретация и валидность {#해석과-유효성}

- Payload — ровно одна запись Reference `DOC-POINTER` (Issuer, ID документа, версия `0`). В качестве ID версии используется только `0`. Версию назначает не документ, а список версий. Для документа Codec используется `CODEC-POINTER` (Issuer, Codec ID, версия `0`) ([CODEC-POINTER](../reference/0x042L-codec-pointer.md)).
- Поэтому запись, указывающая на «этот документ», одинакова в DOC-ID, в записи PUBLICATION списка версий и в цитатах из других документов.
- Один и тот же документ независимо от версии имеет один и тот же `DOC-ID`. ID версии и хеш содержимого в документе не пишутся ([Версия](../document.md#버전)).
- Адреса по имени документа нет ([Адреса публикации и список версий](../publishing.md#문서-이름)). Заголовок для чтения человеком берёт на себя Edge-высказывание [LABEL](../edge/0x0A4L-label.md).
- Если его нет, документ безымянный, и указать на него можно только по хешу содержимого. Он нужен, чтобы другой документ мог указывать на LOCAL этого документа через указывающий Reference.
- Сторона, получающая документ, проверяет, что `DOC-ID` полученного документа совпадает с запрошенными Issuer и ID документа.
- ID документа `0x0000000000000000` — это индексный документ определений терминов Issuer ([Issuer](../issuer.md)). Он тоже является документом версии под `docs/<ID документа>/`, поэтому в нём ставится DOC-ID (`DOC-POINTER` (Issuer, `0`, `0`)). Самого Issuer представляет [ISSUER-POINTER](../reference/0x040L-issuer-pointer.md).
- Документы версий `<ID версии>.geul` (включая документы спецификации) под `<Issuer>/docs/<ID документа>/` и `<Issuer>/codecs/<Codec ID>/` в `.well-known/geul/` обязаны иметь `DOC-ID`.
- Документы-списки — исключение, `DOC-ID` в них не ставится: список версий `versions.geul` ([PUBLICATION](../edge/0x0B8L-publication.md)) и версия `<ID версии>.geul` списка Issuer `issuers/` ([Адреса публикации и список версий](../publishing.md#목록-문서)). Чей это список, говорит DOC-POINTER в записи. Версию документа-списка указывает PUBLICATION в его `versions.geul` через DOC-POINTER (`0x00000000`, зарезервированный ID документа, ID версии). Адрес по хешу содержимого `<Issuer>/hashes/` — копия перечисленных выше документов и следует оригиналу.
- ID документа `0xFFFFFFFFFFFFFFFF` зарезервирован у всех Issuer (как и `0x0000000000000000`) и используется для списка Issuer у Issuer `0x00000000`. Другие Issuer его не используют. Поскольку у документов-списков нет `DOC-ID`, это значение встречается только в DOC-POINTER записей `issuers/versions.geul`.
- Документ спецификации Codec — это документ Codec у GEUL Issuer `0x00000000`. ID документа у него нет, а в качестве `DOC-ID` ставится CODEC-POINTER (`0x00000000`, Codec ID, `0`). Codec ID — это Kind и Codec TAG WORD, записанные в 32 битах (`0x0B80` → `0x00000B80`) ([документ спецификации](../codec-spec.md)).

## Пример {#예시}

- Issuer `0x00000002`, документ `0x…0005`: `1C79 0418 0000 0002 0000 0000 0000 0005 0000 0000` (Meta TAG 1 + Reference TAG 1 + Issuer 2 + ID документа 4 + версия 2 = 10 WORD)

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001C70/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001C7000000000
BODY
#1 DECLARE 0x1C70
#2 FIELD #1 record
#5 CODEC #2 0x0410
#3 BIND #1 "DOC-ID"
#4 BIND #2 "doc"
#6 CODEC #2 0x0420
```
