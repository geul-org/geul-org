Указывает LOCAL ID, который следующая версия этого документа назначит новому описанию (auto increment в СУБД, `AUTO_INCREMENT` в MySQL). Все LOCAL ID, назначенные в любой версии документа, меньше этого значения.

## Раскладка

```
TAG WORD          0001 1LLL L011 1100      Codec 0x3C
Payload           LOCAL ID, назначаемый следующим, unsigned целое наименьшей ширины
```

- Codec: Meta `0x3C`, класс родословной (`011`)
- Payload: сырое значение (unsigned целое наименьшей ширины)
- Количество: не более одного
- Где размещается: HEAD документа списка версий `versions.geul` ([PUBLICATION](/ru/grammar/edge/publication/))

## Интерпретация и валидность

- LOCAL ID (включая Edge Id) -- идентичность, переходящая между версиями ([Редакция](/ru/grammar/document/#редакции)). Новое описание получает это значение, и значение увеличивается на 1. Удалённый LOCAL ID не используется повторно. Поэтому, даже если удалено описание с максимальным значением, это значение не уменьшается.
- LOCAL ID `0` не назначается, поэтому начальное значение -- `1`. Пока версий нет, эта Meta не указывается, и следующий номер -- `1`.
- Публикующая сторона обновляет и записывает его в новом документе списка при публикации версии. Оно должно быть больше любого LOCAL ID, использованного в опубликованных версиях. Если меньше или равно, это invalid.
- Значение только растёт. Если оно меньше значения в предыдущем документе списка ([PARENT](/ru/grammar/meta/lineage/parent/)), это invalid.
- В документах без управления версиями (без `versions.geul`, безымянных) его нет. У таких документов нет и diff ([DELTA-BASE](/ru/grammar/meta/lineage/delta-base/)).
- В тексте документа (документ версии) оно не указывается. Запоминание номера -- не содержимое документа, а состояние публикующей стороны, продолжающей документ (в терминах git -- не коммиты, а refs).

## Пример

Следующий назначаемый номер 524:

```
18BC 020C
```

- TAG `18BC` (Meta `0x3C`, `LLLL=0001`, 2 WORD), Payload `020C`.
