Указывает, как другое представление было преобразовано в этот документ (например, конвертер Wikidata, кодировщик естественного языка). Tool -- чем преобразовано, Version -- по каким исходникам этого инструмента преобразовано. Только при наличии обоих можно заново получить тот же документ из того же входа.

## Раскладка

```
TAG WORD          0001 1LLL L011 0011      Codec 0x33
[Length-расширенный TAG]
Tool              1 запись Reference (инструмент или правила преобразования)
Version           1 запись Value (SHA-256-DIGEST или SHA1-DIGEST)
```

- Codec: Meta `0x33`, класс родословной (`011`)
- Payload: встроенный Reference (инструмент) + встроенный Value (дайджест версии исходников)
- Количество: может быть несколько (по одному на инструмент)

## Интерпретация и валидность

- Tool -- ровно одна полная запись Reference. Можно использовать любой Reference, указывающий на инструмент.
  - Инструмент из документа инструментов geul.org: [EXTERNAL-ISSUER](/ru/grammar/reference/external-issuer/) (`0x0000`, ID документа `0x0001xxxx xxxxxxxx`, его LOCAL). На один инструмент -- один документ (документ определений терминов [Issuer](/ru/grammar/issuer/)).
  - Если кодек сам является документом GEUL, этот документ указывается через [DOC-POINTER](/ru/grammar/reference/doc-pointer/).
- Version -- ровно одна полная запись Value, ID объекта системы управления версиями для исходников Tool. Для git это полный ID объекта коммита.
  - Если формат объектов git-репозитория SHA-256, используется [SHA-256-DIGEST](/ru/grammar/value/binary/sha-256-digest/) (`0x61`, 16 WORD), если SHA-1 -- [SHA1-DIGEST](/ru/grammar/value/binary/sha1-digest/) (`0x62`, 10 WORD). Формат репозитория проверяется командой `git rev-parse --show-object-format`.
  - Сокращённые ID (например, `2bd496f`) не используются. Value дайджеста не допускает усечённых значений.
  - Не записывается как hex-текст (UTF8-TEXT). То же значение занимает 22 WORD при SHA-1 (в бинарном виде 11) и 34 WORD при SHA-256 (в бинарном виде 18).
- Version обязательна. Запись об инструменте с неизвестной версией исходников не может служить основанием воспроизводимости. Для инструмента вне системы управления версиями используется SHA-256 дистрибутива (SHA-256-DIGEST).
- Version указывает на закоммиченные исходники. Для документа, созданного из рабочего дерева с незакоммиченными изменениями, ID этого коммита не используется (рекомендуется, чтобы инструмент отказывался запускаться).
- Если инструмент опирается на код вне репозитория (например, локальную библиотеку, указанную через Go `replace`), этот код тоже записывается отдельно через TRANSFORMED-BY. Одного ID коммита инструмента недостаточно, чтобы этот код был определён.
- Инструмент, который лишь без потерь переносит исходные данные (например, инструмент, загружающий дамп в БД как есть), не определяет содержимое документа и потому не записывается. Загрузка с потерями изменяет документ, поэтому записывается как инструмент.
- Спецификация документа geul.org (`0x1833`) записывается полем из двух записей: Tool (ширина 0, любой Reference, поэтому без CODEC) и Version (ширина 0, [CODEC](/ru/grammar/edge/codec/) `0861` и `0862`).

## Длина

```
всего = 1 + N_len + N_tool + N_version WORD
```

- Курсор после чтения последней записи должен точно совпадать с концом Meta.
- Если Tool -- EXTERNAL-ISSUER-1WORD (7 WORD), а Version -- SHA1-DIGEST (11 WORD), то всего 1 + 1 + 7 + 11 = 20 WORD, и используется расширенная длина. Для SHA-256-DIGEST (18 WORD) получается 27 WORD.

## Пример

Ненормативный пример. Инструмент -- LOCAL 2 (`0360 0000 0001 0000 0000 0001 0002`) из документа инструментов geul.org `0x0001000000000001`, исходники -- коммит `ddc0719974a32aaa7b422ee84221a9721085ce4c` (SHA-1).

```
1F33 0014
0360 0000 0001 0000 0000 0001 0002
0D62 ddc0 7199 74a3 2aaa 7b42 2ee8 4221 a972 1085 ce4c
```

## Открытые вопросы

- Стоит ли перевести версию в [GENERATED-BY](/ru/grammar/meta/lineage/generated-by/) на тот же способ (обязательный дайджест или другой формат). Версия модели не является ID коммита.
