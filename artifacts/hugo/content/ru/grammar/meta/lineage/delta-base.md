Маркер того, что файл этой версии -- не снимок (snapshot), а **diff** относительно базовой версии того же документа (delta в git packfile). Сама версия по-прежнему определяется как снимок. Хеш содержимого, список версий и подписи относятся к снимку, восстановленному применением diff ([Хранение diff](/ru/grammar/document/#хранение-diff)).

## Раскладка

```
TAG WORD          0001 1LLL L011 1010      Codec 0x3A
ID версии         2 WORD unsigned (базовая версия того же документа)
```

- Codec: Meta `0x3A`, класс родословной (`011`)
- Payload: ID версии в 2 WORD (сырое значение)
- Количество: не более одного

## Интерпретация и валидность

- Используется только в документах с [DOC-ID](/ru/grammar/meta/declaration/doc-id/) (документы, версии которых ведутся через список версий). Для `versions.geul`, `documents.geul` и `issuers.geul`, не ведущих версии, а также для безымянных документов diff не применяется.
- Базовая версия -- опубликованная версия с тем же `DOC-ID`, и она предшествует этой версии. `0` (версии нет) -- invalid.
- Хеш содержимого восстановленного снимка должен совпадать с хешем этой версии в списке версий ([PUBLICATION](/ru/grammar/edge/publication/)). Если не совпадает, этот diff invalid. Поэтому результирующий хеш внутри diff отдельно не записывается.
- Diff допускается только для документов, в которых все записи BODY -- Edge (записи с Edge Id). Это потому, что единица diff -- LOCAL ID (Edge Id).
- Правила восстановления снимка следуют разделу [Хранение diff](/ru/grammar/document/#хранение-diff). Удаление берёт на себя [DELTA-REMOVE](/ru/grammar/meta/lineage/delta-remove/).
- Отдельных маркеров добавления и правки нет. Если Edge Id из BODY diff есть в базе, это правка, если нет -- добавление. Добавленные записи получают номера начиная с [NEXT-LOCAL-ID](/ru/grammar/meta/lineage/next-local-id/) из списка версий. Повторное использование удалённого LOCAL ID -- invalid ([Редакция](/ru/grammar/document/#редакции)).

## Пример

diff относительно базовой версии 3:

```
193A 0000 0003
```

- TAG `193A` (Meta `0x3A`, `LLLL=0010`, 3 WORD), ID версии `0000 0003`.

## Открытые вопросы

1. Интервал снимков: через сколько версий делать полный снимок (длина цепочки diff и стоимость восстановления).
2. Ограничивать ли базовую версию непосредственно предыдущей.
3. Где хранить файл diff: на месте файла версии (`<ID версии>.geul`) и связь с хранилищем по адресу содержимого `h/` (`h/` ищется по хешу содержимого снимка).
