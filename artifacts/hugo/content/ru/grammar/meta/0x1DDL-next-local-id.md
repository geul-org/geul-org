## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `next` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

Указывает LOCAL ID, который следующая версия документа назначит новому высказыванию (auto increment в СУБД, MySQL `AUTO_INCREMENT`). Все LOCAL ID, назначенные в любой версии документа, меньше этого значения.

## Раскладка {#레이아웃}

```
TAG WORD          0001 1101 1101 LLLL      Codec 0x1DDL
Payload           LOCAL ID, назначаемый следующим, unsigned целое наименьшей ширины
```

- Codec: Meta `0x1DDL`, класс родословной
- Payload: простое значение (unsigned целое наименьшей ширины)
- Количество: не более одного
- Место размещения: HEAD документа списка версий `versions.geul` ([PUBLICATION](../edge/0x0B8L-publication.md))

## Интерпретация и валидность {#해석과-유효성}

- LOCAL ID (включая Edge Id) — идентичность, сохраняющаяся между версиями ([Редакция](../document.md#개정)). Новое высказывание получает это значение, и значение увеличивается на 1. Удалённый LOCAL ID повторно не используется. Поэтому даже если удалено высказывание с максимальным значением, это значение не уменьшается.
- LOCAL ID `0` не назначается, поэтому начальное значение — `1`. Если версий ещё нет, эта Meta не ставится, а следующий номер — `1`.
- Когда публикующая сторона публикует версию, она обновляет значение в новом документе-списке. Оно должно быть больше любого LOCAL ID, использованного в опубликованных версиях. Если меньше или равно — invalid.
- Значение только растёт. Если оно меньше значения в предыдущем документе-списке ([PARENT](0x1D1L-parent.md)), это invalid.
- В документах без управления версиями (документах без `versions.geul`, безымянных документах) её нет. Для таких документов diff ([DELTA-BASE](0x1DBL-delta-base.md)) тоже не ставится.
- В тело документа (документ версии) не ставится. Запоминание номера — это не содержимое документа, а состояние публикующей стороны, продолжающей документ (в git это не коммит, а сторона refs).

## Пример {#예시}

Следующий назначаемый номер 524:

```
1DD1 020C
```

- TAG `1DD1` (Meta `0x1DDL`, `LLLL=0001`, 2 WORD), Payload `020C`.

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001DD0/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001DD000000000
BODY
#1 DECLARE 0x1DD0
#2 FIELD #1 rest
#3 BIND #1 "NEXT-LOCAL-ID"
#4 BIND #2 "next"
```
