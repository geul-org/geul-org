Meta — это записи не о содержимом мира, а о документе. Все они, кроме записей структуры документа (DOC, BODY, END), ставятся в HEAD документа. В HEAD, помимо Meta, находятся также Edge основания для всего документа [SOURCE](../edge/0x0C0L-source.md#문서-전체의-출처) и его QUALIFIER.

## Раскладка {#레이아웃}

```
TAG WORD          000K KKKC CCCC LLLL      разделы 14, 15 (0x1C0L~0x1FFL)
[Length — расширяющий TAG]
Payload           простое значение либо встроенные записи Value и Reference
```

- У Meta нет формата Issuer. Meta — общая спецификация, которой следуют все Issuer, и определяет её только GEUL.
- `LLLL` — общее число WORD, включая TAG WORD, минус 1. Codec, которых нет в таблице, являются Reserved.

## Формат Payload {#payload-형식}

| Формат | Когда | Пример |
|---|---|---|
| простое значение | когда формат определён однозначно. Не опирается на другие Codec записей | длина `DOC-*`, `SPEC-VERSION`, `ISSUER-KEY` |
| встроенный Value | когда формат выбирается из нескольких. Формат сообщает TAG Value | `PROFILE`, `EFFECTIVE-*`, моменты времени, хеш содержимого |
| встроенный Reference | когда указывается объект вроде человека, организации, инструмента или документа | `DOC-ID`, `AUTHOR`, `CO-AUTHOR`, `RECORDED-BY`, `SIGNED-OFF`, подписывающий в `SIGNATURE` |
| нет | маркер в 1 WORD | `BODY`, `END` |

- Встроенные записи — не самостоятельные записи, а часть своей Meta. Каждая находит свою границу по Length, и позиция после чтения последней записи должна точно совпадать с концом Meta.
- Какие Meta могут стоять в документе только по одной, а какие — по нескольку, определяет пункт «Количество» в документе каждого Codec.

## Классы {#클래스}

Номера Meta идут подряд от `0x1C0L` без Reserved. Биты номера класса не обозначают. Класс определяется по таблице диапазонов ниже.

| Класс | Прямой код | Что охватывает |
|---|---|---|
| структура | `0x1C0L~0x1C4L` | границы и длина документа |
| объявление | `0x1C5L~0x1CAL` | объявления интерпретации |
| происхождение | `0x1CBL~0x1D0L` | кто, когда, где |
| родословная | `0x1D1L~0x1DDL` | от чего и как произошло |
| политика | `0x1DEL~0x1E3L` | как с этим обращаться |
| IMPORT | `0x1E4L` | импорт внешнего документа |
| проверка | `0x1E5L~0x1E9L` | можно ли доверять |
| Reserved (только для проверки) | `0x1EAL~0x1FFL` | |

- Класс проверки — это записи раздела 15 с `C >= 5`, то есть `w >= 0x1E50`. По этому признаку без кодбука определяется класс проверки, и такие записи исключаются из хеша содержимого.
- Последний Reserved `0x1EAL~0x1FFL` предназначен только для проверки. Новую Meta вне проверки перед проверкой поставить нельзя, а если поставить в последний Reserved, она будет исключена из хеша содержимого.
- Классы структуры, объявления и IMPORT по битам не читаются. Декодер узнаёт их по встроенной таблице номеров.
- **Meta, необходимые для интерпретации**: структура, объявление, IMPORT. Если их удалить, записи нельзя прочитать или интерпретация изменится. Обрабатывать их должен каждый декодер. Эти Codec входят в **базовый кодбук GEUL**.
- **Meta, не меняющие интерпретацию**: происхождение, родословная, проверка, политика. Если их удалить, содержимое высказываний останется прежним. Пропадает только материал для оценки доверия и порядка обращения.
- Основание записывается не Meta, а Edge основания [SOURCE](../edge/0x0C0L-source.md) и QUALIFIER. Основание отдельной записи ставится в BODY, а источник документа в целом — в HEAD как SOURCE с Target `0` ([Документ](../document.md#head와-body)).

## Структура {#구조}

Класс структуры Meta (Codec `0x1C0L~0x1C4L`) определяет границы и длину документа. Единица данных GEUL — один документ.

```
DOC-*                  ← начало HEAD
  Meta объявления, происхождения, родословной, проверки, политики, IMPORT
  SOURCE для всего документа и его QUALIFIER
BODY                   ← начало BODY
  Reference, Value, Edge
END                    ← закрытие документа
```

- Каждый документ открывается записью `DOC-1WORD/2WORD/4WORD` с заданием общей длины. По этой длине декодер может пропустить весь документ за один шаг.
- `BODY` и `END` — записи в 1 WORD без Payload. `END` обязательна.
- Документы не вкладываются. Другие документы указываются через IMPORT.
- Если HEAD (Meta, SOURCE для всего документа и его QUALIFIER) пуст, `BODY` опускается. `BODY` может стоять в документе только один раз.

Полная структура документа описана в [Документе](../document.md).

| Codec | Имя | Значение |
|---|---|---|
| `0x1C0L~0x1C2L` | [DOC-1WORD / 2WORD / 4WORD](0x1C0L-doc-1word.md) | открывает документ, задавая общую длину |
| `0x1C3L` | [BODY](0x1C3L-body.md) | завершает HEAD и открывает BODY |
| `0x1C4L` | [END](0x1C4L-end.md) | закрывает документ |

Подробные правила — в [Документе](../document.md).

## Объявление {#정의}

Класс объявления Meta (Codec `0x1C5L~0x1CAL`) — это объявления интерпретации. Объявление меняет правила интерпретации, поэтому обрабатывать его должен каждый декодер. Область действия объявления — этот документ.

- `SPEC-VERSION` определяет, как читать остальные записи, поэтому в ней стоит просто целое число, без встроенного Value. GEUL v1 — `0x0001` (запись `1C51 0001`).
- `DOC-ID` — это `DOC-POINTER` (Issuer, ID документа, версия `0`), указывающий на сам этот документ. Для документа Codec — `CODEC-POINTER` (Issuer, Codec ID, версия `0`). Если его нет, документ безымянный, и указать на него можно только по хешу содержимого.
- Адреса по имени документа нет. Заголовок для чтения человеком добавляется Edge-высказыванием `LABEL` ([Адреса публикации и список версий](../publishing.md#문서-이름)).

| Codec | Имя | Значение |
|---|---|---|
| `0x1C5L` | [SPEC-VERSION](0x1C5L-spec-version.md) | версия спецификации, которой следуют. Одно целое число |
| `0x1C6L` | [PROFILE](0x1C6L-profile.md) | применяемый профиль |
| `0x1C7L` | [DOC-ID](0x1C7L-doc-id.md) | идентификатор этого документа. DOC-POINTER (версия 0), указывающий на сам документ. Для документа Codec — CODEC-POINTER (версия 0) |
| `0x1C8L` | [EFFECTIVE-FROM](0x1C8L-effective-from.md) | дата вступления этой версии в силу. Если нет — момент публикации |
| `0x1C9L` | [EFFECTIVE-UNTIL](0x1C9L-effective-until.md) | конец срока действия этой версии (временный закон). Если нет — до вступления в силу следующей версии |
| `0x1CAL` | [DEFAULT-LANGUAGE](0x1CAL-default-language.md) | язык по умолчанию |

- Адреса по имени документа нет ([Адреса публикации и список версий](../publishing.md#문서-이름)). Заголовок для чтения человеком добавляется LABEL в BODY.

## Происхождение {#출처}

Класс происхождения Meta (Codec `0x1CBL~0x1D0L`) записывает, кто и когда создал и зафиксировал документ.

- Автор и фиксирующий, а также их моменты времени следуют модели author и committer в git (`AUTHOR` и `CREATED-AT`, `RECORDED-BY` и `RECORDED-AT`).
- Если происхождение удалить, содержимое высказываний не изменится. Пропадает только материал для оценки доверия.
- Первоисточников в этом классе нет. Источник документа в целом записывается в HEAD, а источник отдельной записи — в BODY как Edge основания [SOURCE](../edge/0x0C0L-source.md). Соответствующий диапазон в оригинале, момент получения и хеш оригинала — это QUALIFIER, прикрепляемые к этому SOURCE (страница P304, раздел P958, дата обращения P813, контрольная сумма P4092).
- Если свойства, относящиеся к источнику (диапазон в оригинале, момент получения), хранить как Meta, при нескольких источниках нельзя определить, к какому из них они относятся. Поэтому они записываются как QUALIFIER, у которого Target — SOURCE.

| Codec | Имя | Значение |
|---|---|---|
| `0x1CBL` | [AUTHOR](0x1CBL-author.md) | автор (Reference) |
| `0x1CCL` | [CO-AUTHOR](0x1CCL-co-author.md) | соавтор |
| `0x1CDL` | [CREATED-AT](0x1CDL-created-at.md) | момент создания |
| `0x1CEL` | [MODIFIED-AT](0x1CEL-modified-at.md) | момент изменения |
| `0x1CFL` | [RECORDED-BY](0x1CFL-recorded-by.md) | субъект, зафиксировавший документ |
| `0x1D0L` | [RECORDED-AT](0x1D0L-recorded-at.md) | момент фиксации |

- Первоисточники записываются не Meta, а Edge основания [SOURCE](../edge/0x0C0L-source.md#문서-전체의-출처) в HEAD (Target `0`), а диапазон в оригинале, момент получения и хеш оригинала — как QUALIFIER, прикрепляемые к этому SOURCE.

## Родословная {#계보}

Класс родословной Meta (Codec `0x1D1L~0x1DDL`) записывает, от чего и как произошёл документ. Родословная следует модели коммитов git, где единица, соответствующая коммиту, — документ.

- **Хеш содержимого** указывает содержимое одного экземпляра документа (git commit id). Это SHA-256 от открывающей записи (`DOC-*`) до записи непосредственно перед `END`, причём записи класса проверки (раздел 15, `C >= 5`, `w >= 0x1E50`) при вычислении исключаются.
- **ID версии** — 2-WORD целое число, нумеруемое от 1 в порядке публикации внутри именованного документа. `0` означает, что версия не указана.
- Meta родословной указывает версию по хешу содержимого. `PARENT` внутри документа тоже входит в хеш, поэтому хеш содержимого становится цепочкой хешей, связывающей всю историю.
- История не удаляется. Исправленное выпускается как новая версия. Изменяемые указатели вроде branch в документе не ставятся.
- `DELTA-BASE` и `DELTA-REMOVE` — формат, в котором версия хранится как diff относительно базовой версии. Версия всегда определяется как снимок.

Правила редакции — в [Документе](../document.md).

Родословная следует модели коммитов git. Единица, соответствующая коммиту, — документ.

| Codec | Имя | Значение |
|---|---|---|
| `0x1D1L` | [PARENT](0x1D1L-parent.md) | хеш содержимого предыдущей версии. Если несколько — слияние |
| `0x1D2L` | [DERIVED-FROM](0x1D2L-derived-from.md) | произведено от материала другой родословной |
| `0x1D3L` | [GENERATED-BY](0x1D3L-generated-by.md) | субъект-создатель (человек, модель, движок правил) |
| `0x1D4L` | [TRANSFORMED-BY](0x1D4L-transformed-by.md) | инструмент преобразования и версия его исходного кода (дайджест коммита) |
| `0x1D5L` | [CHERRY-PICKED-FROM](0x1D5L-cherry-picked-from.md) | исходная версия перенесённого изменения |
| `0x1D6L` | [REVERTS](0x1D6L-reverts.md) | версия, изменение которой отменено |
| `0x1D7L` | [REPLACES](0x1D7L-replaces.md) | переписанная версия. Исходная версия не удаляется |
| `0x1D8L` | [SQUASHED-FROM](0x1D8L-squashed-from.md) | исходные версии, объединённые в одну |
| `0x1D9L` | [MESSAGE](0x1D9L-message.md) | причина изменения. По одному на язык |
| `0x1DAL` | [TAG](0x1DAL-tag.md) | неизменяемое имя, присвоенное версии |
| `0x1DBL` | [DELTA-BASE](0x1DBL-delta-base.md) | этот файл — diff относительно базовой версии |
| `0x1DCL` | [DELTA-REMOVE](0x1DCL-delta-remove.md) | список LOCAL ID, убираемых в diff |
| `0x1DDL` | [NEXT-LOCAL-ID](0x1DDL-next-local-id.md) | LOCAL ID, назначаемый следующим. Ставится в документ списка версий |

- История не удаляется. Исправленное выпускается как новая версия.
- Изменяемые указатели вроде branch в документе не ставятся. Ими управляют хранилище и индекс.

## Проверка {#검증}

Класс проверки Meta (Codec `0x1E5L~0x1E9L`) записывает материал для оценки того, можно ли доверять документу. Это открытый ключ Issuer с самостоятельной выдачей, подпись, подтверждение права на вклад, степень доверия и результат вердикта по документу в целом.

- Класс проверки исключается из вычисления хеша содержимого. Поэтому ни помещение подписи в документ, ни добавление нескольких подписей хеш содержимого не меняют (так же, как `gpgsig` в git).
- Класс проверки — это записи раздела 15 с `C >= 5`, то есть `w >= 0x1E50`, поэтому хеш можно вычислить без кодбука. Последний Reserved `0x1EAL~0x1FFL` тоже предназначен только для проверки и исключается из хеша.
- Вердикт на уровне узла или записи берёт на себя Edge [TOULMIN](../toulmin/_index.md) `VERDICT` (`0x118L`).

| Codec | Имя | Значение |
|---|---|---|
| `0x1E5L` | [ISSUER-KEY](0x1E5L-issuer-key.md) | алгоритм подписи и открытый ключ Issuer с самостоятельной выдачей |
| `0x1E6L` | [SIGNATURE](0x1E6L-signature.md) | подпись хеша содержимого. Алгоритм, подписывающий, подпись |
| `0x1E7L` | [SIGNED-OFF](0x1E7L-signed-off.md) | подтверждение права на вклад |
| `0x1E8L` | [CONFIDENCE](0x1E8L-confidence.md) | степень доверия |
| `0x1E9L` | [VERDICT](0x1E9L-verdict.md) | результат вердикта по документу в целом (Pass, Review, Fail) |

- Класс проверки исключается из вычисления хеша содержимого. Поэтому ни помещение подписи в документ, ни добавление нескольких подписей хеш содержимого не меняют.

## Политика {#정책}

Класс политики Meta (Codec `0x1DEL~0x1E3L`) определяет, как обращаться с документом. Это лицензия, степень открытости, уровень персональных данных, срок хранения, согласие и ограничения использования.

- Политика не меняет интерпретацию, а определяет порядок обращения.
- Исходная лицензия произведений внутри байтовой последовательности записывается в `LICENSE`.

| Codec | Имя | Значение |
|---|---|---|
| `0x1DEL` | [LICENSE](0x1DEL-license.md) | лицензия |
| `0x1DFL` | [ACCESS](0x1DFL-access.md) | степень открытости |
| `0x1E0L` | [PRIVACY](0x1E0L-privacy.md) | уровень персональных данных |
| `0x1E1L` | [RETENTION](0x1E1L-retention.md) | срок хранения |
| `0x1E2L` | [CONSENT](0x1E2L-consent.md) | объём и основание согласия |
| `0x1E3L` | [USAGE](0x1E3L-usage.md) | ограничения использования |

- Политика не меняет интерпретацию, а определяет порядок обращения.

## IMPORT {#import}

Класс IMPORT Meta (Codec `0x1E4L`) импортирует внешний документ под IMPORT ID. Codec только один — `IMPORT-DOC` (`0x1E4L`).

- IMPORT импортирует только документ. Объекты внутри импортированного документа указываются в BODY через Reference `EXTERNAL-POINTER-*` (IMPORT ID, LOCAL ID) ([Reference](../reference/_index.md)).
- Если указан ID версии, привязка идёт к этой редакции, если `0` — к последней на момент интерпретации. Опубликованные документы указывают версию.
- HEAD импортированного документа не импортируется. Записи Reference и Value не импортируются, а копируются.

```
TAG WORD          0001 1110 0100 LLLL      IMPORT-DOC (0x1E4L)
[Length — расширяющий TAG]
Документ          запись DOC-POINTER (Issuer, ID документа, ID версии). Для документа Codec — CODEC-POINTER
IMPORT ID         остаток. Целое число наименьшей ширины
```

- Используется только [IMPORT-DOC](0x1E4L-import-doc.md) (`0x1E4L`). IMPORT импортирует только документ. Объекты внутри импортированного документа указываются в BODY через `EXTERNAL-POINTER-*` (IMPORT ID, LOCAL ID).
- Если указан ID версии, привязка идёт к этой редакции, если `0` — к последней на момент интерпретации. Опубликованные документы указывают версию.
- В одном документе один и тот же IMPORT ID дважды не назначается.
- HEAD импортированного документа не импортируется. Объекты этого документа интерпретируются по его собственным объявлениям.

Пример: последняя версия документа `0x0000000000000002` Issuer `0x00000002` импортируется под IMPORT ID 1.

```
1E4A 0418 0000 0002 0000 0000 0000 0002 0000 0000 0001
```
