## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([Документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `version` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

Объявляет версию спецификации GEUL, которой следует документ. Как читать остальные записи, определяет это значение.

## Раскладка {#레이아웃}

```
TAG WORD          0001 1100 0101 LLLL      Codec 0x1C5L
[Length — расширяющий TAG]
Payload           версия спецификации. v1 = 0x0001
```

- Codec: Meta `0x1C5L`, класс объявления
- Payload: простое значение (unsigned целое наименьшей ширины)
- Количество: не более одного

## Интерпретация и валидность {#해석과-유효성}

- Не опирается на коды Value. Чтобы декодер любой версии мог её прочитать, ставится просто целое число, без встроенного Value.
- Если версия неизвестна, декодер отвергает документ или предупреждает.
- Если записи нет, декодер читает документ по известной ему версии. Опубликованные документы её указывают.

## Пример {#예시}

- `0x1C51 0x0001`: GEUL v1

## Открытые проблемы {#열린-문제}

- Соответствие версии документа кодбука ([документ спецификации](../codec-spec.md)).

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00001C50/latest.geul`, прочитанный командой `geul show` (16-ричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000001C5000000000
BODY
#1 DECLARE 0x1C50
#2 FIELD #1 rest
#3 BIND #1 "SPEC-VERSION"
#4 BIND #2 "version"
```
