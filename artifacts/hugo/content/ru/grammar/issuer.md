GEUL не собирает систему идентификации в одном месте. Каждый Issuer определяет объекты и форматы, а другие документы берут опубликованные определения. Определения либо держат конфиденциальными, либо публикуют на geul.org (CC0), либо публикуют частным образом (по лицензии, которую задаёт Issuer). Каким определениям доверять, решает пользователь.

Адрес публикации, указание формата, список Issuer, список версий и уровни доверия определяет страница [Адрес публикации и список версий](publishing.md).

## Что определяет Issuer {#issuer가-정의하는-것}

| Объект | Способ |
|---|---|
| Объекты (сущности, понятия, термины) | Объявляются как LOCAL в собственном документе |
| Формат Reference | Определяется 2-WORD номером Codec под кодом Issuer |
| Формат Value | Определяется 2-WORD номером Codec под кодом Issuer |
| Формат Edge | Определяется 2-WORD номером Codec под кодом Issuer |

- Определения форматов Reference, Value и Edge тоже публикуются как документы.

## Принципы {#원칙}

- Объект, определённый Issuer, — это LOCAL документа, опубликованного этим Issuer. Другие документы цитируют его напрямую указывающим объявлением (`EXTERNAL-ISSUER-*`) либо импортируют через `IMPORT-DOC` и указывают через `EXTERNAL-POINTER-*`. Смысл записи [REFERENCE-ISSUER](reference/_index.md#reference-issuer) определяет документ Codec, выпущенный Issuer.
- Для объекта, на который нужно указывать вне документа, выдаётся LOCAL опубликованного документа. У этого документа должен быть [DOC-ID](meta/0x1C7L-doc-id.md).

## Классы Issuer {#issuer-등급}

| Ширина | Диапазон значений | Выдача |
|---|---|---|
| 2 WORD | `0x00000000`~`0xFFFFFFFF` | Регистрация на geul.org. Требуется подтверждение владения доменом. Номера, назначенные geul.org организациям-разработчикам стандартов и крупным учреждениям, тоже имеют эту ширину ([Таблица назначения 2 WORD](#2-word-배정표)) |
| 4 WORD | `2^32`~`2^64−1` | Регистрация на geul.org. Подтверждения владения нет |
| 16 WORD | `2^64` и выше | Самовыдача. Вычисляется из открытого ключа |

- **ID Issuer — целое число.** Одинаковое значение означает одного и того же Issuer. Ширина не входит в идентификатор.
- **Длинная запись короткого ID Issuer с ведущими нулями — тот же Issuer** (2 → 4, 2 → 16, 4 → 16 WORD). `0x00000001` и `0x0000000000000001` — один Issuer. Поэтому 4-WORD Issuer со значением `0x00000000XXXXXXXX` и 16-WORD Issuer, у которого старшие 12 WORD равны 0, не назначаются.
- **Каноническая форма — самая короткая ширина.** В записи пишется самая короткая ширина, в которую значение помещается, а запись с более широкой шириной отвергается. Поэтому назначение каждой ширины начинается со значения после конца диапазона ширины ниже. Самая короткая ширина — 2 WORD. В адресе публикации пишется число цифр, соответствующее ширине выдачи (2 WORD — 8 цифр, 4 WORD — 16 цифр, 16 WORD — 64 цифры), в шестнадцатеричных заглавных (адрес, записанный строчными, приводится к заглавным при поиске), а при чтении расширенная запись принимается как тот же Issuer ([Адрес публикации и список версий](publishing.md#id-표기)).

## Таблица назначения 2 WORD {#2-word-배정표}

geul.org назначает номера 2-WORD Issuer организациям-разработчикам стандартов и крупным учреждениям по порядку с начала. Де-факто стандарты и форматы по соглашению, у которых нет организации-разработчика, помещаются под `ADHOC` (`adhoc.geul.org`). Собственные форматы, разработанные GEUL, — прямые коды. Issuer организаций-разработчиков стандартов — Issuer поддоменов geul.org. Имя поддомена — имя организации строчными (`<имя организации>.geul.org`, например `iso.geul.org`, `iec.geul.org`). - **Домен может измениться.** Привязка Issuer к домену может измениться позже. ID Issuer не меняется. Когда организация начнёт вести его сама, он заменяется официальным доменом этой организации.
- **Поддомены geul.org — не официальные издатели.** Поддомен geul.org с именем организации-разработчика стандартов не является официальным издателем этой организации. Например, `iso.geul.org` — не официальный издатель ISO.

## 16-WORD Issuer {#16-word-issuer}

```
Issuer ID = SHA-256("GEUL-ISSUER-v1" ‖ ID алгоритма подписи (2 байта) ‖ открытый ключ)
```

- 32 байта результата записываются в 16 WORD, начиная со старшего байта.
- Любой может создать его без регистрации. Владение доказывается подписью закрытым ключом.
- Открытый ключ и алгоритм объявляются через [ISSUER-KEY](meta/0x1E5L-issuer-key.md) в HEAD документа. Алгоритм подписи `0x0001` — Ed25519, остальные значения — Reserved.
- Префикс `GEUL-ISSUER-v1` не допускает получения одинакового ID при использовании одного ключа для разных целей (разделение назначений).
- Даже если алгоритм подписи изменится (например, Ed25519 → ML-DSA), ширина ID остаётся прежней — 16 WORD.
- Если результат меньше `2^64` (вероятность практически нулевая), Issuer по этому ключу не создаётся, потому что это пересекается с правилом самой короткой ширины.

## Подтверждение домена {#도메인-증명}

- Подтверждение владения доменом 2-WORD Issuer проверяется только в момент регистрации. Дальнейшее управление доменом — ответственность Issuer.
- Один домен соответствует только одному Issuer. У одного Issuer может быть несколько доменов. Соответствие записывается через BIND в списке Issuer `issuers/` ([Адрес публикации и список версий](publishing.md#issuer-목록)).
- Даже если срок домена истёк или он перешёл другому владельцу, соответствие остаётся за Issuer, первым подтвердившим его. Новый владелец не может использовать этот домен как имя Issuer.
- Доменное имя служит для ввода и отображения в интерпретаторе и CLI. Это не URL-адрес публикации ([Адрес публикации и список версий](publishing.md#도메인-이름)). Внутри документов GEUL записывается только ID Issuer.

## Документы определения терминов {#용어-정의-문서}

- Термины, определённые Issuer (инструменты, программы, роли, понятия внутри организации), заводятся **одним документом на один термин**. Термин — это LOCAL этого документа, имя связывается через [BIND](edge/0x0A3L-bind.md), а указываемый внешний объект (URI и т. п.) — через [REFERENCE-NODE](edge/0x0A0L-reference-node.md).
- Другие документы указывают на термин через `EXTERNAL-ISSUER-*` (Issuer, ID документа, LOCAL ID). Одно и то же определение в каждом документе не повторяется. Пример: инструмент в [TRANSFORMED-BY](meta/0x1D4L-transformed-by.md).
- Диапазон ID документов для документов определения терминов задаёт Issuer. geul.org (`0x00000000`) использует `0x0001xxxx xxxxxxxx`.
- Каждый Issuer резервирует ID документа `0x0000000000000000` и `0xFFFFFFFFFFFFFFFF`. Сейчас они применяются двумя способами ниже.
- ID документа `0x0000000000000000` — место **индексного документа определений терминов** этого Issuer: `<Issuer>/docs/0x0000000000000000/`. Это место, где перечисляются документы определения терминов.
- ID документа `0xFFFFFFFFFFFFFFFF` используется для списка Issuer `issuers/` у Issuer geul.org (`0x00000000`). Другие Issuer этот ID не используют. Этот ID ни у какого Issuer не отдаётся по адресу `<Issuer>/docs/<ID документа>/` (404) ([Адрес публикации и список версий](publishing.md#목록-문서)).
- Индексный документ **рекомендуется** всем Issuer. Он не обязателен.
- Порядок указания внешнего объекта: (1) подходящий Reference Codec, если есть (WIKIDATA-QID и др.), (2) GEUL-документ, определяющий этот объект, если есть (DOC-POINTER, EXTERNAL-ISSUER), (3) иначе объект определяется как LOCAL в собственном документе определения терминов и указывается.

## Способы раскрытия документов {#문서-공개-방식}

| Способ | Для кого | Лицензия | Управление версиями | Сохранность |
|---|---|---|---|---|
| Конфиденциально | Любой Issuer | Внутри Issuer | Issuer | Зависит от Issuer |
| Публикация на geul.org | 2-WORD Issuer | CC0 | geul.org | geul.org сохраняет |
| Частная публикация | Любой Issuer | Задаёт Issuer | Issuer | Зависит от Issuer |

### Публикация на geul.org {#geulorg-공표}

- 2-WORD Issuer может зарегистрировать документ на geul.org и опубликовать его. Зарегистрированный документ — CC0. Зарегистрированное публикуется сразу, а проблемы решаются постфактум.
- Публиковать можно определения понятий и Codec. **Reference, указывающие на физических лиц, на geul.org публиковать нельзя.** Они делаются конфиденциальными или публикуются частным образом.
  - Исключение: указывать на физическое лицо через [WIKIDATA-QID](reference/0x014L-wikidata-qid.md) разрешено.
- Зарегистрированная версия не изменяется и не удаляется, и документ остаётся, даже если Issuer исчез (сохранение прежнего закона). Исключения — удаление по закону и удаление по должностному решению ([TOMBSTONE](edge/0x0BAL-tombstone.md)).
- Issuer может только пометить определение рекомендацией об отказе от использования (deprecated). Определение с такой рекомендацией продолжает интерпретироваться.
- Новая версия того же документа может вводить, изменять и удалять определения ([Документ](document.md#개정)). **Удалённые ID сущностей и номера Codec для других объектов повторно не используются.** Wire-макет номера Codec не пересматривается.

### Частная публикация {#사설-공표}

- Issuer, желающий опубликовать документ под лицензией, отличной от CC0, обслуживает документы в частной сети (на собственном домене и т. п.). Лицензия объявляется через [LICENSE](meta/0x1DEL-license.md) в HEAD документа.
- Частная публикация использует те же пути, что и geul.org ([Адрес публикации и список версий](publishing.md)).
- Управление версиями, доступность, поддержание домена и условия лицензии определяет Issuer. geul.org не участвует в частной публикации и не гарантирует её.

### Конфиденциально {#대외비}

- Конфиденциальные документы не публикуются. На них ставится контроль доступа, и они помечаются через [ACCESS](meta/0x1DFL-access.md).
- Если документ, использующий конфиденциальные определения, отправить вовне, принимающая сторона не сможет интерпретировать эти Reference, Value и Edge и пропустит их. Определения, которыми обмениваются с внешним миром, публикуются.

### Выбор пользователя {#사용자의-선택}

- Пользователь выбирает документы для использования, исходя из объявленной лицензии и вероятности существования Issuer в будущем.
- Определения со слишком ограничительной лицензией или от Issuer с ненадёжным существованием использоваться не будут.
- Для ссылок, которые должны сохраняться долго, используются документы, опубликованные на geul.org.

## Подпись {#서명}

- Подпись обязательна для опубликованного документа. Она ставится в HEAD как [SIGNATURE](meta/0x1E6L-signature.md). Документ без подписи тоже является допустимым документом GEUL, а конфиденциальные и внутренние документы по возможности тоже подписываются.
- Подписывается **хеш содержимого** документа ([Документ](document.md#내용-해시)). Подписывается не только BODY.
  - В HEAD есть правила интерпретации. Если изменить цель `IMPORT-DOC`, тот же BODY будет указывать на другую цель.
  - Если не подписывать `LICENSE` и `PARENT`, лицензию и историю можно подделать.
- В один документ можно поставить несколько подписей. Все они подписывают один и тот же хеш содержимого, поэтому добавление подписи хеш содержимого не меняет.
- Проверка ключа подписи:
  - 2- и 4-WORD Issuer: ключ, зарегистрированный на geul.org (публикация ключей проверки ниже).
  - 16-WORD Issuer: `ISSUER-KEY` того же документа. Issuer ID, вычисленный из этого открытого ключа, должен совпадать с подписавшим.
- Читающая сторона при отсутствии подписи снижает доверие, а если подпись есть, но проверка не прошла, это свидетельство подделки или выдачи себя за другого, и доверие снижается ещё сильнее.
- Подпись документа ставит Issuer этого документа, а подпись списка версий — публикующая сторона, назначившая ID версии ([Адрес публикации и список версий](publishing.md#서명-주체)).

## Публикация ключей проверки {#검증키-공개}

- geul.org публикует ключи проверки подписи зарегистрированных Issuer (2- и 4-WORD).
- Список ключей выпускается как опубликованный документ GEUL Issuer (`0x00000000`). Он CC0 и подписан geul.org.
  - Элементы: Issuer, ID алгоритма подписи, открытый ключ, момент начала действия, момент отзыва и причина.
- Отозванные ключи тоже не стираются. Прошлые подписи проверяются ключом, действовавшим в момент подписания.
- Смена ключа регистрируется подписанием нового ключа старым. Проверяющая сторона может подтвердить непрерывность ключа, не доверяя geul.org.
- История смены ключей ведётся в журнале, допускающем только добавление (как Certificate Transparency, Go sumdb). Правка истории становится заметной.
- Если ключ потерян и подписать старым ключом нельзя, geul.org заново подтверждает личность и регистрирует новый ключ. 2-WORD Issuer заново проходит подтверждение владения доменом. В этом случае необходимо доверять geul.org, причина записывается в журнал.
- 16-WORD Issuer этого не касается. Issuer ID вычисляется из открытого ключа, поэтому проверка выполняется только по `ISSUER-KEY` внутри документа.

## Импорт {#가져오기}

IMPORT импортирует только документы.

```
IMPORT-DOC                      DOC-POINTER (Issuer + ID документа + ID версии) + IMPORT ID
                                для документа Codec — CODEC-POINTER (Issuer + Codec ID + ID версии) + IMPORT ID
EXTERNAL-POINTER-1/2/4WORD      IMPORT ID + LOCAL ID
EXTERNAL-ISSUER-2/4/16WORD      Issuer + ID документа + LOCAL ID (без IMPORT)
ISSUER-POINTER                  Issuer (сам Issuer)
DOC-POINTER                     Issuer + ID документа + ID версии (2 WORD, 0 — последняя)
CODEC-POINTER                   Issuer + Codec ID + ID версии (2 WORD, 0 — последняя)
```

- На Issuer любой ширины и его документ можно указать указывающим объявлением без IMPORT. Сам Issuer — `ISSUER-POINTER`, сам документ — `DOC-POINTER`, LOCAL документа — `EXTERNAL-ISSUER-*`. Указывающее объявление следует последней версии, а чтобы зафиксировать версию, используются `IMPORT-DOC` (ID версии) и `EXTERNAL-POINTER-*`.
- Reference в теле, указывающие на объект внешнего документа, используют не полный путь (Issuer + документ + ID объекта), а только IMPORT ID + ID объекта. [REFERENCE-ISSUER](reference/_index.md#reference-issuer) записывает Issuer и номер Codec.
- Ширина IMPORT ID определяется в `IMPORT-DOC` длиной, а в `EXTERNAL-POINTER-*` — Codec ([IMPORT-DOC](meta/0x1E4L-import-doc.md)).
- Импорт без ID версии следует последней версии. Если ID версии указан, фиксируется эта версия. Опубликованный документ указывает ID версии.

## Лицензия {#라이선스}

- Документы, опубликованные на geul.org, и документы GEUL Issuer (`0x00000000`) — CC0.
- Лицензию частно опубликованных документов задаёт Issuer. GEUL её не навязывает.
- **Лицензия форматов Issuer.** Только прямые коды и публикации, предоставляемые geul.org, — CC0. Лицензию форматов Issuer задаёт этот Issuer.
- **Указание Issuer.** GEUL основывает Resolve на указании Issuer. В документах, использующих Codec другого Issuer, этот Issuer указан всегда.
- Основные продукты GEUL не копируют содержимое документов Issuer, не распространяемых под CC0.

## Открытые проблемы {#열린-문제}

- Способ подтверждения владения доменом (DNS TXT `_geul.<домен>`, HTTP `.well-known`) и вопрос, привязывать ли к значению подтверждения отпечаток ключа подписи.
- Противодействие захвату домена при восстановлении утерянного ключа. Если регистрировать новый ключ только по повторному подтверждению домена, захватчик может забрать Issuer. Рассматриваются проверка регистрационного контакта, отсрочка с возможностью возражения по старому ключу и применение результата доменного спора.
- Формат записей индексного документа определений терминов (ID документа `0`) (Edge, перечисляющий документы определения терминов).
- Значение алгоритма подписи по умолчанию (рекомендуется Ed25519).
