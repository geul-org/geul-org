GEUL не собирает систему идентификации в одном месте. Каждый Issuer определяет объекты и форматы, а другие документы берут опубликованные определения. Определения можно держать конфиденциальными, публиковать через geul.org (CC0) или в частном порядке (лицензию задаёт Issuer). Каким определениям доверять, решает пользователь.

Адрес публикации, указание формата, индекс имён, список версий и уровни доверия определяет страница [Адрес публикации и список версий](/ru/grammar/publishing/).

## Что определяет Issuer

| Объект | Способ |
|---|---|
| Объекты (сущности, понятия, термины) | Объявляются как LOCAL своего документа |
| Форматы Value | Определяются номером формата под кодом Issuer |
| Форматы Edge | Определяются номером формата под кодом Issuer |

- Определения форматов Value и Edge тоже публикуются как документы.

## Принципы

- Все ID действуют в пределах документа. LOCAL ID (включая Edge Id и переменные) и IMPORT ID действительны только внутри этого документа.
- Объект, определённый Issuer, — это LOCAL документа, который этот Issuer опубликовал. Другие документы цитируют его напрямую через указывающее объявление (`EXTERNAL-ISSUER-*`) либо подключают через `IMPORT-DOC` и указывают через `EXTERNAL-POINTER-*`.
- Для объектов, на которые нужно указывать извне документа, выдаётся LOCAL опубликованного документа. В таком документе должен быть [DOC-ID](/ru/grammar/meta/declaration/doc-id/).

## Классы Issuer

| Ширина | Диапазон значений | Выдача |
|---|---|---|
| 1 WORD | `0x0000`–`0xFFFF` | Назначает geul.org организациям по стандартизации и основным учреждениям ([таблица назначения 1 WORD](#таблица-назначения-1-word)) |
| 2 WORD | `0x00010000`–`0xFFFFFFFF` | Регистрация в geul.org. Требуется подтверждение владения доменом |
| 4 WORD | `2^32`–`2^64−1` | Регистрация в geul.org. Подтверждения владения нет |
| 16 WORD | `2^64` и выше | Самовыдача. Вычисляется из открытого ключа |

- **ID Issuer — целое число.** Если значения равны, это один и тот же Issuer (`0x0001` и `0x00000001` — одно значение). Ширина не входит в идентификатор.
- **Каноническая форма — самая короткая ширина.** Записывается самой короткой шириной, в которую значение помещается; более широкая запись отклоняется. Поэтому назначение в каждой ширине начинается со значения, следующего за диапазоном ближайшей более узкой ширины (для 2 WORD — с `0x00010000`).

- Назначение идёт с меньших номеров в пределах диапазона, отведённого организациям данного типа. Диапазон — удобство классификации, декодер не обязан его интерпретировать.

## Issuer в 16 WORD

```
Issuer ID = SHA-256("GEUL-ISSUER-v1" ‖ ID алгоритма подписи (2 байта) ‖ открытый ключ)
```

- 32 байта результата записываются в 16 WORD начиная со старшего байта.
- Создать такой Issuer может любой без регистрации. Владение доказывается подписью закрытого ключа.
- Открытый ключ и алгоритм объявляются в HEAD документа через [ISSUER-KEY](/ru/grammar/meta/verification/issuer-key/). Алгоритм подписи `0x0001` — Ed25519, остальные значения зарезервированы.
- Префикс `GEUL-ISSUER-v1` не даёт получить один и тот же ID, если один ключ используется для другой цели (разделение назначения).
- Даже при смене алгоритма подписи (например, Ed25519 → ML-DSA) ширина ID остаётся 16 WORD.
- Если результат меньше `2^64` (вероятность практически нулевая), Issuer по этому ключу не создаётся, потому что это пересекается с правилом самой короткой ширины.

## Подтверждение домена

- Подтверждение владения доменом для Issuer в 2 WORD проверяется только в момент регистрации. Дальнейшее управление доменом — ответственность Issuer.
- Один домен соответствует только одному Issuer. У одного Issuer может быть несколько доменов. Соответствие записывается через BIND в индексе имён Issuer `issuers.geul` ([Адрес публикации и список версий](/ru/grammar/publishing/#имя-issuer)).
- Если срок домена истёк или он перешёл к другому владельцу, соответствие остаётся за Issuer, который подтвердил его первым. Новый владелец не может использовать этот домен как имя Issuer.
- Доменное имя служит для ввода и отображения адреса. В документе GEUL записывается только ID Issuer.

## Документы определения терминов

- Термины, определённые Issuer (инструменты, программы, роли, понятия внутри организации), оформляются **одним документом на один термин**. Термин — это LOCAL этого документа; имя связывается через [BIND](/ru/grammar/edge/bind/), а внешний объект, на который он указывает (URI и т. п.), — через [REFERENCE-NODE](/ru/grammar/edge/reference-node/).
- Другие документы указывают на термин через `EXTERNAL-ISSUER-*` (Issuer, ID документа, LOCAL ID). Одно и то же определение не повторяется в каждом документе. Пример: инструмент в [TRANSFORMED-BY](/ru/grammar/meta/lineage/transformed-by/).
- Диапазон ID документов для определений терминов задаёт Issuer. geul.org (`0x0000`) использует `0x0001xxxx xxxxxxxx` ([Спецификация Codec](/ru/grammar/codec-spec/#id-документов-issuer-geul)).
- ID документа `0x0000000000000000` каждого Issuer зарезервирован для его **индексного документа определений терминов**: `<Issuer>/0x0000000000000000/`. Это место, где перечисляются документы определений терминов.
- Индексный документ **рекомендуется** всем Issuer, но не обязателен. Если индекса нет, документы определений терминов ищутся через индекс имён `documents.geul`.
- Порядок указания на внешний объект: (1) подходящий Reference Codec, если он есть (WIKIDATA-QID и т. п.); (2) документ GEUL, определяющий этот объект, если он есть (DOC-POINTER, EXTERNAL-ISSUER); (3) иначе определить его как LOCAL в собственном документе определения терминов и указать на него.

## Способы раскрытия документов

| Способ | Для кого | Лицензия | Управление версиями | Сохранность |
|---|---|---|---|---|
| Конфиденциально | Любой Issuer | Внутренняя у Issuer | Issuer | Зависит от Issuer |
| Публикация через geul.org | Issuer в 1 и 2 WORD | CC0 | geul.org | geul.org сохраняет |
| Частная публикация | Любой Issuer | Задаёт Issuer | Issuer | Зависит от Issuer |

### Публикация через geul.org

- Issuer в 1 и 2 WORD могут зарегистрировать документы в geul.org и опубликовать их. Зарегистрированные документы — CC0.
  - Issuer в 1 WORD публикуют после предварительной проверки geul.org.
  - Issuer в 2 WORD публикуются сразу после регистрации, а проблемы устраняются постфактум.
- Публиковать можно определения понятий и кодеков. **Reference, указывающий на физическое лицо, нельзя публиковать через geul.org.** Для него используется конфиденциальный режим или частная публикация.
  - Исключение: указывать на физическое лицо через [WIKIDATA-QID](/ru/grammar/reference/wikidata-qid/) разрешено.
- Зарегистрированные версии не изменяются и не удаляются, а документы остаются, даже если Issuer исчезнет (сохранение прежней редакции). Исключения — юридическое удаление и удаление по служебной обязанности ([TOMBSTONE](/ru/grammar/edge/publication/)).
- Issuer может лишь пометить определение рекомендацией об отказе от использования (deprecated). Определение, помеченное так, продолжает интерпретироваться.
- Новая версия того же документа может вводить, изменять и удалять определения ([Документ](/ru/grammar/document/#редакции)). **ID удалённых сущностей и номера форматов другим объектам повторно не присваиваются.** Wire-раскладка номера формата не редактируется.

### Частная публикация

- Issuer, желающий опубликовать документы под лицензией, отличной от CC0, обслуживает их в частной сети (на собственном домене и т. п.). Лицензия объявляется через [LICENSE](/ru/grammar/meta/policy/license/) в HEAD документа.
- Частная публикация использует те же пути, что и geul.org ([Адрес публикации и список версий](/ru/grammar/publishing/)).
- Управление версиями, доступность, поддержку домена и условия лицензии определяет Issuer. geul.org не участвует в частной публикации и не гарантирует её.

### Конфиденциально

- Конфиденциальные документы не публикуются. На них ставят контроль доступа и отмечают через [ACCESS](/ru/grammar/meta/policy/access/).
- Если документ, использующий конфиденциальные определения, отправить наружу, получатель не сможет интерпретировать эти Reference, Value и Edge и пропустит их. Определения, которыми обмениваются с внешним миром, публикуются.

### Выбор пользователя

- Пользователь выбирает документы по объявленной лицензии и по вероятности того, что Issuer просуществует.
- Определения со слишком строгой лицензией или от Issuer с ненадёжной сохранностью использоваться не будут.
- Ссылки, которые должны сохраняться долго, делают на документы, опубликованные через geul.org.

## Подпись

- Подпись обязательна для опубликованных документов. Она помещается в HEAD как [SIGNATURE](/ru/grammar/meta/verification/signature/). Документ без подписи тоже является допустимым документом GEUL; конфиденциальные и внутренние документы также по возможности подписывают.
- Подписывается **хеш содержимого** документа ([Документ](/ru/grammar/document/#хеш-содержимого)). Одного BODY недостаточно.
  - В HEAD есть правила интерпретации. Если изменить цель `IMPORT-DOC`, тот же BODY указывает на другой объект.
  - Если не подписывать `LICENSE` и `PARENT`, можно подделать лицензию и историю.
- В одном документе может быть несколько подписей. Все они подписывают один и тот же хеш содержимого, поэтому добавление подписи хеш содержимого не меняет.
- Проверка ключа подписи:
  - Issuer в 1, 2, 4 WORD: ключ, зарегистрированный в geul.org (см. «Публикация ключей проверки» ниже).
  - Issuer в 16 WORD: `ISSUER-KEY` того же документа. Issuer ID, вычисленный из этого открытого ключа, должен совпадать с подписавшим.
- Читающая сторона снижает доверие, если подписи нет, а если подпись есть, но проверка не проходит, снижает ещё сильнее, поскольку это свидетельство подмены или самозванства.
- Подпись документа ставит Issuer этого документа, а подпись списка версий — публикующая сторона, назначившая ID версий ([Адрес публикации и список версий](/ru/grammar/publishing/#подписывающая-сторона)).

## Публикация ключей проверки

- geul.org публикует ключи проверки подписи зарегистрированных Issuer (1, 2, 4 WORD).
- Список ключей выпускается как опубликованный документ Issuer GEUL (`0x0000`). Он CC0 и подписан geul.org.
  - Поля: Issuer, ID алгоритма подписи, открытый ключ, момент начала действия, момент и причина отзыва.
- Отозванные ключи не удаляются. Прошлые подписи проверяются ключом, который был действителен на момент подписи.
- Смена ключа регистрируется подписью нового ключа старым ключом. Проверяющая сторона может убедиться в непрерывности ключа, не доверяя geul.org.
- Записи об изменении ключей ведутся в журнале, в который можно только добавлять (как Certificate Transparency и Go sumdb). Изменение истории становится заметно.
- Если ключ утерян и подписать старым ключом нельзя, geul.org заново подтверждает личность и регистрирует новый ключ. Для Issuer в 2 WORD заново проходится подтверждение владения доменом. В этом случае нужно доверять geul.org, причина записывается в журнал.
- Issuer в 16 WORD это не касается. Issuer ID вычисляется из открытого ключа, поэтому проверка выполняется только по `ISSUER-KEY` внутри документа.

## Подключение

IMPORT подключает только документы.

```
IMPORT-DOC                      DOC-POINTER(Issuer + ID документа + ID версии) + IMPORT ID
EXTERNAL-POINTER-1/2/4/8WORD    IMPORT ID + LOCAL ID
EXTERNAL-ISSUER-1/2/4/16WORD    Issuer + ID документа + LOCAL ID (без IMPORT)
ISSUER-POINTER                  Issuer (сам Issuer)
DOC-POINTER                     Issuer + ID документа + ID версии (2 WORD, 0 — последняя)
```

- На Issuer любой ширины и его документы можно указывать без IMPORT через указывающее объявление. На самого Issuer — `ISSUER-POINTER`, на сам документ — `DOC-POINTER`, на LOCAL документа — `EXTERNAL-ISSUER-*`. Указывающее объявление следует последней версии; чтобы зафиксировать версию, используются `IMPORT-DOC` (ID версии) и `EXTERNAL-POINTER-*`.
- Reference в основной части вместо полного пути (Issuer + документ + ID объекта) использует только IMPORT ID + ID объекта.
- Ширина IMPORT ID определяется длиной в `IMPORT-DOC` и Codec в `EXTERNAL-POINTER-*`. Он действует только внутри этого документа ([IMPORT-DOC](/ru/grammar/meta/import/import-doc/)).
- При подключении без ID версии берётся последняя версия. Если ID версии указан, фиксируется эта версия. Опубликованные документы указывают ID версии.

## Лицензия

- Документы, опубликованные через geul.org, и документы Issuer GEUL (`0x0000`) — CC0.
- Лицензию документов частной публикации определяет Issuer. GEUL её не навязывает.
- Основные результаты GEUL не копируют содержимое документов Issuer, лицензия которых не CC0.

## Открытые вопросы

- Разрешать ли публикацию Issuer в 4 WORD и 16 WORD через geul.org.
- Способ подтверждения владения доменом (DNS TXT `_geul.<домен>`, HTTP `.well-known`) и нужно ли связывать значение подтверждения с отпечатком ключа подписи.
- Защита от перехвата домена при восстановлении утерянного ключа. Если регистрировать новый ключ одним лишь повторным подтверждением домена, злоумышленник, захвативший домен, может забрать Issuer. Рассматриваются проверка контакта при регистрации, льготный период с возможностью возражения со стороны старого ключа и применение результатов доменных споров.
- Формат записей индексного документа определений терминов (ID документа `0`) — Edge, перечисляющий документы определений терминов.
- Алгоритм подписи по умолчанию (рекомендуется Ed25519).
