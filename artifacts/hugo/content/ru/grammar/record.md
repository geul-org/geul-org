Данные GEUL — последовательность записей. Каждая запись начинается с одного TAG WORD.

## Раскладка записи

```
TAG WORD (16 бит)
┌──────────┬─────────┬──────────┬─────────────────────┐
│  Prefix  │  Kind   │  Length  │        Codec        │
│  3 бита  │  2 бита │  4 бита  │       7 бит         │
│   000    │   KK    │   LLLL   │       CCCCCCC       │
└──────────┴─────────┴──────────┴─────────────────────┘
[расширенный TAG Length]
[расширенный TAG Codec]
[TAG конкретного Codec]
Payload
```

- TAG WORD имеет вид `000K KLLL LCCC CCCC`.
- Расширенные TAG располагаются только в указанном порядке. Расширенный TAG Length всегда следует сразу за TAG WORD.
- Состав TAG конкретного Codec и Payload определяет спецификация этого Codec. Длина TAG конкретного Codec в TAG WORD не записывается: чтобы интерпретировать Payload, кодекбук всё равно нужен.
- Codec с подформатами задаёт подформат одним WORD в TAG конкретного Codec (Edge WORLD и т. п.).

## Порядок байтов

- Каноническая сериализация — big-endian.
- Битовые поля размещаются начиная со старшего бита.
- Внутри WORD сначала идёт старший байт; значение из нескольких WORD записывается начиная со старшего WORD.
- Представление в памяти реализация выбирает свободно.

## Kind (2 бита)

| Значение | Kind | TAG WORD | Определение |
|---|---|---|---|
| `00` | Reference | `0000 0LLL LCCC CQQQ` | Указывает на объект. Объект идентифицируется по Codec и ID объекта |
| `01` | Value | `0000 1LLL LCCC CCCC` | Хранит само значение. Codec определяет интерпретацию Payload |
| `10` | Edge | `0001 0LLL LCCC CCCC` | Связывает другие записи как компоненты. Codec определяет роли и порядок компонентов |
| `11` | Meta | `0001 1LLL LCCC CCCC` | Говорит о документе и записях |

- Kind — неизменное свойство Codec. Назначенный однажды Codec не переносится в другой Kind.
- Value и Edge имеют один формат «Codec + Payload». Только Edge содержит другие записи в качестве компонентов.
- В Reference 7 бит Codec делятся на 4 бита Codec и 3 бита Quantifier ([Reference](/ru/grammar/reference/)).

## Length (4 бита)

Length — **полное число WORD**, занимаемых записью. Включает TAG WORD, расширенные TAG, Payload и дополнение в последнем WORD.

| Значение | Смысл |
|---|---|
| `0000`–`1101` | 1–14 WORD (значение + 1) |
| `1110` | Расширенная длина 1: следующий 1 WORD содержит полное число WORD (15–65 535) |
| `1111` | Расширенная длина 2: следующие 2 WORD содержат полное число WORD (65 536–2³²−1) |

- Длины 1–14 WORD обязательно записываются как прямая длина. Более широкая запись не является канонической.
- В полное число WORD при расширенной длине входит и сам расширенный TAG Length.
- Записей длиннее 2³²−1 WORD не бывает.
- Запись в 1 WORD — это один TAG WORD без Payload. Допускается только если это разрешает спецификация Codec (например, Meta `BODY`, `END`, пустая последовательность байтов, маркер места).
- Даже без кодекбука запись можно пропустить: `положение следующей записи = начало текущей записи + Length`.

## Codec (7 бит)

| Значение | Имя | Смысл |
|---|---|---|
| `0x00`–`0x7B` | Прямой код | Codec определяется одним TAG WORD |
| `0x7C` | ISSUER-1WORD | В расширенном TAG Codec: Issuer 1 WORD и номер формата 1 WORD |
| `0x7D` | ISSUER-2WORD | В расширенном TAG Codec: Issuer 2 WORD и номер формата 1 WORD |
| `0x7E` | ISSUER-4WORD | В расширенном TAG Codec: Issuer 4 WORD и номер формата 1 WORD |
| `0x7F` | ISSUER-16WORD | В расширенном TAG Codec: Issuer 16 WORD и номер формата 1 WORD |

- Пространство номеров Codec отдельное для каждого Kind. Один и тот же номер при разном Kind — разные Codec.
- Codec, не являющийся прямым кодом, — это пара `(Issuer, номер формата)`. Номер формата определяет сам Issuer ([Issuer и публикация](/ru/grammar/issuer/)). Расширенный формат размещается под Issuer организации, которая этот формат утвердила.
- Codec, у которого есть прямой код, отдельно как формат Issuer не регистрируется.
- Форматы Issuer есть только у Value и Edge. Reference использует 4 бита Codec, а Meta — общая спецификация, которую определяет только GEUL.
- Старшие биты Codec и номера формата указывают семейство (Value, Edge) или класс (Meta). Семейство известно и без кодекбука.
- Прямой код нельзя забрать обратно. В прямой код помещают только форматы с подтверждённой частотой.

## Запись формата Issuer

```
TAG WORD          Codec = 0x7C–0x7F
[расширенный TAG Length]
Issuer            1/2/4/16 WORD (ширину определяет Codec)
номер формата     1 WORD. Старшие биты — семейство
Payload           значение, определённое форматом
```

- Декодер, не знающий формат, знает только семейство по номеру формата и пропускает Payload.

## Последовательности байтов переменной длины

Для значений, длина которых измеряется в байтах (текст, URI, языковой тег, байты неизвестного вида), Codec (или номер формата) назначается **парой чётный/нечётный**.

- Если младший бит Codec равен `0`, число байтов чётное; если `1` — нечётное.
- Число байтов = `2 × число WORD Payload − младший бит`. Поля Byte Count нет.
- При нечётном числе младший байт последнего WORD — дополнение `0x00`. Если там не `0x00`, запись отклоняется.
- Пустая последовательность байтов — запись в 1 WORD (только TAG WORD) с чётным Codec.
- Значения фиксированного размера (UUID, дайджесты, адреса) пары не имеют.

## Пример: чтение TAG WORD

Прочитаем `148A`.

```
0x148A = 0001 0100 1000 1010
         000 | 10 | 1001 | 0001010
Prefix 000, Kind 10(Edge), Length 1001(10 WORD), Codec 0x0A(TRIPLE)
```

Это Edge в 10 WORD с Codec TRIPLE. Даже без кодекбука видно, что следующая запись находится через 10 WORD.

## Маркер места

TAG WORD `0x0000`–`0x0007` — записи в 1 WORD зарезервированного Reference Codec `0000`. Они не указывают на объект, а занимают место поля записи ([Маркер места](/ru/grammar/reference/slot-marker/)).

```
0x0000–0x0007 = 0000 0000 0000 0MMM
                Prefix 000, Kind 00(Reference), LLLL 0000(1 WORD), CCCC 0000, MMM = номер маркера
```

| WORD | Имя | Смысл | О чём это высказывание | Логика | Допущение о мире | Викиданные |
|---|---|---|---|---|---|---|
| `0x0000` | ABSENT | Не записано | Документ: это место не заполнено | Ничего не утверждается | Открытый мир | нет snak |
| `0x0001` | UNKNOWN-VALUE | Неизвестно | Мир: значение есть, но какое — неизвестно | `∃x. P(s, x)` | Существование закрыто, идентичность открыта | `somevalue` |
| `0x0002` | NO-VALUE | Нет | Мир: значения нет | `¬∃x. P(s, x)` | Закрыто для (s, P, ограничивающие условия) | `novalue` |
| `0x0003`–`0x0007` | Резерв | | | | | |

- Пример: если дети (P40) — ABSENT, число детей неизвестно; UNKNOWN-VALUE — не меньше одного; NO-VALUE — нет детей. Если момент окончания (P582) — ABSENT, неизвестно, действует ли утверждение до сих пор; UNKNOWN-VALUE — закончилось, но когда, неизвестно; NO-VALUE — не закончилось.
- Младшие 3 бита `MMM` — не Quantifier, а номер маркера (исключение для Quantifier, см. [Reference](/ru/grammar/reference/)).
- Маркер допустим только тогда, когда список CODEC поля содержит именно этот WORD. В поле с шаблоном (wildcard), в поле без CODEC, на месте записи HEAD и BODY и на месте Edge Id маркер недопустим (invalid) ([CODEC](/ru/grammar/edge/codec/)).
- Обязанности читающей стороны:
  1. UNKNOWN-VALUE — не значение, а утверждение о существовании. Он не равен никакому значению и не отличается ни от какого значения; два UNKNOWN-VALUE также не считаются одним значением. TRIPLE с UNKNOWN-VALUE при удалении дубликатов не объединяются.
  2. NO-VALUE замкнут внутри ограничивающих условий этого утверждения. Если с тем же Subject, Predicate и rank есть TRIPLE со значением, не различимый по ограничивающим условиям, это противоречие, и проверяющий выдаёт предупреждение (не отклоняет).
  3. rank применяется так же. При выборе основного (truthy) значения TRIPLE с обоими маркерами тоже являются кандидатами.
  4. Если маркер служит значением QUALIFIER, он меняет смысл ограничения (`P582 = UNKNOWN`: закончилось, момент неизвестен. `P582 = NONE`: не закончилось).
  5. ABSENT ничего не говорит о мире. Значение, которое не удалось перенести, нельзя записывать как UNKNOWN-VALUE.

## Каноническая форма

Одно и то же содержимое должно давать одни и те же байты. Только так хеш содержимого и подпись определяются однозначно.

- Длина записывается в самой короткой форме (1–14 WORD — прямая длина).
- Целые числа записываются в самой узкой ширине. Действует каноническая форма, заданная спецификацией каждого Codec.
- Запись не в канонической форме отклоняется.
