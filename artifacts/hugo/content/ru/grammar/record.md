Данные GEUL — последовательность записей. Каждая запись начинается с одного TAG WORD.

## Макет записи {#레코드-레이아웃}

```
TAG WORD (16 бит)
┌──────────┬──────────┬──────────┬──────────┐
│  Prefix  │   Kind   │  Class   │  Length  │
│   3bit   │   4bit   │   5bit   │   4bit   │
│   000    │   KKKK   │  CCCCC   │   LLLL   │
└──────────┴──────────┴──────────┴──────────┘
[расширяющий TAG Length]
[расширяющий TAG Codec]
[TAG, зависящий от Codec]
Payload
```

- TAG WORD имеет вид `000K KKKC CCCC LLLL`. Старшие 4 бита `KKKK` — раздел `S = w >> 9`, и один раздел содержит 32 позиции. `C` — 5-битное смещение внутри раздела `(w >> 4) & 0x1F`.
- TAG ID записывается как `0x000L`. Первые три цифры — 9-битная позиция Codec (`w >> 4`), объединяющая раздел и `C`, а `L` — позиция Length. В реальном значении WORD на место L подставляется число (например, TRIPLE — `0x0AAL`, а TAG WORD 10-WORD TRIPLE — `0x0AA9`).
- Расширяющие TAG ставятся только в порядке, показанном выше. Расширяющий TAG Length всегда стоит сразу после TAG WORD.
- Состав TAG, зависящего от Codec, и Payload определяет спецификация каждого Codec. Длина TAG, зависящего от Codec, в TAG WORD не записывается, потому что для разбора Payload всё равно нужен кодекбук.
- Codec с подформатами задаёт подформат одним WORD TAG, зависящего от Codec (Edge WORLD и др.).

## Порядок байтов {#바이트-순서}

- Каноническая сериализация — big-endian.
- Битовые поля располагаются начиная со старшего бита.
- Внутри WORD сначала идёт старший байт, а в значениях из нескольких WORD сначала пишется старший WORD.
- Представление в памяти реализация выбирает свободно.

## Kind (диапазон разделов) {#kind-섹션-구간}

| Раздел | Kind | TAG ID | Определение |
|---|---|---|---|
| 0~2 | Reference | `0x000L~0x05FL` | Указывает на цель. Цель определяется по Codec и ID цели |
| 3·4 | Value | `0x060L~0x09FL` | Содержит само значение. Codec определяет интерпретацию Payload |
| 5~13 | Edge | `0x0A0L~0x1BFL` | Связывает другие записи как составляющие. Codec определяет роль и порядок составляющих |
| 14·15 | Meta | `0x1C0L~0x1FFL` | Говорит о документе и записях |

- Kind определяется одним диапазоном разделов: `w < 0x0600` — Reference, `w < 0x0A00` — Value, `w < 0x1C00` — Edge, остальное — Meta. Исключений нет.

- Kind — неизменное свойство Codec. Назначенный однажды Codec не переносится в другой Kind.
- Value и Edge имеют один и тот же формат «Codec + Payload». Только у Edge составляющими являются другие записи.
- Reference делится кодовыми таблицами на маркеры места, указатели, систему 5Q и REFERENCE-ISSUER. Квантификация находится в кодах системы. Квантификацию REFERENCE-ISSUER определяет документ Issuer ([Reference](reference/_index.md)).

## Length (4 бита) {#length-4비트}

Length — **общее число WORD**, занимаемых записью. Оно включает TAG WORD, расширяющие TAG, Payload и дополнение в последнем WORD.

| Значение | Смысл |
|---|---|
| `0000`~`1101` | 1~14 WORD (значение + 1) |
| `1110` | Расширенная длина 1: общее число WORD в следующем 1 WORD (15~65,535) |
| `1111` | Расширенная длина 2: общее число WORD в следующих 2 WORD (65,536~2³²−1) |

- 1~14 WORD обязательно записываются прямой длиной. Более широкая запись не является канонической.
- В общее число WORD при расширенной длине входит и сам расширяющий TAG Length.
- Записей длиннее 2³²−1 WORD не бывает.
- 1-WORD запись — это один TAG WORD без Payload. Она используется, только если это допускает спецификация Codec (например, Meta `BODY`, `END`, пустая последовательность байтов, маркер места).
- Даже без кодекбука запись можно пропустить: `позиция следующей записи = начало текущей записи + Length`.

## Codec (раздел и C, 9 бит) {#codec-섹션과-c-9비트}

| TAG ID | Имя | Значение |
|---|---|---|
| В начале области каждого Kind | прямой код | Codec определяется одним TAG WORD |
| `0x05DL`, `0x09DL`, `0x1BDL` | REFERENCE-ISSUER-2WORD, VALUE-ISSUER-2WORD, EDGE-ISSUER-2WORD | Issuer в 2 WORD и номер Codec в 2 WORD в расширяющем TAG Codec |
| `0x05EL`, `0x09EL`, `0x1BEL` | REFERENCE-ISSUER-4WORD, VALUE-ISSUER-4WORD, EDGE-ISSUER-4WORD | Issuer в 4 WORD и номер Codec в 2 WORD в расширяющем TAG Codec |
| `0x05FL`, `0x09FL`, `0x1BFL` | REFERENCE-ISSUER-16WORD, VALUE-ISSUER-16WORD, EDGE-ISSUER-16WORD | Issuer в 16 WORD и номер Codec в 2 WORD в расширяющем TAG Codec |

- **Последние три позиции области каждого Kind — это ISSUER.** Ширину Issuer задают два младших бита C (`01` — 2 WORD, `10` — 4 WORD, `11` — 16 WORD). У Meta формата Issuer нет.
- `C` прямого кода в каждом разделе своё. Одно и то же значение `C` в разных разделах — разные Codec. Codec ID прямого кода — весь TAG WORD (L=0), поэтому Kind в нём содержится.
- Номер Codec Issuer — единое пространство на Issuer независимо от Kind. Issuer назначает номера в своём `codecs/` без пересечений ([Адрес публикации и список версий](publishing.md#id-표기)).
- Codec, не являющийся прямым кодом, — пара `(Issuer, номер Codec)`. Номер Codec определяет данный Issuer ([Issuer и публикация](issuer.md)). Расширяющий формат размещается под Issuer организации, установившей этот формат.
- Codec, у которого есть прямой код, отдельно в формате Issuer не регистрируется.
- Формат Issuer есть у Reference, Value и Edge. Meta — общая спецификация, которую определяет только GEUL.
- Раздел прямого кода Edge (`w >> 9`) — это семейство. Прямые коды Value и Meta не выражают семейство и класс битами. Смысл номера Codec определяет Issuer.
- Прямой код нельзя отозвать. В прямые коды помещаются только форматы с подтверждённой частотой.

## Запись формата Issuer {#issuer-형식-레코드}

```
TAG WORD          код ISSUER (последние три позиции области каждого Kind)
[расширяющий TAG Length]
Issuer            2/4/16 WORD (ширину определяет Codec)
Номер Codec       2 WORD. Определяет Issuer
Payload           определяется документом Codec, выпущенным Issuer
```

- Макет у трёх Kind одинаков. Если номеров не хватает, получают ещё один Issuer.
- Payload Edge (EDGE-ISSUER), как у других Edge, начинается с Edge Id. Поэтому порядок такой: TAG, Issuer, номер Codec, Edge Id, остальной Payload.
- Декодер, не знающий формата, доходит до Issuer и номера Codec и пропускает запись по Length.

## Последовательность байтов переменной длины {#가변-길이-바이트열}

Значения, длина которых измеряется в байтах (текст, URI, языковой тег, неопознанная последовательность байтов), получают Codec (или номер Codec) в виде **чётной и нечётной пары**.

- Если младший бит Codec (у прямого кода — младший бит C) равен `0`, число байтов чётное, если `1` — нечётное.
- Число байтов = `2 × число WORD Payload − младший бит`. Поля Byte Count нет.
- Если число нечётное, младший байт последнего WORD — дополнение `0x00`. Если он не `0x00`, запись отвергается.
- Пустая последовательность байтов — 1-WORD запись (только TAG WORD) чётного Codec.
- Для значений фиксированного размера (UUID, дайджест, адрес) пара не заводится.

## Пример: чтение TAG WORD {#예-tag-word-읽기}

Разберём `0AA9`.

```
0x0AA9 = 0000 1010 1010 1001
         000 | 0101 | 01010 | 1001
Prefix 000, раздел 0101 (5, Edge), C 01010, Codec 0x0AAL (TRIPLE), Length 1001 (10 WORD)
```

Эта запись — Edge длиной 10 WORD, а Codec — TRIPLE. Даже без кодекбука известно, что следующая запись находится через 10 WORD.

## Маркер места {#자리-표지}

TAG WORD `0x0000`, `0x0010`, `0x0020` — это 1-WORD записи маркера места Reference. Они ни на что не указывают и занимают место поля записи ([Маркер места](slot-marker.md)).

```
0x0000, 0x0010, 0x0020 = 0000 0000 00CC 0000
                         Prefix 000, раздел 0 (Reference), C 0~2, LLLL 0000 (1 WORD)
```

| WORD | Имя | Значение | О чём высказывание | Логика | Допущение о мире | Викиданные |
|---|---|---|---|---|---|---|
| `0x0000` | ABSENT | не записано | О документе: это место не заполнено | нет утверждения | открытый мир | нет snak |
| `0x0010` | UNKNOWN-VALUE | неизвестно | О мире: значение есть, но неизвестно какое | `∃x. P(s, x)` | существование замкнуто, личность открыта | `somevalue` |
| `0x0020` | NO-VALUE | нет | О мире: значения нет | `¬∃x. P(s, x)` | замкнут для (s, P, ограничивающее условие) | `novalue` |

- Пример: если у детей (P40) стоит ABSENT — число неизвестно, UNKNOWN-VALUE — 1 или больше, NO-VALUE — 0. Если у момента окончания (P582) стоит ABSENT — неизвестно, действует ли ещё, UNKNOWN-VALUE — закончилось, но когда — неизвестно, NO-VALUE — не закончилось.
- Маркер действителен, только если список CODEC поля содержит этот WORD как точную цель. Шаблоны, поля без CODEC, места записей HEAD и BODY и место Edge Id недействительны ([CODEC](edge/0x0BEL-codec.md)).
- Обязанности читающей стороны:
  1. UNKNOWN-VALUE — не значение, а утверждение о существовании. Он не равен и не отличен ни от какого значения, и два UNKNOWN-VALUE тоже не считаются одним значением. TRIPLE с UNKNOWN-VALUE не объединяются как дубликаты.
  2. NO-VALUE замкнут в пределах ограничивающего условия этого суждения. Если он сосуществует с TRIPLE значения с теми же Subject, Predicate и rank, у которых ограничивающие условия не различаются, это противоречие, и проверяющий выдаёт предупреждение (не отвергает).
  3. rank применяется так же. При выборе представительного значения (truthy) TRIPLE с обоими маркерами тоже являются кандидатами.
  4. Если маркер используется как значение QUALIFIER, он меняет смысл этого ограничения (`P582 = UNKNOWN`: закончилось, момент неизвестен. `P582 = NONE`: не закончилось).
  5. ABSENT ничего не говорит о мире. Значение, которое не удалось перенести, не записывается как UNKNOWN-VALUE.

## Каноническая форма {#정규형}

Одно и то же содержание должно давать одни и те же байты. Только тогда хеш содержимого и подпись определяются однозначно.

- Длина записывается самой короткой формой (1~14 WORD — прямая длина).
- Целые записываются в самой короткой ширине. Применяется каноническая форма, заданная спецификацией каждого Codec.
- Запись, не являющаяся канонической, отвергается.
- Исключение: `L=1111` в целевом WORD [CODEC](edge/0x0BEL-codec.md) учитывает только раздел `KKKK` независимо от значения `C`. Рекомендуется первая позиция раздела (`C = 0`), но другое `C` в том же разделе не отвергается.
