Описательные Edge, фиксирующие публикацию, deprecate и удаление документа, и спецификация документа списка версий, который пишется этими Edge. Определяет формат списка версий из раздела [адрес публикации и список версий](/ru/grammar/publishing/#список-версий).

## Коды

| Codec | Название | Payload |
|---|---|---|
| `0x18` | PUBLICATION | Edge Id, DOC-POINTER, хеш содержимого |
| `0x19` | DEPRECATION | Edge Id, DOC-POINTER |
| `0x1A` | TOMBSTONE | Edge Id, DOC-POINTER, категория причины |

- Эти три кода встроены в декодер ([слой 0](/ru/grammar/publishing/#уровни)). Список версий интерпретируется без обращения к кодбуку.
- Подформатов (TAG своего вида у каждого Codec) нет. Полностью соблюдается правило [Edge](/ru/grammar/edge/): первый элемент Payload -- Edge Id.

## Раскладка

```
TAG WORD          Edge, Codec 0x18 / 0x19 / 0x1A
[TAG расширения Length]
Edge Id           запись LOCAL Reference
Документ          запись DOC-POINTER Reference (Issuer, ID документа, ID версии)
Хеш содержимого   16 WORD   (PUBLICATION)
Категория причины 1 WORD    (TOMBSTONE)
```

| Поле | Ширина | Описание |
|---|---|---|
| Edge Id | запись LOCAL Reference | Порядковый номер в списке. Нумеруется с 1 и дописывается подряд |
| Документ | запись DOC-POINTER | Одна версия опубликованного документа ([DOC-POINTER](/ru/grammar/reference/doc-pointer/)). Issuer и ID документа те же, что у документа, список которого ведётся. Благодаря этому документ списка сам говорит, чей это список, и без пути. ID версии -- порядковый номер внутри этого документа (версия [документа](/ru/grammar/document/)), `0` (последняя) не используется |
| Хеш содержимого | 16 WORD | Хеш содержимого этой версии (SHA-256, хеш содержимого [документа](/ru/grammar/document/)) |
| Категория причины | 1 WORD | Код категории причины удаления. Таблица кодов -- открытый вопрос |

- Длина после DOC-POINTER фиксирована для каждого кода (16, 0, 1 WORD). Если иная, запись отвергается.
- Время в запись не вносят. Моментом публикации, deprecate или удаления служит `RECORDED-AT` документа списка, в который эта запись попала впервые.

## Документ списка версий

Место публикации ведёт для каждого документа один документ списка версий, дописывая его: `/<Issuer>/<ID документа>/versions.geul`. В один список входят все версии этого документа, опубликованные в этом месте публикации.

```
DOC-1WORD/2WORD/4WORD     общая длина
  SPEC-VERSION            0x0001 (v1)
  PARENT                  Value SHA-256-DIGEST. Хеш содержимого предыдущего документа списка (у первого списка нет)
  RECORDED-AT             Value POSIX-TIMESTAMP-SECONDS. Момент выпуска этого списка
  NEXT-LOCAL-ID           следующий назначаемый LOCAL ID (если есть версии)
  SIGNATURE               Подпись места публикации. Цель -- хеш содержимого этого документа списка
BODY
  PUBLICATION · DEPRECATION · TOMBSTONE · BIND …
END
```

- Meta HEAD: [SPEC-VERSION](/ru/grammar/meta/declaration/spec-version/), [PARENT](/ru/grammar/meta/lineage/parent/), [RECORDED-AT](/ru/grammar/meta/provenance/recorded-at/), [NEXT-LOCAL-ID](/ru/grammar/meta/lineage/next-local-id/), [SIGNATURE](/ru/grammar/meta/verification/signature/).
- В документе списка `DOC-ID` не ставят (исключение для документа, имя которого не начинается с `0x`, [DOC-ID](/ru/grammar/meta/declaration/doc-id/)). Список -- не опубликованный документ, а сопутствующая запись документа. Чей это список, говорит ID документа в записях. Поэтому даже полученный без пути (`h/`, дамп) он показывает, чей он.
- ID документа во всех записях должен быть документом, список которого ведётся. Записи другого документа отвергаются.
- В документе списка нет IMPORT, используются только Codec слоя 0. В другой список его не включают (списка списков нет).
- Новый документ списка ставит BODY предыдущего документа списка без изменений в начало и дописывает записи. Ничего не исправляется, не удаляется и не переставляется.
- Список подписывает место публикации. Публикации geul.org подписывает geul.org (GEUL Issuer), частные публикации -- свой Issuer.
- ID документа `0x0000000000000000` -- индексный документ определений терминов Issuer ([Issuer и публикация](/ru/grammar/issuer/)). На сам Issuer указывают через [ISSUER-POINTER](/ru/grammar/reference/issuer-pointer/).

## Правила

- ID версии в PUBLICATION идёт по возрастанию с 1 без пропусков. ID версии назначает место публикации.
- Один и тот же хеш содержимого повторно не публикуют. Если он уже есть, возвращают его ID версии.
- DEPRECATION и TOMBSTONE указывают только на ID версии ранее встречавшегося PUBLICATION. Указание на несуществующую версию отвергается.
- Состояние версии вычисляют, применяя записи по порядку: опубликована → deprecated → удалена. Удалённую версию повторно не публикуют и не отдают.
- Последняя версия -- версия с наибольшим ID, которая не deprecated и не удалена.
- Если ID версии доходит до конца 2 WORD, документ больше не публикуют и выпускают под новым ID документа.

## Имя документа

Имя документа для адреса привязывает через [BIND](/ru/grammar/edge/bind/) индекс имён Issuer `/<Issuer>/documents.geul` ([адрес публикации и список версий](/ru/grammar/publishing/#имя-документа)). Интерпретатор читает только этот индекс.

Тот же BIND можно поставить и в документе списка (необязательно). Если ставят, соблюдают следующее.

- Subject -- `DOC-POINTER` (Issuer, ID документа этого списка, версия `0`). Имя привязывается не к версии, а к документу, поэтому версия `0`.
- Привязывают только к документу, перед которым встретился PUBLICATION. Имя документу, никогда не публиковавшемуся, не привязывают.
- Имя следует правилу имён документов (slug из строчных ASCII) и должно совпадать с BIND индекса имён.
- При смене имени дописывают новый BIND. Прежнее имя остаётся и указывает на тот же документ. Основное имя -- последний BIND.
- Внутри документа его собственное имя не записывают.

## Адрес

```
/.well-known/geul/<Issuer>/<ID документа>/versions.geul             последний документ списка (изменяемый)
/.well-known/geul/h/<хеш содержимого>.geul                           прошлые документы списка (неизменяемые)
```

- Изменяем только один адрес последнего списка. Полученный список проверяют по подписи, `RECORDED-AT` и цепочке `PARENT`.
- Все прошлые документы списка остаются в `h/`. По цепочке `PARENT` можно восстановить список на любой момент.

## Проверка

- В документе списка должна быть `SIGNATURE` с ключом определённого места публикации.
- ID документа в записях должен совпадать с запрошенным ID документа.
- Хеш содержимого предыдущего списка, оставшийся в записи блокировки, должен быть в цепочке `PARENT` нового списка. BODY того списка должен совпадать с началом BODY нового списка.
- Хеш содержимого полученного документа должен совпадать со значением, записанным в PUBLICATION с этим ID версии, а `DOC-ID` документа должен совпадать с запрошенными Issuer и ID документа.

## Открытые вопросы

- Таблица кодов категорий причин.
- Алгоритм подписи по умолчанию и раскладка Payload `SIGNATURE`.
- Когда и в каком формате переходить на лог Merkle (доказательства включения и согласованности), когда список растёт.
- Объединять ли BIND списка и индекс имён `documents.geul` в один, подпись индекса.
- Защита от отката на уровне Issuer. Поскольку список образует отдельную цепочку для каждого документа, атака, подсовывающая старый список только одного документа, блокируется лишь цепочкой этого документа.
