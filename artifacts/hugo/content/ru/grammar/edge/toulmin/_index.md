Edge семейства TOULMIN (два старших бита Codec `11`, прямые коды `0x60`~`0x7B`) записывает граф вердиктов и выполнения по модели аргументации Тулмина. Объявления утверждений, возражений и исключений, отношения атаки и вытеснения, связи выполнения и результаты вердикта — всё это Edge. Один документ TANGEUL (язык правил движка toulmin) становится одним документом GEUL. Расширение файла то же, что у других документов: `.geul`.

То, что не определено на этой странице, следует общим правилам [Edge](/ru/grammar/edge/) и [записи и TAG WORD](/ru/grammar/record/).

## Метапознание и самопересмотр

TOULMIN является Codec GEUL, чтобы GEUL мог осознавать самого себя. Правила вердикта и выполнения тоже должны быть записаны на GEUL: тогда TOULMIN может взять эти правила объектом и исправить их сам. Поэтому TOULMIN — не прикладной профиль, а ядро работы GEUL, и он размещён в пространстве прямых кодов Edge (`0x60`~`0x7B`).

- Самоописание делает возможным самоулучшение, но несёт риск циркулярной ошибки. Если правило само выносит вердикт о собственном пересмотре, то пересмотр, ослабляющий критерий вердикта, тоже может пройти (доля прохождений растёт, реальная точность падает).
- Циркулярность принимается как риск, но разрывается структурой.
  - **Фиксированное ядро**: семантика вердикта (Pass, Review, Fail, атака, вытеснение, приоритет, трёхзначная оценка и U → Review из раздела [Вердикт при неизвестных значениях](#вердикт-при-неизвестных-значениях) ниже) зафиксирована в этой спецификации. Документом TOULMIN её изменить нельзя. Это то же место, что и правила, встроенные в декодер (слой 0 в [Адрес публикации и список версий](/ru/grammar/publishing/#уровни)).
  - **Разделение версий**: пересмотр версии правил v(n) оценивается правилами v(n−1) и внешней проверкой. Правило не выносит вердикт о себе. Результат вердикта лежит в документе, отличном от объекта (хеш содержимого объекта не меняется).
  - **Неизменяемая история**: пересмотры накапливаются как новые версии (`PARENT`, хеш содержимого, подпись). Старые версии остаются, поэтому циркулярную ошибку можно найти задним числом и откатить. Страховка самопересмотра — модель версий GEUL ([Документ](/ru/grammar/document/#редакции)).
  - **Внешний критерий**: отдельно хранится набор тестовых случаев, которых путь пересмотра не может касаться. Принятие пересмотра проверяется по результату на этом наборе.
- Опровергающий тест: намеренно внедряется одно ошибочное правило. Если система исправляет его и оценка по внешнему критерию растёт, самоулучшение работает. Если растёт только доля прохождений, а оценка по внешнему критерию падает, это циркулярная ошибка.

## Коды

Запись TOULMIN использует одну из трёх раскладок. Раскладку определяет Codec (или номер формата).

| Раскладка | Применение | Страница |
|---|---|---|
| NODE | узлы графа: дело, правило, определение, точка входа | [NODE](/ru/grammar/edge/toulmin/node/) |
| LINK | отношения между узлами (атака, вытеснение, выполнение, определение) | [LINK](/ru/grammar/edge/toulmin/link/) |
| EXPR | условное выражение (предикат) | [EXPR](/ru/grammar/edge/toulmin/expr/) |

Исходный текст и записи разделов (SOURCE, TEXT, SECTION, CASE-BEGIN·CASE-END, PROSE) определены на странице [SOURCE и разделы](/ru/grammar/edge/toulmin/source/).

### Прямые коды

| Codec | Имя | Раскладка | TANGEUL | Смысл |
|---|---|---|---|---|
| `0x60` | [CASE-DECLARE](/ru/grammar/edge/toulmin/node/) | NODE | `in case of` | Объявление дела. Граф вердиктов, содержащий узлы и отношения |
| `0x61` | [PREDICATE-DECLARE](/ru/grammar/edge/toulmin/expr/) | EXPR | Условное выражение в Rules | Объявление предиката. Выражение вердикта |
| `0x62` | [SPEC-DECLARE](/ru/grammar/edge/toulmin/node/) | NODE | Элемент Definitions | Объявление критерия суждения (Backing). Биты role задают вид определения |
| `0x63` | [RULE-DECLARE](/ru/grammar/edge/toulmin/node/) | NODE | general rule, имя правила в Rules | Объявление утверждения (Warrant). Может быть атаковано |
| `0x64` | [COUNTER-DECLARE](/ru/grammar/edge/toulmin/node/) | NODE | counter rule | Объявление возражения. Атакует, имея собственный вывод. Level по умолчанию — Fail |
| `0x65` | [EXCEPT-DECLARE](/ru/grammar/edge/toulmin/node/) | NODE | except rule | Объявление исключения. Атакует без собственного вывода. Level по умолчанию — Review |
| `0x68` | [ATTACKS](/ru/grammar/edge/toulmin/link/) | LINK | `don't X when Y` | Отношение атаки. Вердикт атакующего постепенно снижает вердикт цели с интенсивностью атаки (0~1, по умолчанию 1) |
| `0x69` | [SUPERSEDES](/ru/grammar/edge/toulmin/link/) | LINK | `X supersedes Y` | Отношение вытеснения. Если атакующий Active, цель окончательно исключается из агрегации. Цепочка (`A > B > C`) записывается по одной записи на пару |
| `0x6A` | SUPERSEDE-CHAIN | — | | Цепочка приоритета `A > B > C`. Сокращение попарных SUPERSEDES. Назначен только код, раскладки пока нет |
| `0x70` | [RUN](/ru/grammar/edge/toulmin/link/) | LINK | `run c when n` | Композиция выполнения. Если узел Active, выполняет подчинённое дело (DAG) |
| `0x71` | [DO](/ru/grammar/edge/toulmin/link/) | LINK | `do fn when n` | Действие, выполняемое, если узел Active |
| `0x72` | [DO-ONCE](/ru/grammar/edge/toulmin/link/) | LINK | `do fn once when n` | Действие, выполняемое один раз даже при повторах |
| `0x73` | [UNDO](/ru/grammar/edge/toulmin/link/) | LINK | `undo fn when n` | Компенсирующее действие для DO (saga). Если последующий шаг не удался, выполняется в обратном порядке |
| `0x74` | [CHECKING](/ru/grammar/edge/toulmin/link/) | LINK | `checking c` | Связь, которая только выносит вердикт, без побочных эффектов |
| `0x75` | [ENTRY](/ru/grammar/edge/toulmin/node/) | NODE | `provides x` | Внешняя точка входа. Выполняет дело или выносит по нему вердикт |
| `0x76` | [TRIGGER](/ru/grammar/edge/toulmin/node/) | NODE | `on`, `every`, `until` | Точка входа по событию или периоду, без внешнего вызова |
| `0x78` | VERDICT | — | | Результат вердикта узла или записи. Итог (Pass, Review, Fail), значение вердикта, Activated, Excluded, Level. Назначен только код, раскладки пока нет |
| `0x79` | EVIDENCE | — | | Свидетельство вердикта. Позиция, ожидаемое значение, фактическое значение (Fact). Назначен только код, раскладки пока нет |
| `0x7C`~`0x7F` | ISSUER-* | | | Форматы, определённые Issuer. См. ниже «Форматы ISSUER» |

- Прямые коды, отсутствующие в таблице (`0x66`·`0x67`, `0x6B`~`0x6F`, `0x77`, `0x7A`·`0x7B`), зарезервированы.
- Группу задают два старших бита из младших 5 бит Codec: `00` объявление, `01` отношение, `10` выполнение, `11` результат (`0x7C`~`0x7F` — ISSUER).
- Вердикт по документу в целом ведёт Meta [VERDICT](/ru/grammar/meta/verification/verdict/) (`0x44`), вердикт по узлу или записи — TOULMIN `VERDICT` (Edge `0x78`). Это два разных Codec с разными Kind.

### Форматы ISSUER

Записи TOULMIN, для которых не хватает прямых кодов, задаются номером формата под Issuer `0x0000` (GEUL) в `ISSUER-1WORD` (`0x7C`). Номера форматов принадлежат семейству TOULMIN (`0xC000`~`0xFFFF`, два старших бита `11`).

```
TAG WORD          0001 0LLL L111 1100      Edge, Codec 0x7C
[Length extension TAG]
Issuer            0x0000
Номер формата     0xC000~0xC029
Edge Id           запись LOCAL Reference
Компоненты        раскладка, заданная форматом
```

| Номер формата | Имя | Раскладка | Смысл |
|---|---|---|---|
| `0xC000` | [SOURCE](/ru/grammar/edge/toulmin/source/) | ID, WORD ширины SPAN, UTF8 Value | Авторский исходный текст |
| `0xC001` | [TEXT](/ru/grammar/edge/toulmin/source/) | ID, UTF8 Value | Имя или строка |
| `0xC002` | [SECTION](/ru/grammar/edge/toulmin/source/) | ID, код раздела 1 WORD | Начало раздела |
| `0xC003` | [CASE-BEGIN](/ru/grammar/edge/toulmin/source/) | ID, REF (дело) | Начало области дела |
| `0xC004` | [CASE-END](/ru/grammar/edge/toulmin/source/) | ID, REF (дело) | Конец области дела |
| `0xC005` | [PROSE](/ru/grammar/edge/toulmin/source/) | ID, SPAN | Абзац повествования |
| `0xC010` | [NAMESPACE](/ru/grammar/edge/toulmin/node/) | NODE | `this document is` |
| `0xC011` | [FUNC](/ru/grammar/edge/toulmin/node/) | NODE | Ссылка на функцию |
| `0xC012` | [FIELD](/ru/grammar/edge/toulmin/node/) | NODE | `is required` |
| `0xC013` | [ALIAS](/ru/grammar/edge/toulmin/node/) | NODE | `see … from` |
| `0xC014` | [GROUP](/ru/grammar/edge/toulmin/node/) | NODE | Упорядоченная группа выполнения |
| `0xC020` | [REQUIRES](/ru/grammar/edge/toulmin/link/) | LINK | дело → поле |
| `0xC021` | [MEANS](/ru/grammar/edge/toulmin/link/) | LINK | элемент определения → значение или тип |
| `0xC022` | [HAS](/ru/grammar/edge/toulmin/link/) | LINK | элемент определения → поле |
| `0xC023` | [RUNS](/ru/grammar/edge/toulmin/link/) | LINK | точка входа → дело, выполнение |
| `0xC024` | [EVALUATES](/ru/grammar/edge/toulmin/link/) | LINK | точка входа → дело, вердикт |
| `0xC025` | [TRIGGERS](/ru/grammar/edge/toulmin/link/) | LINK | триггер → дело |
| `0xC026` | [UNTIL](/ru/grammar/edge/toulmin/link/) | LINK | триггер → дело (`every … until`) |
| `0xC027` | [SAME-AS](/ru/grammar/edge/toulmin/link/) | LINK | узел → глобальный идентификатор |
| `0xC028` | [IMPORTED-FROM](/ru/grammar/edge/toulmin/link/) | LINK | алиас → путь (TEXT) |
| `0xC029` | [LABEL](/ru/grammar/edge/toulmin/link/) | LINK | узел → TEXT, запись имени |

- Пространство номеров форматов отдельное для каждого Kind. Формат GEUL `0xC000` у Value (OPAQUE-BYTES-EVEN) и `0xC000` у Edge (SOURCE) — разные форматы.
- Номера форматов только добавляются. Назначенный номер другому формату повторно не выдаётся.

## Документ

Один файл `.geul` — это один DOC. За пределами DOC других байтов нет.

```
DOC-1WORD/2WORD/4WORD     полная длина
  SPEC-VERSION            0x0001 (v1, целое без встроенного Value)
  PROFILE                 UTF8 Value "tangeul-<major>.<minor>". Сейчас "tangeul-1.0"
  [DEFAULT-LANGUAGE]      LANGUAGE-BCP47-CODE Value. Локаль написания ("en", "ko")
BODY
  SOURCE                  авторский исходный текст. Первая запись BODY
  записи предложений …    в порядке объявления в документе
END
```

- HEAD: [SPEC-VERSION](/ru/grammar/meta/declaration/spec-version/), [PROFILE](/ru/grammar/meta/declaration/profile/), необязательный [DEFAULT-LANGUAGE](/ru/grammar/meta/declaration/default-language/).
- Декодер отклоняет документ, если SPEC-VERSION отличается или major в PROFILE отличается. Если отличается только minor, документ читается.
- Первая запись BODY — SOURCE. Каждый SPAN — диапазон внутри этого исходного текста.
- Порядок записей предложений совпадает с порядком объявления в документе. На этот порядок опирается порядок выполнения (срабатывание `do`·`run`, компенсация `undo` в обратном порядке). В документе TOULMIN порядок Edge имеет значение (исключение из правила порядка в [Edge](/ru/grammar/edge/)).
- Все записи BODY — Edge. Отдельных Value-записей нет. Значения встроены в Payload Edge.
- Идентичность дела и импорт используют Meta [DOC-ID](/ru/grammar/meta/declaration/doc-id/) и [IMPORT-DOC](/ru/grammar/meta/import/import-doc/) (Subject и See в TANGEUL).

## Общие поля

| Поле | Ширина | Описание |
|---|---|---|
| ID | запись LOCAL Reference | Edge Id записи. Первый элемент Payload любой записи |
| REF | запись LOCAL Reference | Edge Id, указывающий на другую запись этого документа. `0` означает «нет» |
| SPAN | ширина, заданная SOURCE × 2 | Диапазон в авторском исходном тексте. Начальный байт, число байтов |

- ID и REF — встроенные записи [LOCAL](/ru/grammar/reference/local/) Reference (`0000 0LLL L000 1000` + ID наименьшей ширины). Ширину задаёт Length этой записи, на уровне документа она не объявляется.
- REF `0` (LOCAL `0`) означает «нет». Это правило Codec, в котором LOCAL `0` используется как «нет» ([LOCAL](/ru/grammar/reference/local/)).
- Edge Id назначаются начиная с 1 и не повторяются в документе. `0` — это «нет» для REF, поэтому как Edge Id не используется.
- На узлы другие записи ссылаются вперёд, поэтому узлы первыми получают номера в порядке объявления в документе. Остальные записи (SOURCE, TEXT, LINK, FUNC, записи разделов) получают номера от кодировщика, начиная со следующего за узлами.
- Декодер проверяет только то, что Edge Id не равен 0 и не повторяется. Порядок назначения при интерпретации не используется.
- На узлы и отношения указывают по Edge Id.
- Встроенный Value — это запись Value целиком, включая TAG WORD. Длину задаёт её TAG.

## Числа

- Значение вердикта (−1~1), Qualifier (0~1) и интенсивность атаки (0~1) — это Value [SIGNED-DECIMAL](/ru/grammar/value/decimal/signed-decimal/). Отдельного формата с фиксированной запятой нет.
- Кодировщик отбрасывает конечные нули коэффициента. 0.8 — это `C=8, E=−1`. Декодер принимает до 4 знаков после запятой.
- Порог уверенности (например, `at least 75%`) записывается WORD оператора сравнения и Value [UNSIGNED-DECIMAL](/ru/grammar/value/decimal/unsigned-decimal/) в процентах (`E=0`) ([LINK](/ru/grammar/edge/toulmin/link/) F_GATE).
- Интенсивность атаки — поле F_FORCE в ATTACKS ([LINK](/ru/grammar/edge/toulmin/link/#интенсивность-атаки)). Вне диапазона запись отклоняется.

## Оси объявления узла

- Объявление узла (RULE·COUNTER·EXCEPT-DECLARE) имеет роль (утверждение, возражение, исключение), Qualifier (0~1) и Level (Unset, Fail, Review). Роль несёт Codec и поле role заголовка NODE, Qualifier — F_QUAL, Level — поле level заголовка ([NODE](/ru/grammar/edge/toulmin/node/)).
- Сила (Strict, Defeasible, Defeater) — ось, независимая от роли. Размещение силы пока не определено.
- Интенсивность атаки (Force) — значение не узла, а ребра ATTACKS ([LINK](/ru/grammar/edge/toulmin/link/#интенсивность-атаки) F_FORCE). Это ось, отличная от силы.

## Вердикт при неизвестных значениях

Когда граф вердиктов получает на вход факты GEUL, три понятия [маркера слота](/ru/grammar/reference/slot-marker/) (не записано, неизвестно, нет) оцениваются по-разному. Оценка операторов сравнения [EXPR](/ru/grammar/edge/toulmin/expr/) такова.

| Вход | `is empty` | `is not empty` | `equals` / `is in` / сравнение величин |
|---|---|---|---|
| Значение v | ложь | истина | оценка по v |
| NO-VALUE (нет) | **истина** | ложь | ложь |
| UNKNOWN-VALUE (неизвестно) | ложь | **истина** | **неопределённо (U)** |
| ABSENT (не записано) / утверждения нет | U (открытый мир) | U | U |

- Логика — сильная трёхзначная логика Клини. `NOT U = U`, `ложь AND U = ложь`, `истина OR U = истина`. В остальных комбинациях U даёт U.
- `EXISTS any` истинно, если истинен хотя бы один элемент. Если истинных нет, но есть U, результат U; если все ложны, результат ложь.
- **Если предикат равен U, вердикт узла — не Pass и не Fail, а Review.** Если неизвестно, решение передаётся человеку (или следующему этапу).
- Чтобы рассматривать ABSENT как empty, а не как U, входная сторона должна **объявить** закрытый мир (передать через критерий SPEC, например: «вход этого дела полон»). Без объявления это U.
- Эта таблица и соответствие U → Review определяют семантику вердикта, поэтому это **фиксированное ядро**. Документом TOULMIN изменить её нельзя.
- Пример: правило «считать только границы, действующие и сейчас» (`P582 is empty`) при P582 = UNKNOWN-VALUE ложно и потому исключает, при P582 = NO-VALUE истинно и потому включает, а если P582 отсутствует, даёт U и отправляется на Review.

## Результат вердикта

- Результат вердикта (`VERDICT`, `EVIDENCE`) лежит в документе, отличном от объекта вердикта. Документ результата импортирует документ объекта через [IMPORT-DOC](/ru/grammar/meta/import/import-doc/) и указывает на него через [EXTERNAL-POINTER-*](/ru/grammar/reference/external-pointer/). Поэтому вынесение вердикта не меняет хеш содержимого документа-объекта.
- Вердикт по документу в целом — Meta `VERDICT`, вердикт по узлу или записи — TOULMIN `VERDICT`.
- Правила выбора применимой версии пересмотра (переходные положения, выбор между законом времени действия и новым законом), а также толкования и прецеденты тоже записываются как правила вердикта ([Документ](/ru/grammar/document/#редакции)).

## Открытые вопросы

- Раскладки SUPERSEDE-CHAIN (`0x6A`), VERDICT (`0x78`), EVIDENCE (`0x79`). Достаточно ли цепочек при нынешнем способе записи SUPERSEDES по одной записи на пару.
- Размещение силы узла (Strict, Defeasible, Defeater).
- ATTACKS с явной интенсивностью 1 и ATTACKS без интенсивности дают одинаковый вердикт, но различаются байтами. Совпадение вердиктов нужно проверять по декодированным значениям, а не по байтам.
- В EXPR число узлов, число меток и индекс метки занимают 1 WORD, а число дочерних — 13 бит. Верхние границы фиксированы.
- Раскладка PROVENANCE (источник и посылки правила).
- Записывать ли имя в обратных кавычках не как TEXT + LABEL (`0xC029`), а через повествовательные [LABEL](/ru/grammar/edge/label/)·[BIND](/ru/grammar/edge/bind/).
- Таблица значений кодов predicate·mode у Claim и значений VerbCode у FuncRef.
- Делать ли объявление закрытого мира (чтение ABSENT как empty) критерием (SPEC) или единицей дела.
- [Документ спецификации Codec](/ru/grammar/codec-spec/) для Codec TOULMIN. Условные поля NODE и LINK и ширина SPAN, задаваемая SOURCE, — раскладки, которые нельзя объявить через FIELD.
