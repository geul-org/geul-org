CODEC -- описательный Edge, который задаёт один Kind и Codec, принимаемые одним [FIELD](/ru/grammar/edge/field/). Codec `0x1E`.

Как [ENUM](/ru/grammar/edge/enum/) придаёт смысл одному коду сырого значения, так CODEC придаёт полю один формат. Один CODEC -- один формат, поэтому можно задать несколько. Раскладка встроена в декодер ([документ спецификации Codec](/ru/grammar/codec-spec/)).

## Раскладка

```
TAG WORD          0001 0LLL L001 1110
[TAG расширения Length]
Edge Id           запись LOCAL Reference
Поле              запись LOCAL Reference, указывающая на Edge FIELD
Цель              1 WORD. 000K KLLL LCCC CCCC (LLLL = 0000 точно, 1111 wildcard)
```

## WORD цели

- Места Kind (`KK`) и Codec (`CCCCCCC`) из TAG WORD остаются как есть. Старшие 3 бита -- 0. `LLLL` -- `0000` (точно) или `1111` (wildcard); другие значения invalid.
- Точная цель (`LLLL = 0000`) -- то же значение, что ID документа спецификации Codec (например, LOCAL `0x0008`, COORDINATE-EARTH `0x0804`, UTF8-LANGUAGE-TEXT `0x084A`). Поэтому цель прямо указывает на документ спецификации этого Codec.
- Пары кодов чётный-нечётный (текст, байтовая строка) тоже задают точными кодами. Чтобы принимать и чётный, и нечётный, указывают оба. Правила совместной интерпретации пары нет (есть соседние коды, не образующие пару, как NUMERIC `0x04`/`0x05`).

### Wildcard (`LLLL = 1111`)

- Kind должен совпадать, а **группа битов Codec, равная 0, совпадает с чем угодно**. У Reference `CCCC` (Codec) и `QQQ` (Quantifier) -- отдельные группы, у остальных Kind все 7 бит -- одна группа.

| Цель | Смысл |
|---|---|
| `0780` | Любой Reference |
| `07A0` | WIKIDATA-QID, Quantifier не важен |
| `0781` | Любой Codec Reference, Quantifier Generic (`001`) |
| `0F80` | Любой Value |
| `1780`, `1F80` | Любой Edge, любой Meta |

- Wildcard, которому нечему соответствовать, invalid. У Value, Edge и Meta Codec должен быть 0, а у Reference `CCCC` или `QQQ` должен быть 0. Reference `CCCC = 0000` (маркер слота) -- зарезервированный Codec, поэтому **он не соответствует ни одному wildcard** (`0780` не принимает ABSENT, UNKNOWN-VALUE, NO-VALUE). В то же время у Kind, где Codec 0 назначен (Value `0x00` (BOOL), Edge `0x00` (REFERENCE-NODE)), wildcard включает и его (чтобы принимать только BOOL, используют `LLLL = 0000`).
- Wildcard не указывает на документ спецификации.
- Выражения, которое фиксирует только одну ненулевую группу и при этом нулевую группу тоже фиксирует (например, «любой Reference, но только Identified»), нет. Такой список составляют перечислением точных целей.
- В 7 битах Codec у Reference содержится Quantifier (`QQQ`). Цель задаёт Quantifier точно. Чтобы принимать несколько Quantifier, ставят несколько CODEC.

### Маркер слота (цель `0000`~`0002`)

[Маркер слота](/ru/grammar/reference/slot-marker/) -- группа записей длиной 1 WORD в зарезервированном Codec Reference `0000`. Младшие 3 бита -- номер маркера (это не Quantifier).

| Цель | Маркер | Смысл |
|---|---|---|
| `0000` | ABSENT | Не записано. Поле необязательное |
| `0001` | UNKNOWN-VALUE | Неизвестно. Принимает утверждение, что значение есть |
| `0002` | NO-VALUE | Нет. Принимает утверждение, что значения нет |
| `0003`~`0007` | Резерв | |

- **Правило приёма:** маркер допустим только тогда, когда в списке CODEC поля тот же WORD есть как точная цель. Wildcard и поле-запись без CODEC («любая запись») маркеры не принимают. Маркер на месте записи HEAD или BODY и на месте Edge Id invalid.
- Список, состоящий только из целей-маркеров (всегда маркер), invalid (обобщение правила списка, состоящего только из `0000`). Его используют вместе с wildcard или точной целью (`0780` + `0000` = любой Reference или пропуск).
- Для поля с сырым значением цель-маркер задать нельзя. У сырого значения нет TAG и ширина фиксирована, поэтому для маркера в 1 WORD нет места.
- Смысл маркера определяет спецификация Codec, который его принимает.

### Необязательное поле (цель `0000`)

- Если в списке CODEC поля-записи есть цель `0000`, это поле **необязательное**. При пропуске на его месте пишут 1 WORD со значением `0x0000`. Эта запись длиной 1 WORD -- маркер слота ABSENT (не записано).
- `0x0000` -- это Codec Reference `0000` (резерв), номер маркера `000`, `LLLL = 0000` (всего 1 WORD). Он не пересекается с другими записями, и декодер, не знающий спецификации, тоже пропускает его как запись в 1 WORD.
- Необязательное поле тоже всегда занимает место. При пропуске обязательно пишут `0x0000`, место не освобождают (даже для замыкающего поля). Поэтому у записи ровно одно представление, а разбор определяется только позицией. На положение и число необязательных полей, а также на пересечение списков с другими полями ограничений нет.
- ABSENT допустим только на месте необязательного поля. `0x0000` на месте записи HEAD или BODY, обязательного поля или Edge Id invalid.
- Пропуск -- это не «значения нет», а «не записано». О мире ничего не утверждается. «Значения нет» записывают как NO-VALUE (`0002`). Что означает пропуск (например, отсутствие цели у TAG означает эту версию), определяет спецификация каждого формата.

## Интерпретация и допустимость

- Поле -- Edge FIELD того же документа. Одну и ту же цель в одно поле дважды не ставят.
- **Поле-запись (ширина 0):** без CODEC принимает любую запись, кроме маркеров слота. Если CODEC есть хотя бы один, список закрытый. Kind и Codec записи этого поля (для Reference вместе с Quantifier) должны входить в список, иначе запись не соответствует спецификации. Это отличается от ENUM, который является открытым списком.
- **Поле с сырым значением (ширина n ≥ 1 или остаток `0xFFFF`):** CODEC ставят ровно одну точную цель (wildcard нельзя). Это сырое значение -- Payload этого Value без TAG. Kind и Codec даёт CODEC, Length -- ширина FIELD. У кодов чётный-нечётный заданный код определяет чётность числа байтов. Если сырое значение не следует правилам этого Value (включая длину), запись не соответствует спецификации.
- Маркеры слота сверяют только с точными целями списка. Если на месте необязательного поля (цель `0000`) стоит `0x0000`, это пропуск. Остальные записи сверяют со списком без целей-маркеров.
- Для поля с сырым значением можно задать CODEC и ENUM вместе. CODEC -- формат, ENUM -- имена кодовых значений (например, rank как UNSIGNED-INTEGER, а 0, 1, 2 как ENUM).
- К Edge Id CODEC можно привязать имя через BIND, но это не обязательно.
- Поле «Reference или Value» записывают двумя CODEC (`0780`, `0F80`).

## Длина

```
всего = 1 + N_len + N_id + N_field + 1 WORD   (6 WORD, если Edge Id и поле -- LOCAL ID в 1 WORD)
```

## Пример

В документе спецификации LABEL `geul.org/label` поле Object (FIELD #3) принимает UTF8-LANGUAGE-TEXT (чётный и нечётный) и LOCAL. Edge Id 7~9.

```
129E 0088 0007 0088 0003 084A
129E 0088 0008 0088 0003 084B
129E 0088 0009 0088 0003 0008
```

- TAG `129E` (Edge, Codec `0x1E`, `LLLL = 0101`, 6 WORD), Edge Id `0088 0007`, поле `0088 0003`, цель `084A`.
