DECLARE -- описательный Edge, который объявляет состав Payload одного Codec. Codec `0x1B`.

Вместе с [FIELD](/ru/grammar/edge/field/) (`0x1C`), [ENUM](/ru/grammar/edge/enum/) (`0x1D`) и [CODEC](/ru/grammar/edge/codec/) (`0x1E`) это словарь для записи спецификации Codec ([документ спецификации Codec](/ru/grammar/codec-spec/)). Раскладка этих четырёх Edge встроена в декодер. Каждый документ спецификации Codec, написанный этим словарём, -- обычный документ. Одна спецификация даёт проверку, разбор и отображение (в просмотрщике). Просмотрщик не держит код для каждого Codec, а рисует по спецификации.

## Раскладка

```
TAG WORD          0001 0LLL L001 1011
[TAG расширения Length]
Edge Id           запись LOCAL Reference
Цель              1 WORD. Из TAG WORD объявляемого Codec берутся только места Kind и Codec (LLLL = 0)
[Issuer и номер формата]  если цель -- формат Issuer. Раскладка та же, что у TAG расширения Codec
```

- Список полей в DECLARE не хранится. Каждый [FIELD](/ru/grammar/edge/field/) указывает на свой DECLARE, а порядок этих FIELD в документе -- порядок полей Payload.

## Правила интерпретации

Это правила чтения и записи записей по спецификации Codec.

- Поле с сырым значением читается на столько WORD, сколько фиксированно объявил FIELD. Одно из полей может быть остатком сырого значения (ширина `0xFFFF`); оно читает оставшиеся WORD за вычетом ширины последующих фиксированных полей. После поля-остатка идут только сырые значения фиксированной ширины.
- Поле-запись начинается с TAG WORD и читается на столько, сколько указывает Length этого TAG.
- Поле с сырым значением -- беззнаковое целое big-endian из n WORD. Записывается как `0x` + hex из ширина×4 цифр, а если для того же значения есть ENUM, рядом указывается имя его BIND.
- Смысл поля-записи определяет спецификация Codec этой записи. Значения, требующие интерпретации (знак, дробь, дата), хранятся не сырым значением, а записью Value.

Других правил границ нет. Codec, где переменных сырых значений два и более, где после переменного сырого значения идут запись или переменное поле, или где ширина сырого значения зависит от значения другого поля или состояния документа, этим словарём объявить нельзя. Такую раскладку приводят к одной переменной части, обернув её в запись (например, подписант в SIGNATURE -- запись Reference).

## Допустимость

- Kind цели -- один из Reference, Value, Edge, Meta. Codec у Reference -- место `CCCC`, а Quantifier равен 0.
- [Маркер слота](/ru/grammar/reference/slot-marker/) (Codec Reference `0000`) целью DECLARE быть не может. Он встроен в декодер (слой 0).
- Edge Id у Edge FIELD-ом не объявляется. Он первый элемент любого Edge и потому неявный ([Edge](/ru/grammar/edge/)).
- Поля DECLARE -- это указывающие на него FIELD, их может быть 0. Один FIELD принадлежит только одному DECLARE. Даже поля одинаковой формы заводят отдельным FIELD для каждого DECLARE.
- В DECLARE нет ничего, кроме цели (и для цели формата Issuer -- Issuer и номера формата).
- Позиция после последовательного чтения полей должна точно совпасть с концом записи. Если остаётся лишнее или не хватает, запись нарушает спецификацию.
- В одном документе одну и ту же цель дважды не объявляют.
- Варианты с разными замыкающими полями ветвлением не записывают. Для каждого Codec заводят отдельный DECLARE.

## Документ спецификации

- Документ спецификации прямого кода -- обычный документ GEUL Issuer `0x0000`. ID документа -- это целевой TAG WORD, расширенный до 4 WORD (`0x1018` → `0x0000000000001018`), и публикуется он так же, как документы других Issuer (ID версии, `versions.geul`) ([документ спецификации Codec](/ru/grammar/codec-spec/)).
- В документе спецификации один DECLARE, и его цель должна совпадать с TAG WORD из ID документа. `DOC-ID` -- это DOC-POINTER (`0x0000`, ID этого документа, `0`).

## Имена

- Имя Codec привязывают к Edge Id DECLARE через [BIND](/ru/grammar/edge/bind/) (например, `PUBLICATION`). Любой UTF8-TEXT к DECLARE, FIELD, ENUM и CODEC прикрепляют через BIND, а не через LABEL или другие Edge.
- Имена полей и имена enum привязывают к FIELD и ENUM так же.

## Пример

В документе спецификации `geul.org/publication` для PUBLICATION (Edge `0x18`): после Edge Id запись DOC-POINTER, хеш содержимого 16 WORD.

```
119B 0088 0001 1018                 DECLARE #1  Edge 0x18                 (BIND "PUBLICATION")
129C 0088 0002 0088 0001 0000       FIELD #2    DECLARE #1, запись        (BIND "doc")
129E 0088 0009 0088 0002 0038       CODEC #9    FIELD #2, DOC-POINTER
129C 0088 0004 0088 0001 0010       FIELD #4    DECLARE #1, сырое значение 16 WORD   (BIND "hash")
```

- DECLARE: TAG 1 + Edge Id 2 + цель 1 = 4 WORD, `LLLL = 0011`.
- FIELD: TAG 1 + Edge Id 2 + DECLARE 2 + ширина 1 = 6 WORD (`LLLL = 0101`). Принимаемые Kind и Codec задаются отдельно через [CODEC](/ru/grammar/edge/codec/) (`0038` = DOC-POINTER).
- Необязательное поле объявляется целью CODEC `0000`. На месте пропущенного пишут ABSENT (`0x0000`) ([CODEC](/ru/grammar/edge/codec/), необязательное поле).
- Порядок полей -- порядок, в котором FIELD #2 и #4 расположены в документе. Edge Id не обязаны идти подряд (LOCAL AUTO INCREMENT -- рекомендация).

## Открытые вопросы

- Повторение. Структура, где предшествующее сырое значение задаёт число, как «аргументы × число аргументов» в `CALL`. Сейчас объявить нельзя.
- Как объявлять Codec с подформатами (TAG своего вида у каждого Codec), например WORLD.
- Как находить документ спецификации формата Issuer (Issuer и номер формата → адрес документа спецификации).
- Какому набору версий документов спецификации прямых кодов соответствует `SPEC-VERSION`.
