## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)). Edge Id у Edge не объявляется через FIELD.

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `field` | #2 | запись | `0050` LOCAL |  |
| 2 | `target` | #4 | простое значение 1 WORD |  |  |

CODEC — Edge-высказывание, указывающий один Kind·Codec, который принимает одно [FIELD](0x0BCL-field.md). Codec `0x0BEL`.

Как [ENUM](0x0BDL-enum.md) придаёт смысл одному кодовому значению поля простого значения, так CODEC придаёт полю один формат. Поскольку на один Edge приходится один формат, их можно указать несколько. Раскладка встроена в декодер ([документ спецификации Codec](../codec-spec.md)).

## Раскладка {#레이아웃}

```
TAG WORD          0000 1011 1110 LLLL
[Length, расширяющий TAG]
Edge Id           запись LOCAL Reference
поле              запись LOCAL Reference, указывающая на Edge FIELD
цель              1 WORD. 000K KKKC CCCC LLLL (LLLL = 0000 точная, 1111 шаблон)
```

## WORD цели {#대상-word}

- Позиция Codec в TAG WORD (раздел `KKKK` и `CCCCC`) сохраняется как есть. Старшие 3 бита равны 0. `LLLL` — `0000` (точная) или `1111` (шаблон), другие значения invalid.
- Значение точной цели (`LLLL = 0000`), записанное в 32 битах, — это Codec ID этого Codec (например, LOCAL `0x0050` → `0x00000050`, COORDINATE-EARTH `0x0640`, UTF8-LANGUAGE-TEXT `0x0780`). Поэтому цель прямо указывает на документ спецификации этого Codec ([документ спецификации Codec](../codec-spec.md)).
- Пары чётных·нечётных кодов (текст, последовательность байтов) тоже указываются точными кодами. Чтобы принимать и чётный, и нечётный, ставят оба. Правила совместного толкования пары нет (есть соседние коды, не образующие пару, как NUMERIC `0x064L`/`0x065L`).

### Шаблон (`LLLL = 1111`) {#와일드카드-llll--1111}

- При `LLLL = 1111` принимается весь раздел `KKKK` (32 позиции) WORD цели независимо от значения `C`. Внутри одного раздела смысл тот же при любом `C`. Сравнивается только совпадение раздела цели и раздела записи. Через границу раздела не принимается.
- При `LLLL = 1111` рекомендуется первая позиция раздела (`C = 0`). Это рекомендация, а не принуждение. Другое `C` в том же разделе тоже допустимо.
- Если Kind охватывает несколько разделов, CODEC перечисляются для каждого раздела.

| Цель | Смысл |
|---|---|
| `000F`·`020F`·`040F` | любая Reference (разделы 0~2, включая REFERENCE-ISSUER) |
| `060F`·`080F` | любое Value (разделы 3·4, включая VALUE-ISSUER) |
| `0A0F`·`0C0F`·`0E0F`·`100F`·`120F`·`140F`·`160F`·`180F`·`1A0F` | любой Edge (разделы 5~13, включая EDGE-ISSUER) |
| `1C0F`·`1E0F` | любой Meta (разделы 14·15) |

- Маркеры места Reference (`0x000L~0x002L`) с `LLLL = 1111` не сочетаются (`000F` не принимает ABSENT·UNKNOWN-VALUE·NO-VALUE). При этом в разделах, где назначена первая позиция, как у Value `0x060L` (BOOL) и Edge `0x0A0L` (REFERENCE-NODE), `LLLL = 1111` её включает (чтобы принимался только BOOL, используется `0600` с `LLLL = 0000`).
- Цель с `LLLL = 1111` на документ спецификации не указывает.
- Безразличие к квантификации или группа записываются только перечислением CODEC (`LLLL = 0000`). Например, WIKIDATA-QID при безразличии к квантификации — это пять: `0140`, `0150`, `0160`, `0170`, `0180`.
- В коды 5Q-системы Reference квантификация входит. Цель указывается точно, вплоть до квантификации. Чтобы принимать несколько Quantifier, ставят несколько CODEC. Квантификацию REFERENCE-ISSUER определяет документ Issuer.

### Маркер места (цель `0000`, `0010`, `0020`) {#자리-표지-대상-0000-0010-0020}

[Маркер места](../slot-marker.md) — группа записей по 1 WORD, назначенная первым трём позициям `0x000L~0x002L` раздела 0 Reference. Квантификации нет.

| Цель | Маркер | Смысл |
|---|---|---|
| `0000` | ABSENT | Не записано. Это поле необязательное |
| `0010` | UNKNOWN-VALUE | Неизвестно. Принимает утверждение о том, что значение есть |
| `0020` | NO-VALUE | Отсутствует. Принимает утверждение о том, что значения нет |

- **Правило приёма:** маркер действителен только тогда, когда в списке CODEC поля есть тот же WORD как точная цель. Шаблон и поле-запись без CODEC («любая запись») маркеры не принимают. Маркер на месте записи HEAD·BODY или на месте Edge Id invalid.
- Список, состоящий только из целей-маркеров (всегда маркер), invalid (обобщение правила для списка только из `0000`). Они используются вместе с целью `LLLL = 1111` или точной целью (`000F`·`020F`·`040F` + `0000` = любая Reference либо пропуск).
- В поле простого значения цель-маркер ставить нельзя. У простого значения нет TAG, ширина задана, и места для маркера в 1 WORD нет.
- Смысл маркера определяет спецификация принимающего его Codec.

### Необязательное поле (цель `0000`) {#선택-필드-대상-0000}

- Если в списке CODEC поля-записи есть цель `0000`, это поле **необязательное**. При пропуске на его месте пишется 1 WORD со значением WORD `0x0000`. Эта запись в 1 WORD — маркер места ABSENT (не записано).
- `0x0000` — это Reference, Codec `0x000L` (Reserved), `LLLL = 0000` (всего 1 WORD). Она не пересекается с другими записями, и декодер, не знающий спецификации, пропустит её как запись из 1 WORD.
- Необязательное поле тоже всегда занимает своё место. При пропуске обязательно пишется `0x0000`, место не оставляют пустым (даже если поле стоит в конце). Поэтому у записи единственное представление, а разбор определяется только позицией. Ограничений на позицию и число необязательных полей и на пересечение списков с другими полями нет.
- ABSENT действителен только на месте необязательного поля. `0x0000` на месте записи HEAD·BODY, на месте обязательного поля и на месте Edge Id invalid.
- Пропуск — это не «значения нет», а «не записано». О мире ничего не утверждается. «Значения нет» записывается через NO-VALUE (`0020`). Что значит пропуск (например, при отсутствии цели у TAG — эта версия), определяет спецификация каждого формата.

## Интерпретация и действительность {#해석과-유효성}

- Поле — FIELD Edge того же документа. Одну и ту же цель в одно поле дважды не ставят.
- **Поле-запись (ширина 0)**: если CODEC нет, принимается любая запись, кроме маркера места. Если есть хотя бы один, это закрытый список. Kind·Codec записи этого поля (для Reference — с Quantifier) должны быть одним из списка, иначе запись не соответствует спецификации. Это отличается от ENUM, который является открытым списком.
- **Поле простого значения (ширина n ≥ 1 или остаток `0xFFFF`)**: CODEC ставится только одна точная цель (шаблон не допускается). Это простое значение — Payload этого Value без TAG. Kind·Codec даёт CODEC, Length — ширина FIELD. Для чётных·нечётных кодов чётность числа байтов определяет указанный код. Если простое значение не следует правилам этого Value (включая длину), запись не соответствует спецификации.
- Маркер места сверяется только как точная цель списка. Если на месте необязательного поля (цель `0000`) стоит `0x0000`, это пропуск. Остальные записи сверяются со списком без целей-маркеров.
- У поля простого значения можно поставить вместе CODEC и ENUM. CODEC — это формат, ENUM — имя кодового значения (например, rank как UNSIGNED-INTEGER с ENUM для 0·1·2).
- Имя можно привязать к Edge Id CODEC через BIND, но это необязательно.
- Поле «Reference или Value» записывается пятью CODEC (`000F`, `020F`, `040F`, `060F`, `080F`).

## Длина {#길이}

```
всего = 1 + N_len + N_id + N_field + 1 WORD   (если Edge Id и поле — LOCAL с ID в 1 WORD, то 6 WORD)
```

## Пример {#예시}

В документе спецификации LABEL `0x00000000/codecs/0x00000A40/` поле Object (FIELD #3) принимает UTF8-LANGUAGE-TEXT (чётный·нечётный) и LOCAL. Edge Id 7~9.

```
0BE5 0051 0007 0051 0003 0780
0BE5 0051 0008 0051 0003 0790
0BE5 0051 0009 0051 0003 0050
```

- TAG `0BE5` (Edge, Codec `0x0BEL`, `LLLL = 0101`, 6 WORD), Edge Id `0051 0007`, поле `0051 0003`, цель `0780`.
