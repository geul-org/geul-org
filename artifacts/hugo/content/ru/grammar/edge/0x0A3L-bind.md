## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)). Edge Id у Edge не объявляется через FIELD.

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `subject` | #2 | запись | любая запись (кроме маркера места) |  |
| 2 | `name` | #3 | запись | `0720` UTF8-TEXT-EVEN, `0730` UTF8-TEXT-ODD |  |

BIND — Edge-высказывание, привязывающий к Subject имя, с которым сверяется машина. Codec `0x0A3L`.

Это именование. Имя, читаемое человеком (название на конкретном языке), ведёт [LABEL](0x0A4L-label.md). Имя символа программы и доменное имя в списке Issuer записываются одной и той же записью.

## Раскладка {#레이아웃}

```
TAG WORD          0000 1010 0011 LLLL
[Length, расширяющий TAG]
Edge Id           запись LOCAL Reference
Subject           1 запись Reference или 1 WORD TAG WORD Codec
имя               1 Value UTF8-TEXT-*
```

## Интерпретация и действительность {#해석과-유효성}

- Subject — ровно одна полная запись [Reference](../reference/_index.md). Если это LOCAL, то это объект этого документа (символ и т. п.), если указывающая Reference — объект другого документа. Сам документ — [DOC-POINTER](../reference/0x041L-doc-pointer.md), сам Issuer — [ISSUER-POINTER](../reference/0x040L-issuer-pointer.md).
- Либо Subject — один TAG WORD Codec (только Kind·Codec, `LLLL = 0`, без Payload). Это не запись с пустым Payload, а указание на сам этот прямой код, то есть на его документ спецификации (Codec Issuer GEUL `0x0000<TAG>`) ([документ спецификации Codec](../codec-spec.md), [DECLARE](0x0BBL-declare.md)). Пример: `0B80` — PUBLICATION. Codec формата Issuer таким образом не указывается.
- Другие записи (Value и т. п.) Subject быть не могут. FIELD документа спецификации BIND объявляет Subject только с шириной `0` (запись), поэтому это ограничение — правило тела BIND.
- Имя — ровно одно Value [UTF8-TEXT](../value/0x072L-utf8-text.md). Языка нет, нормализации нет. Имена одинаковы, только если совпадают байты.
- Область имени — документ, содержащий BIND. В одном документе одно имя не привязывают к разным Subject.
- К одному Subject можно привязать несколько имён (псевдоним, прежнее имя). Если документ не определяет иначе, основное имя — последний BIND.
- Другие записи указывают на объект не по имени, а по LOCAL ID. Имя служит для сопоставления с внешним миром (функции хоста, ввод адреса, человек).
- Какие символы допустимы в имени, определяет назначение. Доменное имя в списке Issuer подчиняется правилам домена (нижний регистр, IDNA) ([адрес публикации и список версий](../publishing.md#issuer-목록)).
- В списке версий BIND не размещается. Адреса по имени документа нет ([адрес публикации и список версий](../publishing.md#문서-이름)).

## Длина {#길이}

```
всего = 1 + N_len + N_id + N_subject + N_name WORD
```

## Пример (не нормативно) {#예시-비규범}

Символ программы: Edge Id `0003`, Subject LOCAL 7, имя `main`.

- Имя `main` — 4 байта (чётное число), поэтому `0722 6D61 696E`, 3 WORD.
- Edge — TAG 1 + Edge Id 2 + Subject 2 + имя 3 = 8 WORD, TAG `0A37`.

```
0A37 0051 0003 0051 0007 0722 6D61 696E
```

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x00000A30/latest.geul`, прочитанный через `geul show` (16-ричные цифры в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x04260000000000000A3000000000
BODY
#1 DECLARE 0x0A30
#2 FIELD #1 record
#3 FIELD #1 record
#4 BIND #1 "BIND"
#5 BIND #2 "subject"
#6 BIND #3 "name"
#7 CODEC #3 0x0720
#8 CODEC #3 0x0730
```
