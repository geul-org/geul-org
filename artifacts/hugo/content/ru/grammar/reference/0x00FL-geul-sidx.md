## Члены {#구성원}

Эта страница охватывает один комплект системы 5Q — пять кодов. Квантификация определяется смещением внутри раздела `C % 5` ([Reference](_index.md#quantifier)). Документ кодека — по одному на код. Поля у пяти документов кодека одинаковы, различаются только цель DECLARE и имя (BIND).

| TAG ID | Имя | Квантификация | Codec ID | Документ спецификации | TAG WORD |
|---|---|---|---|---|---|
| `0x00FL` | `GEUL-SIDX-IDENTIFIED` | Identified | `0x000000F0` | `0x00000000/codecs/0x000000F0/` | `0000 0000 1111 LLLL` |
| `0x010L` | `GEUL-SIDX-GENERIC` | Generic | `0x00000100` | `0x00000000/codecs/0x00000100/` | `0000 0001 0000 LLLL` |
| `0x011L` | `GEUL-SIDX-FREE-CHOICE` | Free-choice | `0x00000110` | `0x00000000/codecs/0x00000110/` | `0000 0001 0001 LLLL` |
| `0x012L` | `GEUL-SIDX-UNIVERSAL` | Universal | `0x00000120` | `0x00000000/codecs/0x00000120/` | `0000 0001 0010 LLLL` |
| `0x013L` | `GEUL-SIDX-VARIABLE` | Variable | `0x00000130` | `0x00000000/codecs/0x00000130/` | `0000 0001 0011 LLLL` |

## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемая форма (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `sidx` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

GEUL-SIDX — объявляющий Reference, указывающий на цель через GEUL SIDX (Semantic-aligned Index). SIDX — идентификатор, сами биты которого несут смысл (вид, свойства).

## Раскладка {#레이아웃}

```
TAG WORD          0000 0000 1111 LLLL      Codec 0x00FL~0x013L (Identified 0x00FL)
[расширяющий TAG Length]
SIDX              всё остальное
```

- Quantifier такой же, как у других объявляющих Codec. Для Variable это анонимная переменная данного вида ([Reference](_index.md) Variable). Квантификацию задают только кодом 5Q (`0x00FL~0x013L`, `C % 5`). В значение SIDX квантификацию не вкладывают.
- Документ спецификации объявляет SIDX как одно поле простого значения остаточной ширины. Когда правило ширины будет определено, это изменится.

## Пример {#예시}

| SIDX | WORD sequence |
|---|---|
| (не нормативно) 64 бита `0x1234 5678 9ABC DEF0`, Identified | `00F4 1234 5678 9ABC DEF0` |

## Принцип назначения {#배정-방침}

- Роль отличается от [GEUL](0x00AL-geul.md). GEUL — идентификационный ID, назначаемый в основном по порядку (auto increment), а GEUL-SIDX — смысловой адрес, придающий близким по смыслу целям близкие значения.
- Степень близости определяют статистикой, накопленной по данным использования. Пока статистики нет, используют GEUL ID, а после назначения SIDX связывают GEUL и GEUL-SIDX одной и той же цели через [SAME-NODE](../edge/0x0A1L-same-node.md).

## Открытые проблемы {#열린-문제}

- **Ширина.** Определяется по статистике. Рассматриваются 4 WORD (64 бита), 16 WORD и другие. В SIDX смысл несут старшие биты, поэтому правило «наименьшей ширины» других объявляющих Codec (запрет ведущего `0x0000`) применить как есть нельзя. Значит, будет фиксированная ширина (или фиксированная ширина по подформатам). Пока она не определена, документ спецификации объявляет SIDX простым значением остаточной ширины.
- **Устойчивость назначения.** У Reference равные целые значения означают одну цель, а выданные ID не используются повторно. Чтобы не переносить уже назначенные SIDX при изменении статистики, нужно назначение только с добавлением (append-only; разреженное назначение с резервированием мест рядом по смыслу). Если переносить придётся часто, нужно решить, определять ли SIDX не как постоянный идентификатор, а как индекс, привязанный к редакции реестра.
- **Уникальность.** Если SIDX порождается по смыслу битов и может сталкиваться, это не согласуется с предпосылкой «равные целые значения — одна цель». При назначении устраняют коллизии и гарантируют уникальность.

## Исходный текст документа спецификации {#규격-문서-원문}

Документ спецификации `0x00000000/codecs/0x000000F0/latest.geul`, прочитанный командой `geul show` (шестнадцатеричные значения в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x042600000000000000F000000000
BODY
#1 DECLARE 0x00F0
#2 FIELD #1 rest
#3 BIND #1 "GEUL-SIDX-IDENTIFIED"
#4 BIND #2 "sidx"
```

Выше — документ кодека `GEUL-SIDX-IDENTIFIED` (`0x00FL`). У остальных членов (`GEUL-SIDX-GENERIC`, `GEUL-SIDX-FREE-CHOICE`, `GEUL-SIDX-UNIVERSAL`, `GEUL-SIDX-VARIABLE`) в документе кодека различаются только Codec ID в DOC-ID, цель DECLARE и имя, привязанное в `#1` (BIND).
