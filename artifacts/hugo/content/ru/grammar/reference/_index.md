Reference — запись, указывающая на цель. Целью может быть сущность, понятие, документ или другой Edge. Указывают не по имени, а по ID.

## Раскладка {#레이아웃}

```
TAG WORD          000K KKKC CCCC LLLL      разделы 0~2 (0x000L~0x05FL)
[расширяющий TAG Length]
[IMPORT ID]       для EXTERNAL-POINTER (1/2/4 WORD)
[Issuer]          для EXTERNAL-ISSUER (2/4/16 WORD)
[ID документа]    для EXTERNAL-ISSUER (4 WORD)
ID цели           всё остальное
```

- `LLLL` — общее число WORD с учётом TAG WORD минус 1 ([запись и TAG WORD](../record.md)).
- Reference — 96 ячеек разделов 0~2 (`w < 0x0600`). Раздел 0, сущности: `0x000L~0x01FL`; раздел 1, EXTERNAL: `0x020L~0x03FL`; раздел 2, прочее: `0x040L~0x05FL`.
- Codec приведены в таблице кодов (ниже). В системе 5Q один код несёт и систему идентификации, и квантификацию. Квантификацию REFERENCE-ISSUER определяет документ Issuer.
- ID цели — целое число без знака в порядке big-endian, записываемое **наименьшей шириной**. Ширина — остаток Length после вычитания предшествующих полей.
- ID цели `0` записывают как `0x0000`, 1 WORD. В остальных случаях WORD `0x0000` спереди не добавляют.
- Равные целые значения — один и тот же ID. Ширина не входит в ID.
- Все Codec используют наименьшую ширину. Codec не фиксирует ширину ID цели.
- [ISSUER-POINTER](0x040L-issuer-pointer.md), [DOC-POINTER](0x041L-doc-pointer.md) и [CODEC-POINTER](0x042L-codec-pointer.md) этой раскладке не следуют. У них нет ID цели, есть только Issuer (и ID документа, Codec ID, ID версии).
- [REFERENCE-ISSUER](#reference-issuer) тоже этой раскладке не следует. Это TAG, Issuer, номер Codec 2 WORD и Payload. Payload определяет документ Codec, выпущенный Issuer.

## Codec {#codec}

| TAG ID | Имя | Классификация | Цель |
|---|---|---|---|
| `0x000L~0x002L` | [маркер места](../slot-marker.md) | маркер места | Не указывает на цель. Используется только маркер в 1 WORD: `0x0000` ABSENT (не указано), `0x0010` UNKNOWN-VALUE (неизвестно), `0x0020` NO-VALUE (нет) |
| `0x005L~0x009L` | [LOCAL](0x005L-local.md) | объявление | ID, выданный этим документом |
| `0x00AL~0x00EL` | [GEUL](0x00AL-geul.md) | объявление | Сущность, выдаваемая geul.org |
| `0x00FL~0x013L` | [GEUL-SIDX](0x00FL-geul-sidx.md) | объявление | Семантически выровненный идентификатор, биты которого несут смысл |
| `0x014L~0x018L` | [WIKIDATA-QID](0x014L-wikidata-qid.md) | объявление | Элемент Викиданных. Целое число после `Q` |
| `0x019L~0x01DL` | [WIKIDATA-PID](0x019L-wikidata-pid.md) | объявление | Свойство Викиданных. Целое число после `P` |
| `0x020L~0x02EL` | [EXTERNAL-POINTER-1/2/4WORD](0x020L-external-pointer-1word.md) | указание | LOCAL ID документа, подключённого через IMPORT |
| `0x02FL~0x03DL` | [EXTERNAL-ISSUER-2/4/16WORD](0x02FL-external-issuer-2word.md) | указание-объявление | LOCAL ID документа, опубликованного Issuer |
| `0x040L` | [ISSUER-POINTER](0x040L-issuer-pointer.md) | указание-объявление | Сам Issuer |
| `0x041L` | [DOC-POINTER](0x041L-doc-pointer.md) | указание-объявление | Одна версия документа, опубликованного Issuer |
| `0x042L` | [CODEC-POINTER](0x042L-codec-pointer.md) | указание-объявление | Одна версия кодека, опубликованного Issuer |
| `0x05DL~0x05FL` | [REFERENCE-ISSUER-2/4/16WORD](#reference-issuer) | форма Issuer | Определяется Issuer. Классификацию и ячейки ID цели определяет документ Issuer |

- Reserved: `0x003L~0x004L`, `0x01EL~0x01FL` (раздел 0), `0x03EL~0x03FL` (раздел 1), `0x043L~0x05CL` (раздел 2, место для новых систем идентификации).
- Номер системы читают по смещению внутри раздела `C`. В разделе 0 при `5 <= C < 30` это система `C / 5` (1~5), в разделе 1 при `C < 30` — система `6 + C / 5` (6~11).

| Система | Имя | Identified | Generic | Free-choice | Universal | Variable |
|---:|---|---|---|---|---|---|
| 1 | LOCAL | `0x005L` | `0x006L` | `0x007L` | `0x008L` | `0x009L` |
| 2 | GEUL | `0x00AL` | `0x00BL` | `0x00CL` | `0x00DL` | `0x00EL` |
| 3 | GEUL-SIDX | `0x00FL` | `0x010L` | `0x011L` | `0x012L` | `0x013L` |
| 4 | WIKIDATA-QID | `0x014L` | `0x015L` | `0x016L` | `0x017L` | `0x018L` |
| 5 | WIKIDATA-PID | `0x019L` | `0x01AL` | `0x01BL` | `0x01CL` | `0x01DL` |
| 6 | EXTERNAL-POINTER-1WORD | `0x020L` | `0x021L` | `0x022L` | `0x023L` | `0x024L` |
| 7 | EXTERNAL-POINTER-2WORD | `0x025L` | `0x026L` | `0x027L` | `0x028L` | `0x029L` |
| 8 | EXTERNAL-POINTER-4WORD | `0x02AL` | `0x02BL` | `0x02CL` | `0x02DL` | `0x02EL` |
| 9 | EXTERNAL-ISSUER-2WORD | `0x02FL` | `0x030L` | `0x031L` | `0x032L` | `0x033L` |
| 10 | EXTERNAL-ISSUER-4WORD | `0x034L` | `0x035L` | `0x036L` | `0x037L` | `0x038L` |
| 11 | EXTERNAL-ISSUER-16WORD | `0x039L` | `0x03AL` | `0x03BL` | `0x03CL` | `0x03DL` |

- **Объявление** напрямую идентифицирует цель по ID, заданному выдающей стороной.
- **Указание** указывает на LOCAL в документе, подключённом через IMPORT ID. Ширина IMPORT ID определяется системой: если система − 6 равна 0, 1, 2, то ширина 1, 2, 4 WORD.
- **Указание-объявление** одной записью без IMPORT указывает на другой документ и цель в нём. Ширина Issuer у EXTERNAL-ISSUER: если система − 9 равна 0, 1, 2, то 2, 4, 16 WORD.
- `0x020L~0x03DL` (раздел 1, системы 6~11) указывают на LOCAL другого документа. Остальные системы объявления идентифицируют цель напрямую (LOCAL этого документа, выданный ID). Указатели (раздел 2, `0x040L~0x042L`) указывают на сам Issuer, документ и кодек. REFERENCE-ISSUER лежит вне этого деления.
- `0x000L~0x002L` — коды, отведённые под маркеры места; как Reference, указывающий на цель, они не используются. WORD `0x0000`, `0x0010`, `0x0020` (L 0, 1 WORD) — это [маркеры места](../slot-marker.md) (`0x0000` ABSENT, `0x0010` UNKNOWN-VALUE, `0x0020` NO-VALUE). Маркер действителен только на месте поля записи, где этот WORD точно задан целью CODEC. Шаблоны-подстановки (wildcard) и поля без CODEC его не принимают, а на местах записей HEAD и BODY и на месте Edge Id он invalid. Форма TAG с Payload (L ≥ 1) при C 0~2 — Reserved.
- CC0 — только прямые коды и публикации, предоставляемые geul.org. Системы идентификации не под CC0 (WordNet и др.) прямыми кодами не делают. Лицензию форм Issuer определяет сам Issuer.

## LOCAL {#local}

LOCAL — ID, выданный этим документом.

- **Уникален.** В одном документе один LOCAL ID указывает только на одну цель.
- **0 не назначают.** ID цели назначают начиная с 1.
- **Рекомендуется назначать по возрастанию** (auto increment). Величина ID смысла не имеет.
- Между версиями он указывает на ту же цель. Удалённый ID повторно не используют (редакции [документа](../document.md)).
- Чтобы на цель можно было указывать из-за пределов документа, в документе должен быть `DOC-ID`.
- Разные LOCAL ID не означают, что в реальности это разные цели. Если они одно и то же, их соединяют Edge `SAME-NODE`, если разные — `DIFFERENT-NODE`.

### Edge Id {#edge-id}

Каждый Edge ставит первым элементом Payload LOCAL Reference. Этот LOCAL ID и есть **Edge Id**.

- Edge Id можно прочитать, не зная кодовой книги.
- LOCAL на месте Edge Id — объявление, а LOCAL на других местах Edge — упоминание.
- Для объявления Edge Id используют только Identified (`0x005L`).
- На другой Edge указывают по Edge Id. Edge этого документа — через LOCAL, Edge другого документа — через указывающий Reference.

## Указание на другой документ {#다른-문서-가리키기}

| На что | Как |
|---|---|
| Сам Issuer | `ISSUER-POINTER` (Issuer) |
| Одна версия документа | `DOC-POINTER` (Issuer, ID документа 4 WORD, ID версии 2 WORD). Версия `0` — последняя |
| Одна версия кодека | `CODEC-POINTER` (Issuer, Codec ID 2 WORD, ID версии 2 WORD). Версия `0` — последняя |
| Цель в опубликованном документе (последняя версия) | `EXTERNAL-ISSUER-*` (Issuer, ID документа, LOCAL ID) |
| Цель в подключённом документе (фиксированная редакция) | Meta `IMPORT-DOC` назначает IMPORT ID, затем `EXTERNAL-POINTER-*` (IMPORT ID, LOCAL ID) |

- На сам документ — и внутри этого документа, и снаружи — указывают только одним DOC-POINTER. На себя — DOC-POINTER на собственный `DOC-ID`. Документ кодека — исключение: на него указывают через CODEC-POINTER (`DOC-ID` тоже CODEC-POINTER).
- EXTERNAL-ISSUER следует последней версии. Чтобы зафиксировать редакцию, используют IMPORT.
- Issuer записывают наименьшей шириной (2/4/16 WORD), в которую помещается значение, и выбирают Codec, подходящий этой ширине. Для EXTERNAL-ISSUER и REFERENCE-ISSUER то же самое.
- ID документа `0` у каждого Issuer зарезервирован под индексный документ терминов (инструментов, ролей и т. д.), определённых этим Issuer. Индексный документ рекомендуется всем Issuer, но не обязателен ([Issuer и публикация](../issuer.md#용어-정의-문서)).

Пример: LOCAL 7 в документе `0x0000000000000002` Issuer `0x00000002`

```
02F7 0000 0002 0000 0000 0000 0002 0007
```

## Quantifier {#quantifier}

| `C % 5` | Имя | Смысл | Пример |
|---|---|---|---|
| `0` | Identified | Идентифицированный объект | Илон Маск, Республика Корея |
| `1` | Generic | Общее высказывание о виде в целом. Допускает исключения | Солдат подчиняется приказам |
| `2` | Free-choice | Любая цель, удовлетворяющая условию | Любой солдат |
| `3` | Universal | Все цели в пределах области | Все солдаты |
| `4` | Variable | Переменная дискурса | тот человек, эта женщина |

- **Квантификацию читают только в системе 5Q (системы 1~11).** По смещению внутри раздела `C`: в разделе 0 при `5 <= C < 30`, в разделе 1 при `C < 30` квантификация равна `C % 5`. В разделе 32 ячейки, поэтому деление 9-битного места Codec (`w >> 4`) на 5 сбивает раздел 1. У маркеров (раздел 0, `C < 3`) и раздела 2 (указатели, REFERENCE-ISSUER) квантификации нет. Маркер `0x0010` UNKNOWN-VALUE — не Generic. Квантификацию REFERENCE-ISSUER определяет документ Codec, выпущенный Issuer.
- Generic, в отличие от Universal, не означает, что высказывание без исключений применимо к каждой отдельной цели. Определяющие выражения вроде `что такое солдат` можно записывать как Generic. Если нужно строгое определение понятия или классификации, его уточняют отдельным отношением.
- Область действия квантификации и отрицание определяет не Reference, а использующий его Edge.
- **Variable** — цель в дискурсе, вид которой известен, но которая ещё не идентифицирована.
  - Именованную переменную получают добавлением Variable к LOCAL. Один и тот же LOCAL ID — одна и та же переменная. Вид связывают Edge.
  - Анонимную переменную получают добавлением Variable к объявляющему Codec, указывающему на вид (GEUL, WIKIDATA-*) (например, «президент» Викиданных + Variable). Кореференция не отслеживается, и снова на неё указать нельзя. Анонимные переменные друг с другом за одну переменную не считаются.
  - Когда цель позже подтвердится, переменную соединяют с этой целью через `SAME-NODE`. Все выражения, указывающие на ту же переменную, вместе интерпретируются как эта цель.
  - Разные переменные не означают, что реальные цели различны. Если они одно и то же, их соединяют `SAME-NODE`, если разные — `DIFFERENT-NODE`.
  - Variable внешних указывающих Codec (EXTERNAL-POINTER-*, EXTERNAL-ISSUER-*) — это LOCAL-переменная указываемого документа.
  - Пример: если в `президент выступил с речью` личность не определена, используют Variable «президент». Чтобы упомянуть его снова, заводят LOCAL Variable и связывают Edge с видом «президент». Если позже выяснится, что это Обама, переменную соединяют через `SAME-NODE` с Identified «Обама». Все выражения, указывающие на ту же переменную, вместе интерпретируются как Обама.
- Пример: если Q5 (человек) Викиданных использовать как Generic, получится `0151 0005` («человек …»).

## REFERENCE-ISSUER {#reference-issuer}

REFERENCE-ISSUER — форма Reference, определяемая Issuer. Это три последние ячейки зоны Reference. Раскладка совпадает с ISSUER у Value и Edge ([запись и TAG WORD](../record.md#issuer-형식-레코드)).

### Раскладка {#레이아웃-1}

```
TAG WORD          0000 0101 11WW LLLL      Codec 0x05DL / 0x05EL / 0x05FL (WW = ширина Issuer: 01 2, 10 4, 11 16 WORD)
[расширяющий TAG Length]
Issuer            2/4/16 WORD (ширину задаёт Codec)
Номер Codec       2 WORD. Определяет Issuer
Payload           Определяет документ Codec, выпущенный Issuer
```

| Codec | Имя | Ширина Issuer |
|---|---|---|
| `0x05DL` | [REFERENCE-ISSUER-2WORD](0x05DL-reference-issuer-2word.md) | 2 WORD |
| `0x05EL` | [REFERENCE-ISSUER-4WORD](0x05EL-reference-issuer-4word.md) | 4 WORD |
| `0x05FL` | [REFERENCE-ISSUER-16WORD](0x05FL-reference-issuer-16word.md) | 16 WORD |

- У каждого кода есть страница: [REFERENCE-ISSUER-2WORD](0x05DL-reference-issuer-2word.md), [REFERENCE-ISSUER-4WORD](0x05EL-reference-issuer-4word.md), [REFERENCE-ISSUER-16WORD](0x05FL-reference-issuer-16word.md).
- Документ кодека Issuer GEUL — по одному на код, в нём три FIELD: Issuer (2·4·16 WORD), номер Codec (2 WORD), Payload (определяет кодек Issuer).

### Интерпретация и действительность {#해석과-유효성}

- GEUL по Length знает только границу Payload. Payload не интерпретируют без кодовой книги.
- Смысл номера Codec и квантификацию определяет Issuer. То, на что он указывает, тоже определяет документ Codec, выпущенный Issuer.
- Общие правила Reference не применяются: наименьшая ширина ID цели, запись ID цели `0` одним WORD, Quantifier, чтение квантификации и системы по смещению внутри раздела, деление на объявление и указание, указываемая цель.
- Номер Codec 2 WORD — как у ISSUER Value и Edge. Если номеров не хватает, получают ещё один Issuer.
- Декодер, не знающий форму, знает Kind, Length, Issuer и номер Codec и пропускает остальное по Length.
- Лицензию формы Issuer определяет этот Issuer ([Issuer и публикация](../issuer.md#라이선스)).
