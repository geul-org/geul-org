GEUL-SIDX — Reference-декларация, указывающая на объект через GEUL SIDX (Semantic-aligned Index). SIDX — идентификатор, у которого смысл (вид, свойства) заложен в самих битах.

## Раскладка

```
TAG WORD          0000 0LLL L001 1QQQ      CCCC = 0011
[Length extension TAG]
SIDX              всё остальное
```

- Quantifier тот же, что у других Codec-деклараций. Variable — анонимная переменная этого вида ([Reference](/ru/grammar/reference/), Variable). Квантификация задаётся только через `QQQ`. В значение SIDX квантификация не вкладывается.
- Документ спецификации объявляет SIDX одним сырым полем остаточной ширины. Когда правило ширины будет определено, это будет заменено.

## Пример

| SIDX | WORD sequence |
|---|---|
| (ненормативно) 64 бита `0x1234 5678 9abc def0`, Identified | `0218 1234 5678 9abc def0` |

## Принцип назначения

- Роль отличается от [GEUL](/ru/grammar/reference/geul/). GEUL — идентификатор личности, который в основном назначается по порядку (auto increment), а GEUL-SIDX — семантический адрес, где близким по смыслу объектам даются близкие значения.
- Степень близости определяется статистикой, накопленной по данным использования. Пока статистика не накоплена, используется GEUL ID; после назначения SIDX GEUL и GEUL-SIDX одного и того же объекта связываются через [SAME-NODE](/ru/grammar/edge/same-node/).

## Открытые вопросы

- **Ширина.** Определяется по статистике. Рассматриваются 4 WORD (64 бита), 16 WORD и т. д. У SIDX смысл лежит в старших битах, поэтому правило «наименьшей ширины» (запрет ведущего `0x0000`), как у других Codec-деклараций, к нему применить нельзя. Поэтому ширина будет фиксированной (или фиксированной для каждого подформата). Пока она не определена, документ спецификации объявляет SIDX сырым значением остаточной ширины.
- **Стабильность назначения.** В Reference одинаковые целочисленные значения означают один и тот же объект, а назначенные ID не используются повторно. Чтобы не переносить уже назначенный SIDX при изменении статистики, нужно назначение append-only (разрежённое назначение, оставляющее места рядом по смыслу). Если переносить придётся часто, нужно решить, определять ли SIDX не как постоянный идентификатор, а как индекс, привязанный к версии реестра.
- **Уникальность.** Если SIDX генерируется из смысла битов и может сталкиваться, это не согласуется с предпосылкой «одинаковые целочисленные значения — один и тот же объект». При назначении коллизии разрешаются, чтобы гарантировать уникальность.
