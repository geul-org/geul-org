Как Codec строит Payload, определяет кодекбук. Кодекбук GEUL — не отдельный формат, а **документ GEUL**. Один Codec — одна спецификация.

## Где находится спецификация

Спецификации прямых кодов публикует Issuer GEUL (`0x0000`). ID документа — TAG WORD этого Codec (только позиции Kind и Codec, Length равен 0), расширенный до 4 WORD.

```
/.well-known/geul/0x0000/0x000000000000<TAG>.geul
```

| Codec | TAG | Спецификация |
|---|---|---|
| Reference LOCAL | `0008` | `0x0000/0x0000000000000008` |
| Value QUANTITY | `0806` | `0x0000/0x0000000000000806` |
| Edge TRIPLE | `100A` | `0x0000/0x000000000000100A` |
| Edge PUBLICATION | `1018` | `0x0000/0x0000000000001018` |

Декодер строит адрес спецификации только по TAG WORD. Встретив неизвестный Codec, он может получить и прочитать этот документ.

- `<TAG>` — 4 hex-цифры целевого TAG WORD. Позиция Length — `0000`; у Reference биты Quantifier равны `000` (для LOCAL — `0008`).
- Reference Codec `0000` зарезервирован, поэтому спецификации с целевым TAG WORD `0x0000` нет. Благодаря этому спецификации не пересекаются с индексным документом определений терминов Issuer GEUL (ID документа `0`, [Issuer и публикация](/ru/grammar/issuer/#документы-определения-терминов)). У [маркера места](/ru/grammar/reference/slot-marker/) Codec `0000` (`0x0000`–`0x0002`) спецификации тоже нет. Он встроен в декодер ([уровень 0](/ru/grammar/publishing/#уровни)).
- В спецификации в качестве `DOC-ID` ставится DOC-POINTER (`0x0000`, `0x000000000000<TAG>`, `0`). Запись списка версий использует тот же DOC-POINTER.
- Как и другие документы, спецификации связываются со slug-именем в нижнем регистре в индексе имён Issuer GEUL `0x0000/documents.geul`. Например: `publication` → `geul.org/publication/` = `0x0000/0x0000000000001018/` ([Адрес публикации и список версий](/ru/grammar/publishing/#имя-документа)).
- Правила версий, канонического адреса и подписи — те же, что у обычных опубликованных документов.

### ID документов Issuer GEUL

| ID документа | Применение |
|---|---|
| `0x0000000000000000` | Индексный документ определений терминов |
| `0x00000000 0000xxxx` | Спецификация Codec. `xxxx` — целевой TAG WORD |
| `0x0001xxxx xxxxxxxx` | Документы определений терминов geul.org. Один термин — один документ ([Issuer и публикация](/ru/grammar/issuer/#документы-определения-терминов)) |

- `0x00000000 0000xxxx` зарезервирован для спецификаций Codec. Другие документы Issuer GEUL (например, документы собственных форматов ISSUER GEUL, которые вводятся, если прямых кодов не хватает) этот диапазон не используют.

### Кодекбук и версия спецификации

- Документы кодекбука не подключаются через `IMPORT-DOC`. Какому кодекбуку следовать, определяет [SPEC-VERSION](/ru/grammar/meta/declaration/spec-version/) в HEAD документа.
- Любой декодер либо встраивает ядро кодекбука, либо получает его по этому адресу.
- Когда предложение (Prefix `000`) принимается как стандарт, раскладка остаётся прежней, а Prefix меняется на `001` ([Обзор](/ru/grammar/overview/#структура-областей)). Целевой TAG WORD при этом меняется, поэтому принятая редакция становится новой спецификацией с другим ID документа, а документ предложения остаётся неизменным.

## Четыре словаря

| Edge | Codec | Что делает |
|---|---|---|
| DECLARE | `0x1B` | Объявляет состав Payload одного Codec. Целевой TAG WORD — 1 WORD |
| FIELD | `0x1C` | Одно поле Payload. Принадлежащий DECLARE и ширина |
| ENUM | `0x1D` | Придаёт смысл одному кодовому значению простого (raw) поля |
| CODEC | `0x1E` | Указывает один Kind и Codec, принимаемые полем |

- Раскладки четырёх Edge встроены в декодер ([уровень 0](/ru/grammar/publishing/#уровни)), поскольку спецификации нужно читать без кодекбука. Для чтения спецификации другие спецификации не нужны.
- Имена (Codec, полей, кодовых значений) во всех случаях связываются через BIND.

### FIELD

```
Edge Id           LOCAL
DECLARE           LOCAL (DECLARE, которому принадлежит это поле)
ширина            1 WORD: 0 = запись, n = простое (raw) значение в n WORD, 0xFFFF = оставшееся простое значение
```

- **Порядок внутри документа** FIELD, указывающих на один DECLARE, — это порядок полей Payload.
- Поле-запись начинается с TAG WORD и читается на длину из его Length.
- Простое (raw) поле — беззнаковое целое, читаемое на заданное число WORD. Значения, требующие интерпретации (знак, дробь, дата), оформляются не как простое поле, а как запись Value.
- Оставшееся простое значение (`0xFFFF`) может быть только одно, и после него идут лишь простые значения фиксированной ширины.
- Edge Id у Edge не объявляется как FIELD. Он первый элемент всякого Edge и потому подразумевается.
- Позиция после последовательного чтения полей должна точно совпадать с концом записи.

### CODEC

Задаёт формат, принимаемый полем. В целевом WORD используются позиции Kind и Codec из TAG WORD как есть.

| Позиция Length | Смысл | Пример |
|---|---|---|
| `0000` | Точный Codec | `0810` SIGNED-DECIMAL, `0008` LOCAL |
| `1111` | Шаблон (wildcard): подходят любые значения в нулевых битах Codec | `0780` любой Reference, `0F80` любой Value, `07A0` QID Викиданных (независимо от квантификации) |

- Если у поля-записи нет CODEC, оно принимает любую запись (кроме маркера места). Если есть один или несколько, запись должна быть одной из них (закрытый список).
- Если у простого поля задан один CODEC, это значение интерпретируется как такой Value без TAG.

### Необязательные поля и маркер места

[Маркер места](/ru/grammar/reference/slot-marker/) — набор записей в 1 WORD зарезервированного Reference Codec `0000`. Он может стоять на месте поля, только если список CODEC поля содержит этот WORD как точную цель.

| Цель CODEC | Маркер | Поле в этом случае |
|---|---|---|
| `0000` | ABSENT, не записано | **необязательное поле**. Его можно опустить |
| `0001` | UNKNOWN-VALUE, неизвестно | принимает утверждение «значение есть, но какое — неизвестно» |
| `0002` | NO-VALUE, нет | принимает утверждение «значения нет» |

- **Правило приёма:** маркер допустим только тогда, когда тот же WORD есть в списке CODEC поля как точная цель. Поле с шаблоном (`0780`, `0781`, `0F80` …) и поле без CODEC («любая запись») маркер не принимают. На месте записей HEAD и BODY и на месте Edge Id маркер недопустим (invalid).
- Чтобы опустить необязательное поле, на его месте записывается один WORD `0x0000` (ABSENT). Необязательное поле тоже всегда занимает место. Поэтому у записи ровно одно представление, а разбор определяется только позицией.
- Маркер — зарезервированный Reference Codec, поэтому он не пересекается с другими записями, и декодер, не знающий спецификации, тоже пропускает его как запись в 1 WORD.
- Три маркера означают разное. ABSENT — высказывание о документе (это место не заполнено), поэтому он ничего не утверждает о мире. UNKNOWN-VALUE — утверждение, что значение есть (`∃x`), NO-VALUE — утверждение, что значения нет (`¬∃x`, в рамках ограничивающих условий). Пропуск — это «не записано», а не «нет значения».
- Что именно означает маркер, определяет спецификация Codec, который его принимает ([TRIPLE](/ru/grammar/edge/triple/), [QUALIFIER](/ru/grammar/edge/qualifier/)).

## Пример: спецификация TRIPLE

BODY документа `0x0000/0x000000000000100A`.

| Edge | Содержание | Имя (BIND) |
|---|---|---|
| #1 DECLARE | цель `100A` | `TRIPLE` |
| #2 FIELD | поле #1, запись | `predicate` |
| #3 FIELD | поле #1, запись | `subject` |
| #4 FIELD | поле #1, запись | `object` |
| #5 FIELD | поле #1, простое значение 1 WORD | `rank` |
| #6–#8 ENUM | кодовые значения #5: 0, 1, 2 | `normal`, `preferred`, `deprecated` |
| #17 CODEC | #5 интерпретируется как UNSIGNED-INTEGER (`0802`) | |
| #18, #19 CODEC | #4 — любой Reference (`0780`) или любой Value (`0F80`) | |
| #20, #21 CODEC | #4 принимает также UNKNOWN-VALUE (`0001`) и NO-VALUE (`0002`) | |

По одному этому документу декодер делит запись TRIPLE на поля, показывает их с именами и проверяет соответствие формату.

## Пример: спецификация QUANTITY

В Value QUANTITY (`0806`) все четыре поля — записи.

| Поле | CODEC |
|---|---|
| `amount` | `0810` SIGNED-DECIMAL |
| `unit` | `0780` любой Reference, `0000` необязательное |
| `lower` | `0810` SIGNED-DECIMAL, `0000` необязательное |
| `upper` | `0810` SIGNED-DECIMAL, `0000` необязательное |

## Правила

- В одной спецификации один DECLARE. Цель DECLARE совпадает с TAG WORD в ID документа.
- В одном документе одна и та же цель не объявляется дважды.
- Варианты с различным составом полей не оформляются как ветвление. Для каждого Codec объявление делается отдельно.
- Раскладка, в которой больше одного простого значения переменной длины или в которой ширина простого значения зависит от другого значения, объявлена быть не может. Такие части оборачивают в запись.
- Спецификации публикуются версиями, как и другие документы. Но бинарная раскладка Codec не редактируется. Чтобы её изменить, назначают новый Codec.

## Открытые вопросы

- Соответствие между значением `SPEC-VERSION` (для v1 `0x0001`) и версией документа кодекбука. Meta родословной, связывающая принятую редакцию с предложением.
