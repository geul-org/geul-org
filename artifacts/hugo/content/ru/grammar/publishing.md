GEUL указывает на документы не строкой URL, а ID (Issuer, ID документа, ID версии). Адрес определяется по ID. Эта страница задаёт правила публикации, необходимые для согласованной работы кодировщиков, декодеров и резолверов. Классы Issuer и способы раскрытия определяет страница [Issuer и публикация](/ru/grammar/issuer/).

## Запись ID

ID в адресе записывается в hex.

- Префикс — `0x` в нижнем регистре, hex-цифры тоже в нижнем регистре.
- Число цифр фиксировано: ширина × 4. Ведущие нули не опускаются, число цифр и есть ширина.
- ID Issuer записывается самой короткой шириной, в которую помещается значение. Расширенной записи вроде `0x00000005` нет (`0x0005`).

| Объект | Ширина | Цифр | Пример |
|---|---|---|---|
| Issuer | 1 WORD | 4 | `0x0001` |
| Issuer | 2 WORD | 8 | `0x00010000` |
| Issuer | 4 WORD | 16 | `0x0000000100000000` |
| Issuer | 16 WORD | 64 | `0x` + 64 цифры |
| ID документа | 4 WORD | 16 | `0x0000000000000000` |
| ID версии | 2 WORD | 8 | `0x00000003` |
| Хеш содержимого | 16 WORD | 64 | `0x` + 64 цифры |

- Запрос не в канонической форме (`0X`, верхний регистр, пропущенные нули) перенаправляется кодом `301` на адрес в канонической форме. Так ключ кэша и объект подписи определяются однозначно.
- Правила ID версии (с 1, `0` — последняя, назначает публикующая сторона, при исчерпании — новый ID документа) задаёт страница [Документ](/ru/grammar/document/#версии).

## Адрес публикации

```
/.well-known/geul/<Issuer>/<ID документа>.geul              последняя версия. Перенаправляет кодом 302 на канонический адрес (изменяемый)
/.well-known/geul/<Issuer>/<ID документа>/<ID версии>.geul  один экземпляр документа (неизменяемый, канонический адрес)
/.well-known/geul/<Issuer>/<ID документа>/versions.geul     документ списка версий (изменяемый, подписанный)
/.well-known/geul/h/<хеш содержимого>.geul                  поиск по хешу содержимого (неизменяемый)
```

Пример: `/.well-known/geul/0x0001/0x0000000000000000.geul`

- Путь следует `.well-known` из RFC 8615. geul.org и частная публикация используют один и тот же путь, различается лишь домен. Регистрируемый суффикс один — `geul`.
- Содержимое документа отдаётся только по неизменяемым адресам. Адрес последней версии содержимого не отдаёт, а перенаправляет кодом `302` на канонический адрес этой версии.
- Канонический адрес версии — `/<Issuer>/<ID документа>/<ID версии>.geul`. Другие адреса, отдающие то же содержимое, указывают на канонический через `Link: rel=canonical`.
- Неизменяемые адреса можно держать в постоянном кэше и CDN. Получатель проверяет их по хешу содержимого из списка версий (или файла блокировки).
- ID всегда начинается с `0x`. Поэтому зарезервированные имена (`h`, `keys`, `issuers.geul`, `documents.geul`, `versions.geul`) и имена, данные людьми, не пересекаются с ID, даже если состоят только из hex-символов, как `add` или `cafe`.
- Местоположение (с какого сервера получать) в содержимое документа не включается. Иначе при смене адреса менялся бы хеш содержимого. Местоположение определяют настройки принимающей стороны.

### Указание формата

- Расширение означает явное указание формата. `.geul` — бинарный формат (`application/vnd.geul`).
- Без расширения учитывается заголовок `Accept`. Браузеру отдаётся HTML-представление, инструментам — бинарный формат. Пример: `/<Issuer>/<ID документа>/<ID версии>`
- Каноническая форма документа — бинарная. Хеш содержимого и подпись вычисляются только по бинарной форме.

### Доменное имя

Issuer, прошедший подтверждение владения доменом, может в адресе на месте `<Issuer>` использовать этот домен вместо ID.

```
/.well-known/geul/<домен>/<ID документа>.geul                  → 302 → /<Issuer>/<ID документа>.geul
/.well-known/geul/<домен>/<ID документа>/<ID версии>.geul      → 302 → /<Issuer>/<ID документа>/<ID версии>.geul
/.well-known/geul/<домен>/<ID документа>/                      → 302 → /<Issuer>/<ID документа>/
```

Пример: `/.well-known/geul/geul.org/0x0000000000001018/0x00000001.geul`

- Адрес с доменом содержимого не отдаёт, а перенаправляет кодом `302` на адрес с ID. Канонический адрес, ключ кэша и объект подписи — адрес с ID. Соответствие может измениться, поэтому постоянный редирект не используется.
- Домен записывается в нижнем регистре, интернационализированный домен — в форме IDNA (punycode). Завершающая `.` не ставится. Запись не в канонической форме перенаправляется кодом `301` на каноническую.
- В домене есть `.`, поэтому он не пересекается с ID, начинающимся с `0x`, и с зарезервированными именами.
- Получив адрес с доменом, резолвер проверяет соответствие по индексу имён Issuer, заменяет домен на ID и фиксирует это в файле блокировки.
- Issuer в 16 WORD, у которых нет реестра, и изолированные от сети среды, не имеющие доступа к geul.org, не могут использовать доменные имена. Они используют адрес с ID.

### Имя Issuer

Индекс имён Issuer — один документ, `/.well-known/geul/issuers.geul`.

```
BODY
  BIND   Subject = ISSUER-POINTER(Issuer)   имя = "geul.org"
  …
```

- Subject — [ISSUER-POINTER](/ru/grammar/reference/issuer-pointer/) (сам Issuer), имя связывается через [BIND](/ru/grammar/edge/bind/).
- Имя — домен, прошедший подтверждение владения. Пишется в нижнем регистре, интернационализированный домен — в IDNA (punycode). Одно имя связывается только с одним Issuer.
- Отображаемое людям имя Issuer (по языкам) присоединяется к тому же Subject описательным [LABEL](/ru/grammar/edge/label/).
- Подписывает geul.org (Issuer GEUL); при изменениях запись добавляется, а не исправляется (то же правило цепочки, что у списка версий).
- Зарезервированное имя `issuers.geul` содержит `.` и потому выглядит как домен. Даже если появится домен с таким именем, этот путь остаётся индексом имён Issuer.

### Имя документа

Вместо ID документа в адресе можно использовать имя документа. На месте `<Issuer>` пишется ID или доменное имя.

```
/.well-known/geul/<Issuer|домен>/<имя документа>.geul                  → 302 → /<Issuer>/<ID документа>.geul
/.well-known/geul/<Issuer|домен>/<имя документа>/<ID версии>.geul      → 302 → /<Issuer>/<ID документа>/<ID версии>.geul
/.well-known/geul/<Issuer|домен>/<имя документа>/                      → 302 → /<Issuer>/<ID документа>/
```

Пример: `/.well-known/geul/geul.org/publication/0x00000001.geul` → `/0x0000/0x0000000000001018/0x00000001.geul`

**Имена документов связывает через BIND индекс имён Issuer `/<Issuer>/documents.geul`.** Резолвер по этому индексу сопоставляет имя с ID документа.

```
BODY
  BIND   Subject = DOC-POINTER(Issuer, ID документа, версия 0)   имя = "publication"
  …
```

- Subject — [DOC-POINTER](/ru/grammar/reference/doc-pointer/) (Issuer, ID документа, версия `0`). Имя связывается не с версией, а с документом.
- Issuer у Subject должен совпадать с Issuer, который ведёт индекс. Документы другого Issuer игнорируются.
- Имя связывается только с опубликованным документом.
- Имя документа — slug из ASCII в нижнем регистре: `a-z`, `0-9`, `-`. Не начинается и не заканчивается на `-` и не начинается с `0x`. Поэтому оно не пересекается с ID документа (`0x…`) и зарезервированными именами (`h`, `versions.geul` и т. п.) ([BIND](/ru/grammar/edge/bind/)).
- В пределах одного Issuer имя связывается только с одним документом, и однажды связанное имя другому документу повторно не присваивается. При смене имени добавляется новый BIND. Старое имя продолжает перенаправлять на тот же документ. Если одно имя встречается несколько раз, главным считается последний BIND.
- Собственное имя в документе не записывается. Канонический адрес, ключ кэша и объект подписи — адрес с ID. IMPORT и цитаты внутри документа используют только ID.
- Заголовок, читаемый людьми (по языкам), именем не является. Он присоединяется описательным `LABEL`.
- В документ списка версий тоже можно поместить такой же BIND имени документа ([PUBLICATION](/ru/grammar/edge/publication/#имя-документа)). Если он есть, он должен совпадать с индексом имён. Резолвер читает только индекс имён.

### Удалённые документы

- По адресу версии, удалённой юридически или по служебной обязанности, возвращается `410 Gone` и надгробие (ID версии, хеш содержимого, дата удаления, категория причины).
- В списке версий это остаётся записью [TOMBSTONE](/ru/grammar/edge/publication/).

## Уровни

GEUL выражает документом GEUL даже происхождение, мета-сведения и списки. Минимум, необходимый для их чтения, встроен в декодер, чтобы разорвать цикл. Каждый уровень опирается только на нижележащие.

| Уровень | Содержание | На что опирается |
|---|---|---|
| Уровень 0 | Правила, встроенные в декодер: фрейминг, хеш содержимого, проверка подписи, Codec записей списка версий (`PUBLICATION`, `DEPRECATION`, `TOMBSTONE`), словарь спецификаций Codec (`DECLARE`, `FIELD`, `ENUM`, `CODEC`), [маркер места](/ru/grammar/reference/slot-marker/) (`0x0000`–`0x0002`), доверенные ключи, получаемые вне документа | Ни на что. Запросов не делает |
| Уровень 1 | Документ списка версий | Уровень 0 |
| Уровень 2 | Обычные документы, кодекбуки, спецификации Codec, документы ключей проверки Issuer | Находятся через уровень 1, проверяются через уровень 0 |

- Ни один уровень не опирается на свой уровень или вышестоящие.
- Различаются то, что выражается в GEUL, и то, что читается лишь при интерпретации средствами GEUL. Уровень 0 можно выразить в GEUL, но для его интерпретации запросы не нужны.
- Сюда же помещается неизменное ядро, которое нельзя заменить документом TOULMIN, — например смысл суждения ([TOULMIN](/ru/grammar/edge/toulmin/#метапознание-и-самопересмотр)).

## Список версий

Публикующая сторона ведёт для каждого документа один документ списка версий (`/<Issuer>/<ID документа>/versions.geul`), дополняя его. Формат записей и структуру документа определяет [PUBLICATION](/ru/grammar/edge/publication/).

```
DOC-*
  SPEC-VERSION
  PARENT          хеш содержимого предыдущего списка
  RECORDED-AT     время выпуска этого списка
  NEXT-LOCAL-ID   LOCAL ID, который будет назначен следующим
  SIGNATURE       подпись публикующей стороны
BODY
  PUBLICATION     #1  документ@1  хеш содержимого
  PUBLICATION     #2  документ@2  хеш содержимого
  DEPRECATION     #3  документ@1
  …
END
```

| Edge | Смысл |
|---|---|
| PUBLICATION | Публикует одну версию документа и её хеш содержимого |
| DEPRECATION | Помечает опубликованную версию рекомендацией об отказе от использования. Она продолжает интерпретироваться |
| TOMBSTONE | Удаляет опубликованную версию (юридическое удаление или по служебной обязанности). Записывается категория причины |

- Записи только добавляются. Их нельзя исправлять, удалять и переставлять. Deprecate и удаление тоже добавляют записи. Новый список сохраняет BODY предыдущего списка как есть в начале и добавляет записи; списки связаны цепочкой хешей `PARENT`.
- Имеется в виду неизменность записи о публикации, а не редактирование содержимого документа ([Документ](/ru/grammar/document/#редакции)). Текущее состояние версии вычисляется последовательным применением записей.
- ID версий идут по возрастанию с 1 без пропусков. Одно и то же содержимое повторно не публикуется.
- Последняя версия — наибольшая версия, которая не отмечена ни рекомендацией об отказе, ни удалением.
- Время в записях не указывается. Время публикации — `RECORDED-AT` списка, в котором запись впервые появилась.
- В документе списка нет `DOC-ID`. О том, чей это список, говорит ID документа в записях.
- В документе списка нет IMPORT, используются только Codec уровня 0.
- Документ списка не включается в другой список (списка списков нет). На прежние списки указывают только по хешу содержимого (`h/<хеш содержимого>.geul`), а история связывается цепочкой `PARENT`.
- Единственный изменяемый адрес — адрес последнего списка (`/<Issuer>/<ID документа>/versions.geul`). Изменяемый указатель нельзя сделать документом, поэтому полученный список проверяется по подписи, `RECORDED-AT` и `PARENT`.

### Подписывающая сторона

| Подпись | Кто подписывает | Что подписывается |
|---|---|---|
| Подпись документа | Issuer этого документа | Хеш содержимого документа ([Issuer и публикация](/ru/grammar/issuer/#подпись)) |
| Подпись списка | Публикующая сторона, назначившая ID версий | Хеш содержимого документа списка |

- Публикацию через geul.org ведёт и ID версий назначает, а список подписывает geul.org (Issuer GEUL); частную публикацию — сам этот Issuer.
- Автор отвечает за содержимое, публикующая сторона — за номера и порядок.

### Проверка

- Подпись исключается из хеша содержимого, поэтому при её удалении хеш не меняется. Поэтому проверка формулируется не как «если подпись есть, проверить», а как «должна быть подпись заданного ключа». Какие ключи требовать, определяют настройки доверия резолвера и файл блокировки.
- Резолвер записывает в файл блокировки хеш содержимого последнего виденного списка. Если в цепочке `PARENT` вновь полученного списка этого хеша нет, список отклоняется (защита от отката и ветвления).
- Зеркала и изолированные от сети среды копируют цепочку документов списка вместе. При наличии открытого ключа проверка выполняется офлайн.
- Полученный документ проверяется по хешу содержимого независимо от источника. Источнику доверять не нужно.

## Разрешение зависимостей

- Документ записывает зависимые документы в HEAD через [IMPORT-DOC](/ru/grammar/meta/import/import-doc/).
- Новая версия не обещает совместимости с предыдущей. Поэтому в целом графе версия документа к одной не сводится (минимальный выбор версий не используется).
- Каждый `IMPORT-DOC` привязан к редакции, которую он зафиксировал. Несколько редакций одного документа могут одновременно присутствовать в одном графе (решение, цитирующее прежний закон, и решение, цитирующее действующий). Ссылка разрешается по (документ, версия, LOCAL ID).
- Подключение последней версии (версия `0`) привязывается к последней редакции на момент интерпретации. Если интерпретация выполняется на заданный момент, то к редакции, действовавшей в этот момент ([Документ](/ru/grammar/document/#редакции)).
- Подключение с фиксацией по ID версии воспроизводимо (содержимое ID версии неизменно и проверяется по файлу блокировки).

## Медиатип

- Медиатип документа GEUL — `application/vnd.geul`. Расширение — `.geul`.
- Даже если его перенесут в стандартное дерево `application/geul`, `application/vnd.geul` продолжат принимать.

## Открытые вопросы

- До какого предела документы Issuer в 1, 2, 4 и 16 WORD обслуживает непосредственно geul.org, а с какого перенаправляет на адреса реестра. Коды состояния в этом случае (канонический 308, последняя версия 302 и 307).
- Обработка расхождения ID версий (тот же ID версии, другое содержимое) при частной публикации, у Issuer в 16 WORD и в изолированных средах.
- Определение текстового представления и согласование содержимого (бинарный формат, текст, HTML-представление в зависимости от `Accept`).
- Соотношение индекса имён документов `documents.geul` и BIND в списке версий (объединять ли в одно), подпись индекса.
- Состав HEAD у `issuers.geul`, формат подписи и цепочки. Правила имён для Issuer без домена (1 и 4 WORD), разрешение споров об именах и верхний предел длины.
- Позволить ли и Issuer в 1 WORD по желанию проходить подтверждение домена и использовать доменное имя.
- Момент и формат перехода от полной цепочки к журналу Merkle (доказательства включения и согласованности), когда списки вырастут.
- Meta, указывающая Issuer, предоставляющего местоположение, в HEAD.
