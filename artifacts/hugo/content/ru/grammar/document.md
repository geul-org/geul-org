Единица данных GEUL — один документ (DOC). Один файл (`.geul`, медиатип `application/vnd.geul`) — это один документ.

## Структура

```
DOC-*            ← открывает документ (полная длина)
  Meta …         ← HEAD: записи о документе
  SOURCE …       ←   (источник всего документа и его QUALIFIER)
BODY             ← завершает HEAD и открывает BODY
  Reference, Value, Edge …
END              ← закрывает документ
```

| Запись | TAG | Смысл |
|---|---|---|
| DOC-1WORD | `1880` + 1 WORD | Открывает документ, задавая полную длину в 1 WORD |
| DOC-2WORD | `1901` + 2 WORD | Полная длина в 2 WORD |
| DOC-4WORD | `1A02` + 4 WORD | Полная длина в 4 WORD |
| BODY | `180E` | 1 WORD. Завершает HEAD и начинает BODY |
| END | `180F` | 1 WORD. Закрывает документ |

- Значение DOC-* — полное число WORD от начала открывающей записи до конца END. Используется самая узкая ширина, в которую значение помещается.
- END обязателен. Если положение END не совпадает с длиной в DOC-*, документ отклоняется. Если ввод закончился без END, документ обрезан.
- По длине в DOC-* декодер может пропустить весь документ сразу.
- Открыть документ, не зная длины, нельзя. Данные реального времени, конец которых заранее неизвестен, режут на единицы известной длины и отправляют несколькими документами.
- Если HEAD пуст, BODY можно опустить. Документ без записи BODY целиком состоит из BODY. BODY ставится только один раз. Если в HEAD есть хотя бы одна запись (Meta или HEAD Edge), BODY ставится.
- Документы не вкладываются друг в друга. На другой документ указывают через [IMPORT](/ru/grammar/meta/) или указывающий Reference.

## HEAD и BODY

- В HEAD помещают только Meta и **HEAD Edge**. Всё это — описание **документа**, который их содержит.
  - Meta: структура, определения, происхождение, родословная, проверка, политика и IMPORT документа.
  - HEAD Edge: обосновывающий Edge [SOURCE](/ru/grammar/edge/source/#источник-всего-документа), записывающий источник всего документа (Target `0`), и [QUALIFIER](/ru/grammar/edge/qualifier/), у которых Target — этот SOURCE (хеш исходного текста, время получения, диапазон в исходном тексте и т. п.). QUALIFIER ставится после своего SOURCE.
- В BODY помещают только Reference, Value и Edge. Происхождение отдельной записи записывается обосновывающим Edge [SOURCE](/ru/grammar/edge/source/) внутри BODY, а прочие основания, например достоверность, — QUALIFIER, присоединённым к этой записи. SOURCE с Target `0` и QUALIFIER, у которых Target — HEAD SOURCE, в BODY ставить нельзя.
- Декодер читает HEAD с начала и разделяет записи. Meta относится к HEAD. SOURCE с Target `0` относится к HEAD, и его Edge Id запоминается. QUALIFIER, у которого Target — запомненный SOURCE, относится к HEAD. Если приходит любая другая запись, то при пустом HEAD это значит, что BODY опущен (BODY начинается с этой записи), иначе документ invalid из-за отсутствующего BODY.
- **HEAD и BODY используют одно пространство номеров Edge Id.** Edge Id уникален в пределах документа и, как у Edge в BODY, берётся из [NEXT-LOCAL-ID](/ru/grammar/meta/lineage/next-local-id/). Если Origin у HEAD Edge — LOCAL, его определение помещается в BODY (область действия LOCAL — весь документ).
- Meta может содержать запись Value внутри Payload. Вложенный Value — не самостоятельная запись, а часть этой Meta.
- Область действия объявлений (класс определений Meta) — этот документ.

## Базовые объявления

Каждое из двух объявлений встречается не более одного раза. В каких документах оно обязательно, определяют условия ниже.

| Meta | Смысл | В каких документах обязательно |
|---|---|---|
| [SPEC-VERSION](/ru/grammar/meta/declaration/spec-version/) | Версия спецификации, которой следует документ. Определяет, как читать остальные записи. Если версия неизвестна, документ отклоняют или выдают предупреждение. Для документов v1 значение `0x0001` | Опубликованные документы. Если нет — читается по версии, известной декодеру |
| [DOC-ID](/ru/grammar/meta/declaration/doc-id/) | Идентификатор самого документа. Нужен, чтобы указывать на этот документ и на объекты в нём извне | Документы под `.well-known/geul/` с именем, начинающимся с `0x` (документы версий, спецификации). В список версий и индекс имён не помещается |

- `SPEC-VERSION` содержит одно целое число, чтобы его мог прочитать декодер любой версии (для v1 `1890 0001`). Он не опирается на код Value.
- `DOC-ID` — DOC-POINTER, указывающий на сам документ (Issuer, ID документа, версия `0`). ID документа занимает 4 WORD.
- Документ без `DOC-ID` — безымянный документ. На него можно указать только по хешу содержимого.

## Хеш содержимого

Один экземпляр документа определяется **хешем содержимого** (та же роль, что у ID коммита в git).

- Это SHA-256 от открывающей записи (DOC-*) до записи непосредственно перед END. 16 WORD.
- Meta класса проверки (подпись и т. п.) из вычисления исключаются. Поэтому подпись внутри документа не создаёт цикла.
- При вычислении длина в DOC-* заменяется длиной без записей проверки, а ширина — самой узкой, подходящей этой длине. Поэтому хеш содержимого до и после добавления подписи одинаков.
- Хеш содержимого в документе не записывается, а вычисляется. Как значение он указывается только при ссылке на другую версию (`PARENT` и т. п.).
- `PARENT` внутри документа тоже входит в вычисление, поэтому хеш содержимого образует цепочку хешей через всю историю.
- Meta, добавленная позже вне документа (комментарий в отдельном хранилище и т. п.), хеш содержимого не меняет (как git notes).
- Каноническая форма документа — бинарная. Хеш содержимого и подпись вычисляются только по бинарной форме.

## Версии

Именованный документ (с `DOC-ID`) имеет версии.

- **ID версии** — 2-WORD целое число, которое в пределах документа нумеруется с 1 в порядке публикации. `0` означает «версия не указана» и трактуется как последняя версия.
- ID версии назначает публикующая сторона при публикации. Соответствие между ID версии и хешем содержимого хранится в списке версий, подписанном публикующей стороной ([Адрес публикации и список версий](/ru/grammar/publishing/#список-версий)).
- Одно и то же содержимое повторно не публикуется. Если такой хеш содержимого уже есть, возвращается его ID версии.
- Если 2 WORD исчерпаны, документ выпускается под новым ID документа.
- Начиная с v2 версии в HEAD записывают `PARENT` (хеш содержимого предыдущей версии). Он входит в хеш содержимого, поэтому версии связываются в цепочку хешей. В первой версии его нет.

## Редакции

Документы GEUL изменяются в редакциях, как законы.

- **Версия неизменна.** Опубликованная версия не изменяется и не удаляется. Исключения — только юридическое удаление и удаление по служебной обязанности ([TOMBSTONE](/ru/grammar/edge/publication/)).
- История не стирается. Исправления выходят новой версией, исходная версия не перезаписывается (сохранение прежней редакции закона). Исправленная версия связывается с исходной через [REPLACES](/ru/grammar/meta/lineage/replaces/).
- Изменяемые указатели, такие как branch, HEAD, reflog, в документе не хранятся. Ими управляют вне документа (в хранилище или индексе).
- Новая версия может вводить, изменять и удалять определения. Совместимость с предыдущей версией не обещается. Изменение определения одного и того же термина — тоже редакция (например, «совершеннолетие» в Гражданском кодексе Кореи: 20 лет → 19 лет; объект изнасилования в Уголовном кодексе: «женщина» → «человек»).
- **LOCAL ID — идентичность, переходящая через версии** (как номер статьи). Один и тот же LOCAL ID в разных версиях указывает на один и тот же объект.
  - Введение: получает новый LOCAL ID. У ID нет смысла порядка, поэтому вставки вроде «статья X-2» не нужны. Новый номер берётся из `NEXT-LOCAL-ID` списка версий (auto increment).
  - Изменение: меняется содержимое под тем же LOCAL ID.
  - Удаление: этот LOCAL ID исключается из новой версии. **Удалённый ID повторно не используется.**
  - Перенос, разделение, объединение: получается новый LOCAL ID, а к новой записи добавляется QUALIFIER P1365 (replaces, значение — прежний LOCAL ID), который связывает с прежним ID. Прежний ID повторно не используется, поэтому он указывает на эту запись в предыдущей версии.
- Инструменты, заново создающие документ из исходного материала, тоже соблюдают это правило. Тем же утверждениям, что и в предыдущей версии, присваивается тот же LOCAL ID, а новый номер получают только изменившиеся или новые утверждения. Нельзя каждый раз нумеровать заново с 1.
- Цитата указывает редакцию. Цитата с зафиксированной версией привязана к этой версии, цитата последней версии (версия `0`) — к действующей версии на момент интерпретации. Документ, в котором рассматривается событие прошлого, цитирует версию, действовавшую в то время.
- Публикация и вступление в силу — разные вещи. Время публикации записывает список версий, срок действия — документ.
  - [EFFECTIVE-FROM](/ru/grammar/meta/declaration/effective-from/), [EFFECTIVE-UNTIL](/ru/grammar/meta/declaration/effective-until/): срок действия версии в целом.
  - QUALIFIER P580 (начало) и P582 (конец) у Edge статьи: когда даты вступления в силу различаются по статьям.
- **Редакция, действующая в момент T, — это наибольшая версия, дата вступления в силу которой не позднее T.** Если у статьи есть QUALIFIER P580/P582, он имеет приоритет. Редакция с истёкшим сроком действия (`EFFECTIVE-UNTIL`) не действует.
- Правила, определяющие, какую редакцию применять, — переходные положения («применяется прежняя норма»), выбор между законом на момент деяния и более благоприятным для обвиняемого новым законом, — относятся к суждению ([TOULMIN](/ru/grammar/edge/toulmin/)). Сведения о вступлении в силу — материал для него.
- Сужение или расширение толкования термина разъяснениями и судебной практикой — не редакция документа, а правило суждения. Если толкование установлено законодательно (например, введение определения «1 неделя» в Законе о трудовых стандартах), это редакция.
- Бинарная (wire) раскладка Codec и номеров форматов не редактируется, потому что записи, закодированные по номеру формата, читаются без фиксации версии кодекбука. Чтобы изменить раскладку, назначают новый номер. Удалённый номер формата другому формату повторно не присваивается.

## Хранение diff

Версия всегда определяется как документ целиком (снимок). diff — лишь формат, позволяющий хранить и передавать этот снимок в меньшем объёме.

- В виде diff можно хранить только документ с `DOC-ID`, у которого весь BODY состоит из Edge. Для `versions.geul`, `documents.geul`, `issuers.geul` без управления версиями и для безымянных документов diff не используется.
- Документ-diff — обычный документ GEUL; в его HEAD помещается [DELTA-BASE](/ru/grammar/meta/lineage/delta-base/) (ID базовой версии).
- Удаление записывается через [DELTA-REMOVE](/ru/grammar/meta/lineage/delta-remove/) (список удаляемых LOCAL ID), добавление и изменение — Edge в BODY. Отдельной отметки «добавлено» или «изменено» нет. Если Edge Id есть в базовой версии, это изменение, если нет — добавление.
- Восстановление снимка должно быть детерминированным (иначе хеш не совпадёт).
  1. Восстановить снимок базовой версии. Если база сама diff, восстанавливать рекурсивно.
  2. HEAD целиком заменяется на HEAD diff без `DELTA-BASE` и `DELTA-REMOVE`. HEAD Edge тоже заменяются вместе с ним (в `DELTA-REMOVE` они не указываются).
  3. BODY сохраняет порядок базовой версии. ID из `DELTA-REMOVE` удаляются, а если Edge Id из BODY diff есть в базовой версии, запись заменяется на месте.
  4. Edge Id, которых нет в базовой версии, добавляются в конец в том порядке, в каком они идут в diff.
  5. Хеш содержимого результата должен совпадать с хешем этой версии в списке версий. Если нет, это invalid.
- Если удалённый LOCAL ID используется в diff повторно, это invalid. Edge Id пропавшего HEAD Edge тоже повторно не используется.
- Хеш содержимого, список версий и подписи всегда относятся к восстановленному снимку.
