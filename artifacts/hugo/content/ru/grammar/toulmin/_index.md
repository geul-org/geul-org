Граф вердиктов и выполнения записывается по модели аргументации Тулмина. Это ключевое семейство, с помощью которого GEUL описывает собственные правила на GEUL и сам их исправляет.

| Группа | Codec |
|---|---|
| объявление | [CASE-DECLARE](0x100L-case-declare.md) (дело), [PREDICATE-DECLARE](0x101L-predicate-declare.md) (предикат), [SPEC-DECLARE](0x102L-spec-declare.md) (критерий), [RULE-DECLARE](0x103L-rule-declare.md) (утверждение), [COUNTER-DECLARE](0x104L-counter-declare.md) (возражение), [EXCEPT-DECLARE](0x105L-except-declare.md) (исключение) — [NODE](#node) |
| отношение | [ATTACKS](0x108L-attacks.md) (атака), [SUPERSEDES](0x109L-supersedes.md) (отстранение) — [LINK](#link), [SUPERSEDE-CHAIN](0x10AL-supersede-chain.md) (цепочка приоритетов, раскладка не определена) |
| выполнение | [RUN](0x110L-run.md), [DO](0x111L-do.md), [DO-ONCE](0x112L-do-once.md), [UNDO](0x113L-undo.md), [CHECKING](0x114L-checking.md) — [LINK](#link), [ENTRY](0x115L-entry.md), [TRIGGER](0x116L-trigger.md) — [NODE](#node) |
| результат | [VERDICT](0x118L-verdict.md) (результат вердикта: Pass, Review, Fail), [EVIDENCE](0x119L-evidence.md) (доказательство вердикта) — раскладка не определена |

- Исходный текст, разбиение, вспомогательные узлы и отношения — прямые коды `0x120L~0x134L` семейства формата TOULMIN ([исходный текст и разбиение](#source와-구획), [формат TOULMIN](#toulmin-형식)).
- Результат вердикта хранится в документе, отличном от объекта вердикта. Документ результата импортирует документ-цель и указывает на него. Поэтому вынесение вердикта не меняет хеш содержимого документа-цели.

Edge семейства TOULMIN (прямые коды `0x100L~0x11BL`, вспомогательные записи — коды `0x120L~0x134L` семейства формата TOULMIN) записывают граф вердиктов и выполнения по модели аргументации Тулмина. Объявления утверждений, возражений и исключений, отношения атаки и отстранения, связи выполнения и результаты вердиктов — всё это Edge. Один документ TANGEUL (язык правил движка toulmin) становится одним документом GEUL. Расширение файла, как и у других документов, — `.geul`.

То, что этот документ не определяет, следует общим правилам [Edge](../edge/_index.md) и [записям и TAG WORD](../record.md).

## Метапознание и самопересмотр {#메타-인지와-자기-개정}

TOULMIN является Codec GEUL, чтобы GEUL мог метапознавать самого себя. Правила вердикта и выполнения тоже должны быть записаны на GEUL, чтобы TOULMIN мог взять эти правила объектом и сам их исправлять. Поэтому TOULMIN — не прикладной профиль, а ключевая часть эксплуатации GEUL, и он помещён в пространство прямых кодов Edge (`0x100L~0x11BL`).

- Самоописание делает возможным самосовершенствование, но несёт риск круговой ошибки. Если правило само выносит вердикт о собственном пересмотре, может пройти и пересмотр, ослабляющий критерий (доля прохождения растёт, а реальная точность падает).
- Круговость принимается как риск, но разрывается структурой.
  - **Неизменное ядро**: смысл вердикта (Pass, Review, Fail, атака, отстранение, приоритет, трёхзначное вычисление и U → Review из раздела [Вердикт при неизвестном](#미상-위에서-판정하기) ниже) зафиксирован в этой спецификации. Документом TOULMIN его изменить нельзя. Это то же место, что у правил, встроенных в декодер (слой 0 в разделе [Публикуемый адрес и список версий](../publishing.md#층)).
  - **Разделение редакций**: по пересмотру документа правил v(n) выносится вердикт на основании правил v(n−1) и внешней проверки. Правило не выносит вердикт о самом себе. Результат вердикта хранится в документе, отличном от цели (хеш содержимого цели не меняется).
  - **Неизменяемая история**: пересмотры накапливаются как новые версии (`PARENT`, хеш содержимого, подпись). Старые версии сохраняются, поэтому круговую ошибку можно найти постфактум и откатить. Страховка самопересмотра — модель редакций GEUL ([Документ](../document.md#개정)).
  - **Внешний критерий**: отдельно держится набор проверочных случаев, которых путь пересмотра коснуться не может. Принятие пересмотра подтверждается результатом на этом наборе.
- Проверка опровержением: намеренно внедряется одно неверное правило. Если система его исправляет и оценка по внешнему критерию растёт, самосовершенствование работает. Если растёт только доля прохождения, а оценка по внешнему критерию падает, это круговая ошибка.

## Код {#코드}

Запись TOULMIN использует одну из трёх раскладок. Раскладку задаёт Codec.

| Раскладка | Применение | Страница |
|---|---|---|
| NODE | узлы графа: дело, правило, определение, точка входа | [NODE](#node) |
| LINK | отношения между узлами (атака, отстранение, выполнение, определение) | [LINK](#link) |
| EXPR | условное выражение (предикат) | [EXPR](0x101L-predicate-declare.md) |

Записи исходного текста и разбиения (SOURCE, TEXT, SECTION, CASE-BEGIN и CASE-END, PROSE) определяет [исходный текст и разбиение](#source와-구획).

- Группы: `0x100L~0x107L` — объявление, `0x108L~0x10FL` — отношение, `0x110L~0x117L` — выполнение, `0x118L~0x11FL` — результат (`0x11CL~0x11FL` Reserved).
- Вердикт всего документа ведёт Meta [VERDICT](../meta/0x1E9L-verdict.md) (`0x1E9L`), вердикт узла или записи — TOULMIN `VERDICT` (Edge `0x118L`). Это два разных Codec с разным Kind.

### Формат TOULMIN {#toulmin-형식}

Исходный текст, разбиение, вспомогательные узлы и отношения помещены в прямые коды `0x120L~0x134L` семейства формата Edge TOULMIN. Полей Issuer и номера Codec нет, Payload идёт сразу за TAG.

```
TAG WORD          0001 0010 0000 LLLL      Edge, Codec 0x120L (SOURCE). У других кодов то же место
[Length extension TAG]
Edge Id           запись LOCAL Reference
компоненты        раскладка, заданная форматом
```

| Codec | Имя | Раскладка | Значение |
|---|---|---|---|
| `0x120L` | [SOURCE](0x120L-source.md) | ID, ширина SPAN WORD, UTF8 Value | авторский исходный текст |
| `0x121L` | [TEXT](0x121L-text.md) | ID, UTF8 Value | имя или строка |
| `0x122L` | [SECTION](0x122L-section.md) | ID, код раздела 1 WORD | начало раздела |
| `0x123L` | [CASE-BEGIN](0x123L-case-begin.md) | ID, REF (дело) | начало области дела |
| `0x124L` | [CASE-END](0x124L-case-end.md) | ID, REF (дело) | конец области дела |
| `0x125L` | [PROSE](0x125L-prose.md) | ID, SPAN | абзац повествования |
| `0x126L` | [NAMESPACE](0x126L-namespace.md) | NODE | `this document is` |
| `0x127L` | [FUNC](0x127L-func.md) | NODE | ссылка на функцию |
| `0x128L` | [FIELD](0x128L-field.md) | NODE | `is required` |
| `0x129L` | [ALIAS](0x129L-alias.md) | NODE | `see … from` |
| `0x12AL` | [GROUP](0x12AL-group.md) | NODE | упорядоченная группа выполнения |
| `0x12BL` | [REQUIRES](0x12BL-requires.md) | LINK | дело → поле |
| `0x12CL` | [MEANS](0x12CL-means.md) | LINK | элемент определения → значение или тип |
| `0x12DL` | [HAS](0x12DL-has.md) | LINK | элемент определения → поле |
| `0x12EL` | [RUNS](0x12EL-runs.md) | LINK | точка входа → дело, выполнение |
| `0x12FL` | [EVALUATES](0x12FL-evaluates.md) | LINK | точка входа → дело, вердикт |
| `0x130L` | [TRIGGERS](0x130L-triggers.md) | LINK | триггер → дело |

| `0x134L` | [LABEL](0x134L-label.md) | LINK | узел → TEXT, запись имени |

## Документ {#문서}

Один файл `.geul` — это один DOC. Вне DOC других байтов нет.

```
DOC-1WORD/2WORD/4WORD     полная длина
  SPEC-VERSION            0x0001 (v1, целое без встроенного Value)
  PROFILE                 UTF8 Value "tangeul-<major>.<minor>". Сейчас "tangeul-1.0"
  [DEFAULT-LANGUAGE]      LANGUAGE-BCP47-CODE Value. Локаль автора ("en", "ko")
BODY
  SOURCE                  авторский исходный текст. Первая запись BODY
  записи предложений …     в порядке объявления в документе
END
```

- HEAD: [SPEC-VERSION](../meta/0x1C5L-spec-version.md), [PROFILE](../meta/0x1C6L-profile.md), необязательный [DEFAULT-LANGUAGE](../meta/0x1CAL-default-language.md).
- Декодер отклоняет документ, если SPEC-VERSION отличается или отличается major у PROFILE. Если отличается только minor, документ читается.
- Первая запись BODY — SOURCE. Все SPAN — диапазоны внутри этого исходного текста.
- Порядок записей предложений совпадает с порядком объявления в документе. На этот порядок опирается порядок выполнения (запуск `do` и `run`, компенсация `undo` в обратном порядке). В документе TOULMIN порядок Edge имеет значение (исключение из правила порядка в [раскладке Edge](../edge/_index.md#레이아웃)).
- Все записи BODY — Edge. Отдельных записей Value нет. Значения встраиваются в Payload Edge.
- Идентичность дела и импорт используют Meta [DOC-ID](../meta/0x1C7L-doc-id.md) и [IMPORT-DOC](../meta/0x1E4L-import-doc.md) (Subject и See в TANGEUL).

## Общие поля {#공통-필드}

| Поле | Ширина | Описание |
|---|---|---|
| ID | запись LOCAL Reference | Edge Id записи. Первый элемент Payload каждой записи |
| REF | запись LOCAL Reference | Edge Id, указывающий на другую запись этого документа. `0` — нет |
| SPAN | ширина, заданная SOURCE × 2 | диапазон внутри авторского исходного текста. Начальный байт, число байтов |

- ID и REF — встроенные записи [LOCAL](../reference/0x005L-local.md) Reference (`0000 0000 0101 LLLL` + ID кратчайшей ширины). Ширину задаёт Length этой записи, на уровне документа она не объявляется.
- REF `0` (LOCAL `0`) означает «нет». Это правило Codec, использующего LOCAL `0` как «нет» ([LOCAL](../reference/0x005L-local.md)).
- Edge Id назначаются с 1 и не повторяются в пределах документа. `0` — «нет» у REF, поэтому как Edge Id не используется.
- На узлы ссылаются вперёд другие записи, поэтому узлы первыми получают номера в порядке объявления в документе. Остальные записи (SOURCE, TEXT, LINK, FUNC, записи разбиения) получают номера кодировщиком, начиная со следующего за узлами.
- Декодер проверяет лишь, что Edge Id не равен 0 и не повторяется. Порядок назначения при интерпретации не используется.
- На узлы и отношения указывают через Edge Id.
- Встроенный Value — это запись Value целиком, вместе с TAG WORD. Длину задаёт её TAG.

## Числа {#수치}

- Значение вердикта (−1~1), Qualifier (0~1) и сила атаки (0~1) — это [SIGNED-DECIMAL](../value/0x068L-signed-decimal.md) Value. Отдельного формата с фиксированной точкой нет.
- Кодировщик отбрасывает конечные нули коэффициента. 0.8 — это `C=8, E=−1`. Декодер принимает до четырёх знаков после запятой.
- Вентиль уверенности (например, `at least 75%`) записывается оператором сравнения 1 WORD и процентным [UNSIGNED-DECIMAL](../value/0x069L-unsigned-decimal.md) Value (`E=0`) ([LINK](#link) F_GATE).
- Сила атаки — поле F_FORCE у ATTACKS ([LINK](#공격-세기)). Выход за диапазон отклоняется.

## Оси объявления узла {#노드-선언의-축}

- Объявление узла (RULE-, COUNTER-, EXCEPT-DECLARE) имеет роль (утверждение, возражение, исключение), Qualifier (0~1) и Level (Unset, Fail, Review). Роль хранит Codec и role в заголовке NODE, Qualifier — F_QUAL, Level — level в заголовке ([NODE](#node)).
- Прочность (Strict, Defeasible, Defeater) — ось, независимая от роли. Размещение прочности пока не определено.
- Сила атаки (Force) — значение не узла, а ребра ATTACKS ([LINK](#공격-세기) F_FORCE). Это иная ось, чем прочность.

## Вердикт при неизвестном {#미상-위에서-판정하기}

Когда граф вердиктов принимает на вход факты GEUL, три понятия [маркера места](../slot-marker.md) (не записано, неизвестно, нет) вычисляются по-разному. Вычисление операторов сравнения [EXPR](0x101L-predicate-declare.md) таково.

| Вход | `is empty` | `is not empty` | `equals` / `is in` / сравнение по величине |
|---|---|---|---|
| значение v | ложь | истина | вычисляется по v |
| NO-VALUE (нет) | **истина** | ложь | ложь |
| UNKNOWN-VALUE (неизвестно) | ложь | **истина** | **неопределённо (U)** |
| ABSENT (не записано) / описания нет | U (открытый мир) | U | U |

- Логика — сильная трёхзначная логика Клини. `NOT U = U`, `ложь AND U = ложь`, `истина OR U = истина`. В остальных сочетаниях U остаётся U.
- `EXISTS any` истинно, если истинен хотя бы один элемент. Если истинных нет, но есть U, результат U, если все ложны — ложь.
- **Если предикат даёт U, вердикт этого узла — не Pass и не Fail, а Review.** Если неизвестно, решение передаётся человеку (или следующему этапу).
- Чтобы читать ABSENT не как U, а как empty, входная сторона должна **объявить** закрытый мир (внедрить через критерий SPEC, например: «вход этого дела полон»). Без объявления это U.
- Эта таблица и соответствие U → Review — смысл вердикта, поэтому они относятся к **неизменному ядру**. Документом TOULMIN их изменить нельзя.
- Пример: правило «считать только границы, действующие и сейчас» (`P582 is empty`) при P582 = UNKNOWN-VALUE даёт ложь и исключает, при P582 = NO-VALUE даёт истину и включает, а если P582 нет, даёт U и отправляет на Review.

## Результат вердикта {#판정-결과}

- Результат вердикта (`VERDICT`, `EVIDENCE`) хранится в документе, отличном от объекта вердикта. Документ результата импортирует документ-цель через [IMPORT-DOC](../meta/0x1E4L-import-doc.md) и указывает на него через [EXTERNAL-POINTER-*](../reference/0x020L-external-pointer-1word.md). Поэтому вынесение вердикта не меняет хеш содержимого документа-цели.
- Вердикт всего документа — Meta `VERDICT`, вердикт узла или записи — TOULMIN `VERDICT`.
- Правила выбора применимой редакции пересмотра (переходные положения, выбор между законом времени действия и новым законом), а также толкования и прецеденты тоже используются как правила вердикта ([Документ](../document.md#개정)).

## Открытые проблемы {#열린-문제}

- Раскладки SUPERSEDE-CHAIN (`0x10AL`), VERDICT (`0x118L`), EVIDENCE (`0x119L`). Достаточно ли для цепочки нынешнего способа с SUPERSEDES на каждую пару.
- Размещение прочности узла (Strict, Defeasible, Defeater).
- ATTACKS с явно записанной силой 1 и ATTACKS без неё дают один вердикт, но разные байты. Совпадение вердиктов нужно сравнивать по интерпретированному значению, а не по байтам.
- Число узлов, число меток и индекс метки в EXPR занимают 1 WORD, а число дочерних — 13 бит. Верхние пределы фиксированы.
- Раскладка PROVENANCE (источник и предпосылки правила).
- Записывать ли имя в обратных кавычках не как TEXT + LABEL (`0x134L`), а как Edge-высказывания [LABEL](../edge/0x0A4L-label.md) и [BIND](../edge/0x0A3L-bind.md).
- Таблица значений кодов predicate и mode у Claim и значений VerbCode у FuncRef.
- Делать ли объявление закрытого мира (чтение ABSENT как empty) на уровне критерия (SPEC) или отдельного дела.
- [Спецификация Codec](../codec-spec.md) для Codec TOULMIN. Условные поля NODE и LINK и ширина SPAN, задаваемая SOURCE, — раскладки, которые нельзя объявить через FIELD.

## NODE {#node}

NODE — раскладка для записи узлов графа вердиктов и выполнения TOULMIN. Вид узла задаёт Codec, а заголовок в 1 WORD задаёт роль, Level, форму Claim и условные поля.

### Codec {#codec}

| Codec | Имя | TANGEUL | Узел |
|---|---|---|---|
| `0x100L` | [CASE-DECLARE](0x100L-case-declare.md) | `in case of` | дело |
| `0x102L` | [SPEC-DECLARE](0x102L-spec-declare.md) | элемент Definitions (`means`, `has`) | критерий (Backing). role задаёт вид определения |
| `0x103L` | [RULE-DECLARE](0x103L-rule-declare.md) | general rule | утверждение (Warrant) |
| `0x104L` | [COUNTER-DECLARE](0x104L-counter-declare.md) | counter rule | возражение (Rebuttal) |
| `0x105L` | [EXCEPT-DECLARE](0x105L-except-declare.md) | except rule | исключение (Defeater) |
| `0x115L` | [ENTRY](0x115L-entry.md) | `provides x` | внешняя точка входа |
| `0x116L` | [TRIGGER](0x116L-trigger.md) | `on`, `every`, `until` | точка входа по событию или периоду |
| `0x126L` | [NAMESPACE](0x126L-namespace.md) | `this document is` | пространство имён документа |
| `0x127L` | [FUNC](0x127L-func.md) | ссылка на функцию | внешняя функция (например, `bank.withdraw`) |
| `0x128L` | [FIELD](0x128L-field.md) | `x is required [as Type]` | обязательное поле |
| `0x129L` | [ALIAS](0x129L-alias.md) | `see a from path` | псевдоним импортированного пакета |
| `0x12AL` | [GROUP](0x12AL-group.md) | `1.` нумерованный список | упорядоченная группа выполнения |

`0x126L~0x12AL` — прямые коды семейства формата Edge TOULMIN ([формат TOULMIN](#toulmin-형식)).

### Раскладка {#레이아웃}

```
ID               запись LOCAL Reference (Edge Id)
заголовок 1 WORD role 2b | Reserved 2b | F_GROUNDS 1b | level 2b | вид object 2b | flags 7b
[F_FUNC]         FuncRef: REF(ALIAS, 0 если нет) + VerbCode 1 WORD
[F_QUAL]         SIGNED-DECIMAL Value. Qualifier
[F_CHECK]        REF(дело)
[F_CLAIM]        Claim: REF(subject) + predicate 1 WORD + object + mode 1 WORD
[F_VERDICT]      SIGNED-DECIMAL Value. Начальное значение вердикта
[F_WITH]         число (UNSIGNED-INTEGER Value) + REF(TEXT) × число
[F_GROUNDS]      число (UNSIGNED-INTEGER Value) + REF(TEXT) × число
SPAN             ширина, заданная SOURCE × 2 (начальный байт, число байтов)
```

#### WORD заголовка {#헤더-word}

| Биты | Поле | Значение |
|---|---|---|
| 15–14 | role | 0 general, 1 counter, 2 except |
| 13–12 | Reserved | 0 |
| 11 | F_GROUNDS | есть список оснований |
| 10–9 | level | 0 Unset, 1 Fail, 2 Review (3 Reserved) |
| 8–7 | вид object | форма object у Claim. 0 REF, 1 UNSIGNED-INTEGER Value, 2 SPAN |
| 6–0 | flags | таблица ниже |

| Бит | flag | Значение |
|---|---|---|
| b0 | F_FUNC | есть поле FuncRef |
| b1 | F_QUAL | есть поле Qualifier |
| b2 | F_CHECK | есть поле дела, по которому только выносится вердикт (`checking`) |
| b3 | F_CLAIM | есть поле Claim |
| b4 | F_VERDICT | есть поле начального значения вердикта |
| b5 | F_STRIKE | объявление, вычеркнутое зачёркиванием. Полей нет |
| b6 | F_WITH | есть поле списка критериев |

- Условные поля идут в порядке flag (F_FUNC, F_QUAL, F_CHECK, F_CLAIM, F_VERDICT, F_WITH, F_GROUNDS). Поле с выключенным flag места не занимает.
- Если flag включён, а поля нет, запись отклоняется. Позиция после последовательного чтения полей, после SPAN, должна в точности совпадать с концом записи.

### Поля {#필드}

| Поле | Описание |
|---|---|
| FuncRef | место функции. REF — запись ALIAS, импортировавшая эту функцию, а для функции этого документа — `0`. VerbCode — код в 1 WORD, пока не назначен (`0x0000` допускается). Исходная запись функции пишется отдельно как TEXT + [LABEL](#link) |
| Qualifier | уверенность узла (0~1) |
| дело | F_CHECK: дело, по которому этот узел только выносит вердикт (`checking c`) |
| Claim | высказывание, которое несёт узел. subject REF, predicate 1 WORD, object, mode 1 WORD. Форму object задаёт вид object в заголовке |
| значение вердикта | начальное значение вердикта (−1~1) |
| F_WITH | критерий на момент объявления (`기준으로 하는`, «принимая за критерий»). Список REF записей TEXT |
| F_GROUNDS | имена внешних фактов, разрешаемых на момент вычисления (`근거로 하는`, «принимая за основание»). Список REF записей TEXT |
| SPAN | диапазон исходного текста, из которого вышло это объявление |

- Запись значения вердикта и Qualifier следует числовым правилам [TOULMIN](#수치).
- Число элементов списка — встроенная запись [UNSIGNED-INTEGER](../value/0x062L-unsigned-integer.md) Value.
- Базовая форма Claim-повествования: subject и predicate равны `0`, а object — SPAN (вид object 2). Фиксируется на исходной записи.

### Интерпретация и действительность {#해석과-유효성}

- role у RULE-, COUNTER-, EXCEPT-DECLARE должен совпадать с Codec (0 general, 1 counter, 2 except). У SPEC-DECLARE это вид определения. У остальных Codec он равен 0.
- Если level равен 0 (Unset), используется значение движка по умолчанию: Fail у COUNTER-DECLARE, Review у EXCEPT-DECLARE.
- Правило функции хоста в `tangl:규칙` TANGEUL (`쓰는 규칙이다`, «правило, которое использует») записывается как NODE RULE-DECLARE вне дела. Функция — F_FUNC, критерий — F_WITH, основание — F_GROUNDS. Только условному правилу предшествует [PREDICATE-DECLARE](0x101L-predicate-declare.md).
- Биты Reserved (13–12) должны быть 0. Если бит Reserved включён или role не соответствует Codec, запись отклоняется.

## LINK {#link}

LINK — раскладка для записи отношений между узлами в графе TOULMIN. Вид отношения задаёт Codec.

### Codec {#codec-1}

| Codec | Имя | TANGEUL | src → dst |
|---|---|---|---|
| `0x108L` | [ATTACKS](0x108L-attacks.md) | `don't X when Y` | правило → правило. Постепенно уменьшает вердикт на силу атаки |
| `0x109L` | [SUPERSEDES](0x109L-supersedes.md) | `X supersedes Y` | правило → правило. Если Active, исключает цель из агрегирования |
| `0x110L` | [RUN](0x110L-run.md) | `run c when n` | правило → дело |
| `0x111L` | [DO](0x111L-do.md) | `do fn when n` | правило → FuncRef |
| `0x112L` | [DO-ONCE](0x112L-do-once.md) | `do fn once when n` | правило → FuncRef |
| `0x113L` | [UNDO](0x113L-undo.md) | `undo fn when n` | правило → FuncRef |
| `0x114L` | [CHECKING](0x114L-checking.md) | `checking c` | правило → дело. Вердикт без побочных эффектов |
| `0x12BL` | [REQUIRES](0x12BL-requires.md) | `f is required` | дело → поле |
| `0x12CL` | [MEANS](0x12CL-means.md) | Definitions `means` | элемент определения → значение или тип |
| `0x12DL` | [HAS](0x12DL-has.md) | Definitions `has` | элемент определения → поле |
| `0x12EL` | [RUNS](0x12EL-runs.md) | точка входа `run c` | точка входа → дело (выполнение) |
| `0x12FL` | [EVALUATES](0x12FL-evaluates.md) | точка входа `check c` | точка входа → дело (вердикт) |
| `0x130L` | [TRIGGERS](0x130L-triggers.md) | триггер `run c` | триггер → дело |
| `0x131L` | [UNTIL](0x131L-until.md) | `every … until c` | триггер → дело |
| `0x132L` | [SAME-AS](0x132L-same-as.md) | | узел → глобальный идентификатор |
| `0x133L` | [IMPORTED-FROM](0x133L-imported-from.md) | `see a from path` | псевдоним → путь (TEXT) |
| `0x134L` | [LABEL](0x134L-label.md) | имя в обратных кавычках | узел → TEXT. Запись имени |

### Раскладка {#레이아웃-1}

```
ID               запись LOCAL Reference (Edge Id)
src              REF
dst              REF. У DO, DO-ONCE, UNDO — FuncRef
flags 1 WORD     b0 F_ONCE, b1 F_GATE, b2 F_STRIKE, b3 F_ORDERED, b4 F_FORCE
[F_GATE]         оператор 1 WORD (старшие 2 бита) + UNSIGNED-DECIMAL Value (проценты)
[F_FORCE]        SIGNED-DECIMAL Value. Сила атаки (0~1). Только у ATTACKS
SPAN             ширина, заданная SOURCE × 2
```

| flag | Значение |
|---|---|
| b0 F_ONCE | выполняется только один раз (`once` у UNDO) |
| b1 F_GATE | есть поле вентиля уверенности |
| b2 F_STRIKE | отношение, вычеркнутое зачёркиванием |
| b3 F_ORDERED | принадлежит нумерованному списку `1.` |
| b4 F_FORCE | есть поле силы атаки. Только у ATTACKS |

| Оператор вентиля | Значение |
|---|---|
| 0 | at least |
| 1 | above |
| 2 | less than |
| 3 | at most |

- Условные поля идут в порядке flag (F_GATE, F_FORCE). Поле с выключенным flag места не занимает.

### Сила атаки {#공격-세기}

Силу атаки (F_FORCE) использует только [ATTACKS](0x108L-attacks.md#공격-세기). Формула вердикта, запись и пример приведены там.

### Интерпретация и действительность {#해석과-유효성-1}

- REF — Edge Id записи этого документа ([TOULMIN](#공통-필드), общие поля).
- Форму dst задаёт Codec. У DO, DO-ONCE, UNDO это FuncRef (REF(ALIAS, 0 если нет) + VerbCode 1 WORD, [NODE](#필드)), у LABEL и IMPORTED-FROM — REF записи TEXT, у остальных — REF узла.
- `do … once` выражается Codec DO-ONCE. F_ONCE в flags у DO-ONCE не используется (если он включён, запись отклоняется). `once` у UNDO записывается через F_ONCE.
- Оператор вентиля — старшие 2 бита WORD оператора, остальные 14 бит равны 0. Проценты — UNSIGNED-DECIMAL Value с `E=0`, значение 0~100.
- Биты b5~b15 в flags Reserved и должны быть 0. Иначе запись отклоняется.
- F_FORCE используется только у ATTACKS. Если он включён у другого Codec (SUPERSEDES, связи выполнения и вердикта, отношения формата TOULMIN), запись отклоняется.
- Если сила атаки не является SIGNED-DECIMAL Value, выходит за 0~1 или не выражается точно четырьмя десятичными знаками, запись отклоняется.
- Цепочка SUPERSEDES `A > B > C` записывается по одному SUPERSEDES на каждую пару.

## Исходный текст и разбиение {#source와-구획}

Записи исходного текста и разбиения документа TOULMIN. Все они — прямые коды `0x120L~0x125L` семейства формата Edge TOULMIN ([формат TOULMIN](#toulmin-형식)). Полей Issuer и номера Codec нет, Payload идёт сразу за TAG.

### Формат {#형식}

| Codec | Имя | Раскладка |
|---|---|---|
| `0x120L` | [SOURCE](0x120L-source.md) | ID, ширина SPAN WORD, UTF8 Value |
| `0x121L` | [TEXT](0x121L-text.md) | ID, UTF8 Value |
| `0x122L` | [SECTION](0x122L-section.md) | ID, код раздела 1 WORD |
| `0x123L` | [CASE-BEGIN](0x123L-case-begin.md) | ID, REF (дело) |
| `0x124L` | [CASE-END](0x124L-case-end.md) | ID, REF (дело) |
| `0x125L` | [PROSE](0x125L-prose.md) | ID, SPAN |

- ID — Edge Id, REF — Edge Id записи этого документа ([TOULMIN](#공통-필드), общие поля).
- UTF8 Value — запись [UTF8-TEXT](../value/0x072L-utf8-text.md) Value. Байты хранятся как есть.
