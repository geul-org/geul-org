GEUL (General Encoding Unified Language) — искусственный язык и двоичный формат, позволяющий людям и ИИ обмениваться данными без неоднозначности.

Эти документы определяют грамматику GEUL v1. Текущая редакция — черновик до публикации и может измениться. Спецификация открыта по лицензии [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/).

## Обзор {#한눈에-보기}

- Все данные — последовательность **16-битных слов (WORD)**. Запись ведётся в порядке big-endian.
- Единица данных — **запись**. Запись начинается с одного TAG WORD, и этот TAG WORD задаёт вид и длину записи.
- Записи бывают четырёх видов (**Kind**).

| Kind | Назначение | Пример |
|---|---|---|
| Reference | Указывает на объект | Q42 Викиданных, #7 внутри этого документа |
| Value | Хранит само значение | дата, количество, текст с указанием языка |
| Edge | Связывает другие записи и высказывает утверждение | «Q42 — человек», «английское имя Q42 — Douglas Adams» |
| Meta | Говорит о самом документе | редакция спецификации, ID документа, автор, подпись |

- Записи собраны в один **документ**. Как и HTML, документ делится на HEAD (Meta, а также источник всего документа SOURCE и его QUALIFIER) и BODY (Reference, Value, Edge).
- Документ выпускает **Issuer** (выпускающий субъект), а каждая версия фиксируется хешем содержимого. Опубликованная версия не меняется.

## Принципы проектирования {#설계-원칙}

1. **Пропуск возможен без кодовой книги.** Вид и длина записи заключены в 16 битах TAG WORD. Декодер, не знающий способа интерпретации (кодовой книги), всё равно может подсчитать записи и пропустить их.
2. **Хранится высказывание, а не факт.** Документ фиксирует вместе с Meta и Edge основания, кто, когда и из чего это высказал.
3. **Идентификация — через Reference.** Объект указывается по ID, а не по имени. Имя присоединяется через Edge.
4. **Опубликованное не меняется.** Исправления выходят в новой версии. ID внутри документа указывает на один и тот же объект во всех версиях.
5. **Пространство оставляется свободным.** Большая часть битового пространства оставлена на будущее. Прямые коды нельзя отозвать, поэтому назначаются только те, чья частота использования подтверждена.

## Что известно без кодовой книги {#코덱북-없이-알-수-있는-것}

| Информация | Без кодовой книги | Основание |
|---|---|---|
| Kind | известно | диапазон раздела `w >> 9` в TAG WORD (Reference 0–2, Value 3 и 4, Edge 5–13, Meta 14 и 15) |
| Полная длина записи, положение следующей записи | известно | Length в TAG WORD |
| Номер Codec | известно | TAG WORD (в формате Issuer — Issuer и номер Codec из расширяющего TAG) |
| Семейство, класс | частично известно | По битам известно только семейство прямых кодов Edge. Прямые коды Value, семейство формата Issuer и класс Meta по битам неизвестны. В формате Issuer известны Issuer и номер Codec. Класс проверки Meta определяется по `C >= 5` раздела 15 (`w >= 0x1E50`) |
| Edge Id у Edge | известно | первый компонент Edge (разделы 5–13) — всегда LOCAL Reference |
| Маркер места (не записано, неизвестно, отсутствует) | известно | значение WORD `0x0000`, `0x0010`, `0x0020` (Reference, C < 3, L 0). См. [Маркер места](slot-marker.md) |
| Quantifier | известно | смещение `C` внутри раздела: для раздела 0 при `5 <= C < 30`, для раздела 1 при `C < 30` это `C % 5` |
| Длина TAG по Codec, начало Payload | неизвестно | кодовая книга |
| Интерпретация Payload, роли компонентов Edge | неизвестно | кодовая книга |

- Декодер без кодовой книги может, пропуская записи, считать их по Kind и Codec, но не может проследовать по структуре графа.
- Все декодеры обязаны обрабатывать классы Meta: структуру, объявление и IMPORT. Эти Codec входят в базовую кодовую книгу GEUL, и декодер знает их по встроенной таблице номеров ([Meta](meta/_index.md)).

Кодовая книга публикуется как документ GEUL ([Документ спецификации Codec](codec-spec.md)). Поэтому декодеру достаточно получить и прочитать нужный документ спецификации.

## Структура областей {#영역-구조}

Старшие биты TAG WORD делят пространство на области.

| Prefix | Область | Доля | Определение |
|---|---|---|---|
| `1` | далёкое будущее | 50% | Reserved (далёкое будущее). Не используется |
| `01` | будущее | 25% | Reserved (ближайшее будущее). Не используется |
| `001` | стандарт | 12.5% | грамматика, официально принятая и применяемая |
| `000` | свободная и предлагаемая | 12.5% | текущая грамматика. При принятии раскладка сохраняется, меняется только Prefix на `001` |

Вся текущая грамматика находится в области `000`. Все TAG WORD этой спецификации начинаются с `000`.

- Декодер v1 отклоняет TAG WORD, у которого Prefix не `000`. Остальные области определит более поздняя редакция.
- Область `000` — пространство предложений. Сейчас регистрация и защита к ней не применяются.
