GEUL (General Encoding Unified Language) — искусственный язык и бинарный формат, на котором люди и ИИ обмениваются данными без неоднозначности. Этот документ определяет грамматику GEUL v1.

## Коротко

- Все данные — последовательность **16-битных слов (WORD)**. Записываются в порядке big-endian.
- Единица данных — **запись**. Запись начинается с одного TAG WORD, который задаёт вид и длину записи.
- Записей четыре вида (**Kind**).

| Kind | Что делает | Пример |
|---|---|---|
| Reference | Указывает на объект | Q42 в Викиданных, #7 внутри этого документа |
| Value | Хранит само значение | дата, количество, текст с указанием языка |
| Edge | Связывает другие записи в одно утверждение | «Q42 — человек», «английское имя Q42 — Douglas Adams» |
| Meta | Говорит о самом документе | версия спецификации, ID документа, автор, подпись |

- Записи собраны в одном **документе**. Как и HTML, документ делится на HEAD (Meta, а также источник всего документа SOURCE и его QUALIFIER) и BODY (Reference, Value, Edge).
- Документ выпускает **Issuer** (издатель); каждая версия фиксируется хешем содержимого. Опубликованная версия не меняется.

## Принципы проектирования

1. **Пропускать записи можно без кодекбука.** Вид и длина записи лежат в 16 битах TAG WORD. Декодер, не знающий способа интерпретации (кодекбука), всё равно может считать записи и пропускать их.
2. **Хранится описание, а не факт.** Документ вместе с Meta и Edge-обоснованием записывает, кто, когда и из чего получил это описание.
3. **Идентификация идёт через Reference.** На объект указывают по ID, а не по имени. Имя присоединяется через Edge.
4. **Опубликованное не меняется.** Исправления выходят новой версией. ID внутри документа указывает на один и тот же объект во всех версиях.
5. **Место оставляется свободным.** Большая часть битового пространства оставлена на будущее. Прямые коды нельзя забрать обратно, поэтому им назначают только форматы с подтверждённой частотой.

## Структура областей

Старшие биты TAG WORD делят пространство на области.

| Prefix | Область | Доля | Определение |
|---|---|---|---|
| `1` | Далёкое будущее | 50% | Резерв на далёкое будущее. Не используется |
| `01` | Будущее | 25% | Резерв на ближайшее будущее. Не используется |
| `001` | Стандарт | 12,5% | Грамматика, официально принятая и действующая |
| `000` | Свободная область и предложения | 12,5% | Текущая грамматика. При принятии раскладка остаётся прежней, меняется только Prefix на `001` |

Вся текущая грамматика находится в области `000`. Каждый TAG WORD этой спецификации начинается с `000`.

- Декодер v1 отклоняет TAG WORD, у которого Prefix не `000`. Остальные области определят следующие версии.
- Область `000` — пространство для предложений. Сейчас регистрация и защита не применяются. Однако раскладка форматов Issuer резервируется в расчёте на систему регистрации после официального запуска стандарта.

## Что известно без кодекбука

| Сведения | Без кодекбука | Основание |
|---|---|---|
| Kind | Известно | TAG WORD |
| Полная длина записи, положение следующей записи | Известно | Length в TAG WORD |
| Номер Codec | Известно | TAG WORD (для формата Issuer — Issuer и номер формата в расширенном TAG) |
| Семейство, класс | Известно | Старшие биты номера Codec или номера формата |
| Edge Id у Edge | Известно | Первый компонент Edge — всегда LOCAL Reference |
| Маркер места (не записано, неизвестно, нет) | Известно | Значение WORD `0`–`7` (Reference Codec `0000`, 1 WORD). [Маркер места](/ru/grammar/reference/slot-marker/) |
| Длина TAG для конкретного Codec, начало Payload | Неизвестно | Кодекбук |
| Интерпретация Payload, роли компонентов Edge | Неизвестно | Кодекбук |

- Декодер без кодекбука может пропускать записи и считать их по Kind и Codec, но не может идти по структуре графа.
- Любой декодер должен обрабатывать классы Meta: структура, определение, IMPORT. Эти Codec входят в ядро кодекбука GEUL ([Meta](/ru/grammar/meta/)).

Кодекбук публикуется как документ GEUL ([Спецификация Codec](/ru/grammar/codec-spec/)). Поэтому декодеру достаточно получить и прочитать нужную спецификацию.

## Открытые вопросы

- Kind для пограничных случаев. Например, утверждение об утверждении: неясно, относить его к Reference, Value, Edge или Meta.
