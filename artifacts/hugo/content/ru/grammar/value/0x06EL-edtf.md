EDTF — Value, хранящий в расширенной строке дат ISO 8601-2 даты с точностью до года или месяца, до нашей эры, неопределённые и интервалы (Codec 0x06EL/0x06FL).

## Члены {#구성원}

Эта страница охватывает два кода чётно-нечётной пары. Чётный код — значение с чётным числом байтов, нечётный — с нечётным ([Запись и TAG WORD](../record.md#가변-길이-바이트열)). Документ Codec один на каждый код. Поля двух документов Codec одинаковы, различаются только цель DECLARE и имя (BIND).

| TAG ID | Имя | Число байтов | Codec ID | Документ спецификации | TAG WORD |
|---|---|---|---|---|---|
| `0x06EL` | `EDTF-EVEN` | чётное | `0x000006E0` | `0x00000000/codecs/0x000006E0/` | `0000 0110 1110 LLLL` |
| `0x06FL` | `EDTF-ODD` | нечётное | `0x000006F0` | `0x00000000/codecs/0x000006F0/` | `0000 0110 1111 LLLL` |

## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD внутри документа — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `bytes` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

EDTF — Value, хранящий дату строкой [Extended Date/Time Format](https://www.loc.gov/standards/datetime/edtf.html) (Библиотека Конгресса США, ISO 8601-2:2019). Он выражает точность грубее дня, до нашей эры, неопределённые, приблизительные и частично неизвестные даты, а также интервалы.

## Раскладка {#레이아웃}

- Код: прямой код Value `0x06EL` (чётное число байтов)·`0x06FL` (нечётное число байтов). Семейство TIME. Payload — строка, но отнесён к семейству TIME.
- Число байтов определяется младшим битом Codec и числом WORD Payload. Оно равно `2 × число WORD Payload − младший бит`, Byte Count не вводится ([Value](_index.md)).

```
TAG WORD          0000 0110 111P LLLL      Codec 0x06EL/0x06FL (P = нечётное число байтов)
[Length-расширяющий TAG] если всего 15 WORD и более
Payload WORD 1st ... Nth          ASCII-байты строки EDTF / при нечётном числе последний 0x00
```

## Интерпретация и действительность {#해석과-유효성}

- Последовательность байтов — ASCII-строка по грамматике EDTF Level 0·1·2. Пустая строка — invalid.
- Примеры: день `1952-03-11`, месяц `1952-03`, год `1952`, десятилетие `195X`, 44-й год до нашей эры `-0043`, неопределённое `1974?`, приблизительное `~1974`, интервал `1952/2001`, большой год `Y-13799999999`.
- Годы астрономические по ISO 8601. `0000` — 1-й год до нашей эры, `-0043` — 44-й год до нашей эры. При переносе из исторической записи год сдвигается на один.
- Календарь — григорианский. EDTF другие календари не рассматривает. Исходная запись в другом календаре, например юлианском, сохраняется как [GEDCOM-DATE](0x070L-gedcom-date.md). Значение, перенесённое в григорианский календарь для того же дня или периода, можно записать как EDTF или GREGORIAN-DATE.
- **Каноническая форма:** дата, которую можно точно записать как [GREGORIAN-DATE](0x06AL-gregorian-date.md), то есть `[-]YYYY-MM-DD` без квалификаторов (`?`, `~`, `%`), неизвестных разрядов (`X`), интервалов и префикса `Y`, записывается как GREGORIAN-DATE. Если такая дата записана как EDTF, это invalid. Индексировать и сравнивать по времени можно, только если один и тот же день записывается в единственном формате.
- schema пока не проверяет грамматику EDTF. Производитель проверяет её парсером EDTF. Например, `parser.ParseString` из `github.com/sfomuseum/go-edtf` (BSD-3-Clause). `parser.IsValid` проверяет только грамматику и пропускает `2023-02-29` и `1974-13`, поэтому не используется. Этот парсер пока не поддерживает годы с префиксом `Y`.

## Длина {#길이}

- Общая длина — число WORD: TAG 1 WORD, Length-расширяющий TAG (если есть) и Payload ([Length](../record.md)).

## Пример {#예시}

| Дата | Байты | Всего WORD |
|---|---|---|
| `1974` | 4 (чётное) | `06E2 3139 3734` |
| `197X` | 4 (чётное) | `06E2 3139 3758` |
| `1952-03` | 7 (нечётное) | `06F4 3139 3532 2D30 3300` |

## Стандартное обоснование {#표준-근거}

- [Library of Congress, Extended Date/Time Format (EDTF) Specification](https://www.loc.gov/standards/datetime/edtf.html). Level 0 — подмножество ISO 8601-1, Level 1·2 — возможности ISO 8601-2.
- В RDF та же строка обозначается типом данных `http://id.loc.gov/datatypes/edtf`.

## Открытые проблемы {#열린-문제}

- Проверка грамматики EDTF валидатором (будет ли валидатор полагаться на внешнюю библиотеку).
- Правило переноса точности Викиданных «век» и «тысячелетие» в неизвестные разряды EDTF.

## Исходный текст документа спецификации {#규격-문서-원문}

Так выглядит документ спецификации `0x00000000/codecs/0x000006E0/latest.geul`, прочитанный командой `geul show` (16-ричные цифры в верхнем регистре).

```
SPEC-VERSION 0x0001
DOC-ID 0x042600000000000006E000000000
BODY
#1 DECLARE 0x06E0
#2 FIELD #1 rest
#3 BIND #1 "EDTF-EVEN"
#4 BIND #2 "bytes"
```

Выше приведён документ Codec для `EDTF-EVEN` (`0x06EL`). У документа Codec другого члена (`EDTF-ODD`) различаются только Codec ID в DOC-ID, цель DECLARE и имя (BIND), связанное с `#1`.
