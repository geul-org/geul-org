## Участники {#구성원}

Эта страница охватывает пару кодов «чётный/нечётный». У чётного кода число байтов чётное, у нечётного — нечётное ([запись и TAG WORD](../record.md#가변-길이-바이트열)). Документ Codec заведён на каждый код. Поля в двух документах Codec совпадают, различаются только цель DECLARE и имя (BIND).

| TAG ID | Имя | Число байтов | Codec ID | Документ спецификации | TAG WORD |
|---|---|---|---|---|---|
| `0x074L` | `URI-EVEN` | чётное | `0x00000740` | `0x00000000/codecs/0x00000740/` | `0000 0111 0100 LLLL` |
| `0x075L` | `URI-ODD` | нечётное | `0x00000750` | `0x00000000/codecs/0x00000750/` | `0000 0111 0101 LLLL` |

## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

URI — Value, хранящий ASCII-последовательность байтов по грамматике RFC 3986 `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]`. Поскольку scheme включена, для интерпретации base URI не нужен.

## Раскладка {#레이아웃}

- Код: прямой код Value `0x074L` (чётное число байтов) и `0x075L` (нечётное число байтов). Семейство TEXT.
- Число байтов определяется младшим битом Codec и числом Payload WORD: `2 × число Payload WORD − младший бит`. Byte Count не вводится ([Value](_index.md)).

```
TAG WORD          0000 0111 010P LLLL      Codec 0x074L/0x075L
[расширяющий Length TAG] если всего 15 WORD и более
Payload WORD 1st ... Nth          URI bytes / final zero padding
```

## Интерпретация и действительность {#해석과-유효성}

- Последовательность байтов должна соответствовать грамматике RFC 3986 `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]`. Допускаются query и fragment.
- Терминалы грамматики URI — символы US-ASCII. Допустимые ASCII-символы хранятся как есть, а при percent-кодировании octet используется форма `pct-encoded = "%" HEXDIG HEXDIG`. Не-ASCII символы нельзя вставлять напрямую как literal byte.
- `scheme` и `:` обязательны. Для относительных ссылок используется [URI-RELATIVE-REF](ietf.geul.org/uri-relative-ref.md) (номера Codec IETF `0x00008000`·`0x00008001`).
- Production URI из RFC 3986 не допускает пустой строки. Запись в 0 byte недействительна.
- Внутри WORD старший byte идёт первым. Если число байтов нечётное (нечётный код), неиспользуемый младший byte последнего WORD должен быть `00`.
- Число Payload WORD равно `ceil(число байтов/2)`. Если код нечётный, а младший byte последнего WORD не равен `00`, значение отвергается.

## Основание в стандартах {#표준-근거}

- `URI`, символы URI и грамматика percent-кодирования соответствуют [RFC 3986, Uniform Resource Identifier (URI): Generic Syntax](https://www.rfc-editor.org/rfc/rfc3986).
- Пара кодов «чётный/нечётный», zero padding, GEUL TAG/Length и раскладка по 16-битным WORD — правила обрамления (framing) этого формата.

## Длина {#길이}

- Всего — число WORD: 1 WORD TAG, расширяющий Length TAG (если есть) и Payload. До 14 WORD используется прямая длина, от 15 WORD — расширенная длина `1110`·`1111`; расширяющий TAG также входит в общее число ([Length](../record.md)).

## Пример {#예시}

- `https://example.com/` — ASCII, 20 byte (чётное), поэтому `URI-EVEN` (`0x074L`).
- Payload — 10 WORD: `6874 7470 733A 2F2F 6578 616D 706C 652E 636F 6D2F`.
- TAG 1 WORD и Payload 10 WORD дают всего 11 WORD, поэтому `LLLL=1010`. Целиком: `074A 6874 7470 733A 2F2F 6578 616D 706C 652E 636F 6D2F`.

## GEUL Archive URI {#geul-archive-uri}

`archive.geul.org` задуман как хранилище неизменяемого содержимого, на которое GEUL ссылается для крупного внешнего содержимого — бинарных данных и документов; пока он не работает. Рекомендуемая форма адреса — `https://archive.geul.org/sha256/{digest}`. Одинаковая последовательность байтов должна иметь один и тот же URI, а после публикации байты по этому URI изменять нельзя.

Value URI лишь указывает расположение или строку адреса внешнего содержимого и не гарантирует ни тождественности, ни неизменности самого объекта. Бинарные данные и текст, выходящие за максимальный предел встроенного Value, можно адресовать через archive URI. В метаданных объекта хранилища нужно записывать следующее.

- Исходный URI и время получения
- SHA-256 и Byte Length
- MIME type
- license identifier и version
- Автор, источник и уведомления
- URI основания лицензии и, при необходимости, копия основания на момент получения

Возможность сбора определяется не тем, что доступ бесплатный, а тем, что право на распространение подтверждено явно. Следует соблюдать применимые условия лицензии: указание авторства, некоммерческое использование, запрет изменений, распространение на тех же условиях и др. В документах и содержимом записывается явная лицензия вроде Creative Commons, а для программного обеспечения по возможности используется SPDX License ID.

Даже если предоставление прекращено из-за правовой проблемы или исправления, в существующий URI нельзя помещать другие байты. Этот URI должен возвращать tombstone с причиной и временем прекращения, а исходный digest и журнал аудита должны сохраняться. Однако если юридическая обязанность запрещает хранить журнал аудита, приоритет у этой обязанности.

archive URI даёт и место доступа, и digest содержимого. Это правило content-address и неизменяемости — политика профиля GEUL Archive, а общая грамматика Value URI от `archive.geul.org` не зависит.

## Исходный текст документа спецификации {#규격-문서-원문}

Так выглядит документ спецификации `0x00000000/codecs/0x00000740/latest.geul`, прочитанный командой `geul show` (шестнадцатеричные цифры заглавные).

```
SPEC-VERSION 0x0001
DOC-ID 0x0426000000000000074000000000
BODY
#1 DECLARE 0x0740
#2 FIELD #1 rest
#3 BIND #1 "URI-EVEN"
#4 BIND #2 "bytes"
```

Выше — документ Codec для `URI-EVEN` (`0x074L`). В документах Codec других участников (`URI-ODD`) различаются только Codec ID в DOC-ID, цель DECLARE и имя, привязанное в `#1` (BIND).
