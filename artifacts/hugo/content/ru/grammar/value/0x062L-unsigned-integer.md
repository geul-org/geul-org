## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD внутри документа — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `magnitude` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

UNSIGNED-INTEGER — Value, представляющий беззнаковое целое число. Прямой код Value `0x062L`, семейство NUMERIC. Весь Payload читается как unsigned magnitude произвольной точности с порядком WORD big-endian. Payload занимает минимум 1 WORD, и допускается только каноническое представление минимальной длины в WORD.

## Раскладка {#레이아웃}

```
TAG WORD          0000 0110 0010 LLLL      Codec 0x062L
[Length-расширяющий TAG] если всего 15 WORD и более
Payload WORD 1st  (старшее WORD)   Unsigned Magnitude 1st
...
Payload WORD Nth  (младшее WORD)   Unsigned Magnitude Nth
```

## Интерпретация {#해석}

- Первое WORD Payload — самый старший разряд, последнее WORD — самый младший.
- Если Payload состоит из N WORD, он читается как единый `16N`-битный unsigned magnitude.
- Эта ширина — не объявленная ширина хранения, и descriptor битовой ширины отсутствует.

## Каноническое представление {#정규-표현}

- 0 — это Payload из 1 WORD `0000`.
- Если Payload состоит из 2 WORD и более, а первое WORD равно `0000`, представление неканонично, так как значение не изменится после его удаления.
- Декодер обязан отвергать представление с лишними ведущими нулевыми WORD.

## Длина {#길이}

- Общая длина — число WORD: TAG 1 WORD, Length-расширяющий TAG (если есть) и Payload. До 14 WORD используется прямая длина, от 15 WORD — расширенная длина `1110`·`1111`, и расширяющий TAG тоже входит в общее число ([Запись и TAG WORD](../record.md)).
- Объявленная ширина вроде UINT8·UINT16·UINT32 не сохраняется, сохраняется только числовое значение.

## Пример {#예시}

| Значение | Payload WORD | Вердикт |
|---:|---|---|
| 0 | `0000` | канонично |
| 1 | `0001` | канонично |
| 65535 | `FFFF` | канонично |
| 65536 | `0001 0000` | канонично |
| 1 | `0000 0001` | неканонично: лишнее ведущее `0000` |
| Payload из 7 WORD | 7 WORD после TAG `0627` (прямая длина `LLLL=0111`, всего 8 WORD) | канонично |
| Payload из 7 WORD | 7 WORD после Length-расширяющего TAG и расширенного значения `0009` | неканонично: до 14 WORD используется прямая длина |

## Статус формата {#형식-지위}

- Это представление, нормализующее unsigned magnitude произвольной точности в последовательность 16-битных WORD минимальной длины и объединяющее её с TAG GEUL, — собственный scalar profile GEUL.
- При обмене с внешними типами фиксированной ширины, такими как UINT8/16/32/64, требуются проверка диапазона и явное преобразование ширины.
