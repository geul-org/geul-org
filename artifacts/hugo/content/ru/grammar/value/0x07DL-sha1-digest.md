## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `digest` | #2 | простое значение, 10 WORD |  |  |

SHA1-DIGEST — Value фиксированной ширины, хранящий результат SHA-1 целиком. Прямой код Value `0x07DL`, семейство BINARY. Payload — ровно 10 WORD (160 бит), усечение (truncation) не допускается.

**Используется только для идентификации.** Устойчивость SHA-1 к коллизиям нарушена (SHAttered, 2017). В качестве основания целостности и подписи используется [SHA-256-DIGEST](0x07CL-sha-256-digest.md). Этот формат введён, чтобы хранить как есть идентификаторы, уже определённые через SHA-1, прежде всего ID объектов (ID коммитов) репозиториев git на SHA-1. Например, Version (ID коммита) в [TRANSFORMED-BY](../meta/0x1D4L-transformed-by.md) хранится в 11 WORD вместо hex-текста (22 WORD).

## Раскладка {#레이아웃}

```
TAG WORD          0x07DA (0000 0111 1101 1010)  LLLL=1010
Payload           10 WORD  SHA-1 Digest
```

## Интерпретация и действительность {#해석과-유효성}

- 20 octet Payload читаются в том порядке, в каком их выдаёт SHA-1. В каждом WORD первым идёт старший octet (то же обрамление, что у SHA-256-DIGEST).
- Если Payload не равен 10 WORD или результат произвольно усечён (сокращённый ID git и т. п.), значение отвергается. Descriptor и padding нет.
- ID объекта git — это значение в точности так, как его вычислил git. SHA-1 в git — вариант с обнаружением коллизий (SHA-1DC), но на входах, не являющихся коллизионной атакой, результат совпадает с SHA-1.

## Основание в стандартах {#표준-근거}

- Алгоритм SHA-1 и 160-битный результат соответствуют NIST [FIPS 180-4, Secure Hash Standard (SHS)](https://csrc.nist.gov/pubs/fips/180-4/final).
- GEUL TAG и обрамление 16-битными WORD — правила, которые добавляет этот формат.

## Длина {#길이}

- Всего — ровно 11 WORD: TAG 1 WORD и Payload 10 WORD; используется `LLLL=1010`. Расширения Length нет.

## Пример {#예시}

Коммит git `ddc0719974a32aaa7b422ee84221a9721085ce4c`:

```
07DA DDC0 7199 74A3 2AAA 7B42 2EE8 4221 A972 1085 CE4C
```
