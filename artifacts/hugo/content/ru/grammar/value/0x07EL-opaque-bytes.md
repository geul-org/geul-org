OPAQUE-BYTES — произвольная последовательность байтов, смысл и формат которой этот формат сам не определяет. Прямой код Value `0x07EL` (чётное число байтов) и `0x07FL` (нечётное число байтов), семейство BINARY. Число байтов определяется младшим битом Codec и числом Payload WORD: `2 × число Payload WORD − младший бит`. Byte Count не вводится ([Value](_index.md)).

## Участники {#구성원}

Эта страница охватывает пару кодов «чётный/нечётный». У чётного кода число байтов чётное, у нечётного — нечётное ([запись и TAG WORD](../record.md#가변-길이-바이트열)). Документ Codec заведён на каждый код. Поля в двух документах Codec совпадают, различаются только цель DECLARE и имя (BIND).

| TAG ID | Имя | Число байтов | Codec ID | Документ спецификации | TAG WORD |
|---|---|---|---|---|---|
| `0x07EL` | `OPAQUE-BYTES-EVEN` | чётное | `0x000007E0` | `0x00000000/codecs/0x000007E0/` | `0000 0111 1110 LLLL` |
| `0x07FL` | `OPAQUE-BYTES-ODD` | нечётное | `0x000007F0` | `0x00000000/codecs/0x000007F0/` | `0000 0111 1111 LLLL` |

## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD в документе — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `bytes` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

## Раскладка {#레이아웃}

```
TAG WORD          0000 0111 111P LLLL      Codec 0x07EL/0x07FL
[расширяющий Length TAG] если всего 15 WORD и более
Payload WORD 1st ... Nth   байты / последний zero padding
```

## Интерпретация и действительность {#해석과-유효성}

- Из Payload по порядку читается столько byte, сколько указано числом байтов. Внутри WORD старший byte идёт первым.
- Число Payload WORD равно `ceil(число байтов/2)`. Если код нечётный, а младший byte последнего WORD не равен `00`, значение отвергается.
- Если чётный или нечётный код, число Payload WORD и zero padding не согласуются друг с другом, значение отвергается.

## Статус формата {#형식-지위}

- Пара кодов «чётный/нечётный» (`0x07EL` чётный, `0x07FL` нечётный), размещение payload и zero padding в последнем WORD — не ссылка на внешний отраслевой стандарт, а собственное обрамление (framing) GEUL.

## Длина {#길이}

- Всего — число WORD: 1 WORD TAG, расширяющий Length TAG (если есть) и Payload. До 14 WORD используется прямая длина, от 15 WORD — расширенная длина `1110`·`1111`; расширяющий TAG также входит в общее число ([запись и TAG WORD](../record.md)).
- 0 byte записывается как запись в 1 WORD с чётным кодом (`0x07EL`) (только TAG WORD) ([Value](_index.md)).

## Пример {#예시}

byte `AB CD EF` — 3 byte (нечётное), поэтому `OPAQUE-BYTES-ODD` (`0x07FL`), Payload `ABCD EF00`. Всего 3 WORD, поэтому `LLLL=0010`.

```
07F2 ABCD EF00
```

Пустая последовательность байтов — 1 WORD `07E0` (`OPAQUE-BYTES-EVEN`, только TAG WORD).

## Исходный текст документа спецификации {#규격-문서-원문}

Так выглядит документ спецификации `0x00000000/codecs/0x000007E0/latest.geul`, прочитанный командой `geul show` (шестнадцатеричные цифры заглавные).

```
SPEC-VERSION 0x0001
DOC-ID 0x042600000000000007E000000000
BODY
#1 DECLARE 0x07E0
#2 FIELD #1 rest
#3 BIND #1 "OPAQUE-BYTES-EVEN"
#4 BIND #2 "bytes"
```

Выше — документ Codec для `OPAQUE-BYTES-EVEN` (`0x07EL`). В документах Codec других участников (`OPAQUE-BYTES-ODD`) различаются только Codec ID в DOC-ID, цель DECLARE и имя, привязанное в `#1` (BIND).
