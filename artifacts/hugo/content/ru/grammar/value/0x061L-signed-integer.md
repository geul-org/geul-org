## Поля (документ спецификации) {#필드-규격-문서}

Порядок FIELD внутри документа — это порядок полей Payload ([документ спецификации Codec](../codec-spec.md)).

| Порядок | Поле (BIND) | FIELD | Ширина | Принимаемый формат (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `integer` | #2 | остаток, простое значение (`0xFFFF`) |  |  |

SIGNED-INTEGER — Value, представляющий знаковое целое число. Прямой код Value `0x061L`, семейство NUMERIC. Весь Payload читается как целое число произвольной точности в дополнительном коде с порядком WORD big-endian. Payload занимает минимум 1 WORD, и допускается только каноническое представление минимальной длины в WORD.

## Раскладка {#레이아웃}

```
TAG WORD          0000 0110 0001 LLLL      Codec 0x061L
[Length-расширяющий TAG] если всего 15 WORD и более
Payload WORD 1st  (старшее WORD)   Integer 1st
...
Payload WORD Nth  (младшее WORD)   Integer Nth
```

## Интерпретация {#해석}

- Старший бит первого WORD Payload — знаковый бит всего целого числа.
- Все WORD Payload читаются как единая непрерывная битовая строка в дополнительном коде. Первое WORD — самый старший разряд, последнее — самый младший.
- Если Payload состоит из N WORD, ширина интерпретации равна `16N` бит. Эта ширина — не объявленная ширина хранения, а ширина представления значения, определяемая каноническим представлением.
- Byte Count и descriptor битовой ширины отсутствуют.

## Каноническое представление {#정규-표현}

- 0 — это Payload из 1 WORD `0000`.
- Ведущие WORD знакового расширения, не меняющие значения, запрещены.
- Если Payload состоит из 2 WORD и более, неканоническими являются следующие случаи.
  - первое WORD равно `0000`, а старший бит следующего WORD равен 0
  - первое WORD равно `FFFF`, а старший бит следующего WORD равен 1
- Ведущее `0000`, сохраняющее знак положительного числа, допускается, когда старший бит следующего WORD равен 1.
- Ведущее `FFFF`, сохраняющее знак отрицательного числа, допускается, когда старший бит следующего WORD равен 0.
- Декодер обязан отвергать неканоническое представление.

## Длина {#길이}

- Общая длина — число WORD: TAG 1 WORD, Length-расширяющий TAG (если есть) и Payload. До 14 WORD используется прямая длина, от 15 WORD — расширенная длина `1110`·`1111`, и расширяющий TAG тоже входит в общее число ([Запись и TAG WORD](../record.md)).
- Объявленная ширина вроде INT8·INT16·INT32 не сохраняется, сохраняется только числовое значение. Значения от `-32768` до `32767` занимают 1 WORD, а при выходе за этот диапазон добавляется столько WORD, сколько нужно. Отдельного формата SIGNED-INT8 нет.

## Пример {#예시}

| Значение | Payload WORD | Вердикт |
|---:|---|---|
| 0 | `0000` | канонично |
| 1 | `0001` | канонично |
| 32767 | `7FFF` | канонично |
| 32768 | `0000 8000` | канонично: для сохранения знака положительного числа нужно `0000` |
| -1 | `FFFF` | канонично |
| -32768 | `8000` | канонично |
| -32769 | `FFFF 7FFF` | канонично: для сохранения знака отрицательного числа нужно `FFFF` |
| 1 | `0000 0001` | неканонично: лишнее ведущее `0000` |
| -1 | `FFFF FFFF` | неканонично: лишнее ведущее `FFFF` |

## Статус формата {#형식-지위}

- Дополнительный код — широко распространённое соглашение, но это представление, нормализующее значение произвольной точности в последовательность 16-битных WORD минимальной длины и объединяющее её с TAG GEUL, — собственный scalar profile GEUL.
- При обмене с внешними типами фиксированной ширины, такими как INT8/16/32/64, требуются проверка диапазона и явное преобразование ширины.
