لا تجمع GEUL نظام التعريف في مكان واحد. يعرّف كل Issuer الأهداف والصيغ، وتستعير المستندات الأخرى التعريفات المنشورة. وتُكتب التعريفات سريةً، أو تُنشر على geul.org (CC0)، أو تُنشر نشراً خاصاً (برخصة يحددها Issuer). وللمستخدم أن يقرر أي تعريف يثق به ويستعمله.

يحدد [عنوان النشر وقائمة الإصدارات](/ar/grammar/publishing/) عنوان النشر وتحديد الصيغة وفهرس الأسماء وقائمة الإصدارات وطبقات الثقة.

## ما يعرّفه Issuer

| الهدف | الطريقة |
|---|---|
| الأهداف (الكيانات والمفاهيم والمصطلحات) | تُعلن بـ LOCAL في مستنده |
| صيغ Value | تُعرَّف برقم صيغة تحت كود Issuer |
| صيغ Edge | تُعرَّف برقم صيغة تحت كود Issuer |

- تعريفات صيغ Value وEdge تُنشر أيضاً مستندات.

## المبادئ

- كل المعرّفات نطاقها المستند. LOCAL ID (ومنه Edge Id والمتغيرات) وIMPORT ID لا تصح إلا داخل ذلك المستند.
- الهدف الذي يعرّفه Issuer هو LOCAL في المستند الذي ينشره ذلك Issuer. وتقتبسه المستندات الأخرى مباشرة بتصريح إشاري (`EXTERNAL-ISSUER-*`)، أو تستورده بـ `IMPORT-DOC` وتشير إليه بـ `EXTERNAL-POINTER-*`.
- الهدف الذي يجب الإشارة إليه من خارج المستند يُصدَر له LOCAL في مستند منشور. ويجب أن يكون في ذلك المستند [DOC-ID](/ar/grammar/meta/declaration/doc-id/).

## مستويات Issuer

| العرض | نطاق القيم | الإصدار |
|---|---|---|
| 1 WORD | `0x0000`~`0xFFFF` | تخصصه geul.org لهيئات وضع المعايير والمؤسسات الكبرى ([جدول تخصيص 1 WORD](#جدول-تخصيص-1-word)) |
| 2 WORD | `0x00010000`~`0xFFFFFFFF` | تسجيل في geul.org. يمر بإثبات ملكية النطاق |
| 4 WORD | `2^32`~`2^64−1` | تسجيل في geul.org. بلا إثبات ملكية |
| 16 WORD | `2^64` فأكثر | إصدار ذاتي. يُحسب من المفتاح العام |

- **معرّف Issuer قيمة عددية.** إذا تساوت القيمتان فهما Issuer واحد (`0x0001` و`0x00000001` قيمة واحدة). والعرض ليس جزءاً من المعرّف.
- **الصيغة القانونية هي أقصر عرض.** يُكتب بأقصر عرض تتسع له القيمة، ويُرفض التمثيل بعرض أوسع. لذلك يبدأ تخصيص كل عرض من القيمة التي يلي نهاية نطاق العرض الأضيق منه (يبدأ 2 WORD من `0x00010000`).

## جدول تخصيص 1 WORD

تخصص geul.org Issuer ذا 1 WORD لهيئات وضع المعايير والمؤسسات الكبرى. وتوضع الصيغ الخاصة التي صممتها GEUL تحت `GEUL`، وتوضع المعايير الواقعية أو الصيغ العرفية التي ليس لها هيئة واضعة تحت `ADHOC`.

| `0x0002`~`0x000F` | محجوز | | |
| `0x0010` | ISO | International Organization for Standardization | ISO 8601 وISO 4217 (العملات) وISO 3166 (الدول) |
| `0x0011` | IEC | International Electrotechnical Commission | IEC 80000 (كتابة الوحدات) |
| `0x0012` | ISO-IEC-JTC1 | ISO/IEC Joint Technical Committee 1 | معايير ISO/IEC لتقنية المعلومات |
| `0x0013` | ITU-T | ITU Telecommunication Standardization Sector | X.509 وX.690 (ترميز ASN.1) |
| `0x0014`~`0x001F` | محجوز | هيئات المعايير الدولية | |
| `0x0020` | IETF | Internet Engineering Task Force | URI (RFC 3986) وUUID (RFC 9562) وCRC32C وIPv4 وIPv6 |

| `0x0023` | WHATWG | Web Hypertext Application Technology Working Group | URL وHTML |
| `0x0024` | UNICODE | Unicode Consortium | ترميز المحارف والتطبيع وCLDR |
| `0x0025` | ECMA | Ecma International | JSON (ECMA-404) |
| `0x0026`~`0x003F` | محجوز | هيئات معايير الإنترنت والويب | |
| `0x0040` | IEEE | Institute of Electrical and Electronics Engineers | الفاصلة العائمة وdecimal في IEEE 754، وعنوان MAC (802) |

| `0x0061` | IERS | International Earth Rotation and Reference Systems Service | الثانية الكبيسة وUTC−TAI |
| `0x0062` | NIST | National Institute of Standards and Technology | SHA-2 (FIPS 180-4) وSHA-3 (FIPS 202) |
| `0x0063` | GPS | الجهة الحكومية المشغِّلة لـ GPS | وقت GPS |
| `0x0064`~`0x00FF` | محجوز | هيئات القياس والهيئات الحكومية | |
| `0x0100` | KATS | الوكالة الكورية للتكنولوجيا والمعايير | معايير KS |
| `0x0101`~`0x01FF` | محجوز | هيئات المعايير الوطنية | |
| `0x0200`~`0xFFFF` | محجوز | يُخصَّص لاحقاً | |

- توضع الصيغ الموسعة تحت Issuer الهيئة التي وضعت تلك الصيغة. وأرقام الصيغ تحت Issuer يعرّفها كل Issuer.
- يجب أن تتبع البتات العليا من رقم الصيغة قاعدة العائلة الخاصة بذلك Kind. ليُعرف الصنف دون codebook.
- إذا كانت هيئة المعايير لا تدير أرقام صيغ GEUL بنفسها فإن geul.org تسجّل معايير تلك الهيئة بأرقام نيابة عنها. وتُسجَّل الأرقام مع معرّف وثيقة المعيار.
- يُجرى التخصيص من الأرقام الدنيا ضمن نطاق تصنيف الهيئات. والنطاق للتيسير في التصنيف، وليس على decoder واجب تفسيره.

## 16 WORD Issuer

```
Issuer ID = SHA-256("GEUL-ISSUER-v1" ‖ معرّف خوارزمية التوقيع (2 بايت) ‖ المفتاح العام)
```

- تُكتب النتيجة (32 بايتاً) في 16 WORD من البايت الأعلى.
- يمكن لأي أحد إنشاؤه دون تسجيل. وتُثبَّت الملكية بتوقيع المفتاح الخاص.
- يُعلن المفتاح العام والخوارزمية بـ [ISSUER-KEY](/ar/grammar/meta/verification/issuer-key/) في HEAD المستند. خوارزمية التوقيع `0x0001` هي Ed25519، وما سواها محجوز.
- تمنع البادئة `GEUL-ISSUER-v1` أن يعطي المفتاح نفسه المعرّف نفسه عند استخدامه لغرض آخر (فصل الاستخدامات).
- حتى لو تغيرت خوارزمية التوقيع (مثل Ed25519 → ML-DSA) يبقى عرض المعرّف 16 WORD.
- إذا كانت النتيجة أقل من `2^64` (واحتمالها صفر عملياً) فلا يُنشأ Issuer بذلك المفتاح. لأنه يتعارض مع قاعدة أقصر عرض.

## إثبات النطاق

- إثبات ملكية النطاق لـ Issuer ذي 2 WORD يُتحقق منه وقت التسجيل فقط. وإدارة النطاق بعد ذلك مسؤولية Issuer.
- النطاق الواحد يقابل Issuer واحداً فقط. ويمكن لـ Issuer واحد أن يملك عدة نطاقات. يُكتب التقابل بـ BIND في فهرس أسماء Issuer `issuers.geul` ([عنوان النشر وقائمة الإصدارات](/ar/grammar/publishing/#اسم-issuer)).
- حتى لو انتهى النطاق أو انتقل تبقى المقابلة مع Issuer الذي أثبته أولاً. ولا يستطيع المالك الجديد استخدام ذلك النطاق اسماً لـ Issuer.
- اسم النطاق لإدخال العنوان وعرضه. ولا يُكتب داخل مستند GEUL إلا Issuer ID.

## مستند تعريف المصطلحات

- المصطلحات التي يعرّفها Issuer (الأدوات والبرامج والأدوار والمفاهيم داخل المنظمة) توضع في **مستند واحد لكل مصطلح**. المصطلح هو LOCAL في ذلك المستند، ويُربط اسمه بـ [BIND](/ar/grammar/edge/bind/)، ويُوصل الهدف الخارجي الذي يشير إليه (URI وغيره) بـ [REFERENCE-NODE](/ar/grammar/edge/reference-node/).
- تشير المستندات الأخرى إلى المصطلح بـ `EXTERNAL-ISSUER-*` (Issuer، ومعرّف المستند، وLOCAL ID). ولا يُكرَّر التعريف نفسه في كل مستند. مثال: أداة [TRANSFORMED-BY](/ar/grammar/meta/lineage/transformed-by/).
- نطاق معرّفات مستندات تعريف المصطلحات يحدده Issuer. وتستخدم geul.org (`0x0000`) النطاق `0x0001xxxx xxxxxxxx` ([مستند مواصفة Codec](/ar/grammar/codec-spec/#معرف-المستند-في-geul-issuer)).
- معرّف المستند `0x0000000000000000` في كل Issuer محجوز لـ **مستند فهرس تعريف المصطلحات** الخاص بذلك Issuer: `<Issuer>/0x0000000000000000/`. وهو موضع سرد مستندات تعريف المصطلحات.
- يُوصى بمستند الفهرس لكل Issuer، وليس إلزامياً. فإن لم يوجد فيُبحث عن مستندات تعريف المصطلحات بفهرس الأسماء `documents.geul`.
- ترتيب الإشارة إلى هدف خارجي: (1) إن وُجد Reference Codec مناسب فهو (WIKIDATA-QID وغيره)، (2) إن وُجد مستند GEUL يعرّف ذلك الهدف فهو (DOC-POINTER وEXTERNAL-ISSUER)، (3) وإلا يُعرَّف بـ LOCAL في مستند تعريف المصطلحات الخاص به ويُشار إليه.

## طرق إتاحة المستندات

| الطريقة | لمن | الرخصة | إدارة الإصدارات | البقاء |
|---|---|---|---|---|
| سري | كل Issuer | داخلية لدى Issuer | Issuer | يتوقف على Issuer |
| نشر على geul.org | Issuer ذو 1 WORD أو 2 WORD | CC0 | geul.org | تحفظه geul.org |
| نشر خاص | كل Issuer | يحددها Issuer | Issuer | يتوقف على Issuer |

### النشر على geul.org

- يستطيع Issuer ذو 1 أو 2 WORD تسجيل المستند ونشره على geul.org. والمستند المسجَّل CC0.
  - Issuer ذو 1 WORD ينشر بعد مراجعة مسبقة من geul.org.
  - Issuer ذو 2 WORD ينشر فور التسجيل، وتُعالج المشكلات لاحقاً.
- التعريفات التي يمكن نشرها هي المفاهيم والـ codec. **لا يجوز نشر Reference يشير إلى شخص طبيعي على geul.org.** يكون ذلك سرياً أو نشراً خاصاً.
  - استثناء: يُسمح بالإشارة إلى الأشخاص الطبيعيين بـ [WIKIDATA-QID](/ar/grammar/reference/wikidata-qid/).
- لا يُغيَّر الإصدار المسجَّل ولا يُحذف، وتبقى المستندات وإن زال Issuer (حفظ القانون القديم). والاستثناء هو الحذف القانوني والحذف بحكم السلطة ([TOMBSTONE](/ar/grammar/edge/publication/)).
- لا يستطيع Issuer إلا وضع علامة توصية بالإيقاف (deprecated) على تعريف. والتعريف الموصى بإيقافه يظل يُفسَّر.
- يجوز للإصدار الجديد من المستند نفسه أن ينشئ تعريفات أو يعدّلها أو يحذفها ([المستند](/ar/grammar/document/#المراجعة)). **لا يُعاد استخدام معرّف الكيان المحذوف ورقم الصيغة لهدف آخر.** ولا يُراجَع تخطيط wire لرقم الصيغة.

### النشر الخاص

- يقدّم Issuer الذي يريد النشر برخصة غير CC0 المستندَ على شبكة خاصة (نطاق خاص وغيره). وتُعلن الرخصة بـ [LICENSE](/ar/grammar/meta/policy/license/) في HEAD المستند.
- يستخدم النشر الخاص المسارات نفسها المستخدمة في geul.org ([عنوان النشر وقائمة الإصدارات](/ar/grammar/publishing/)).
- إدارة الإصدارات والإتاحة وصيانة النطاق وشروط الرخصة يحددها Issuer. ولا تتدخل geul.org في النشر الخاص ولا تضمنه.

### السري

- لا تُنشر المستندات السرية. يُفرض عليها التحكم في الوصول وتُعلَّم بـ [ACCESS](/ar/grammar/meta/policy/access/).
- إذا أُرسل خارجاً مستند استخدم تعريفات سرية فإن الطرف المتلقي لا يستطيع تفسير Reference وValue وEdge تلك ويتخطاها. والتعريفات التي تُتبادل مع الخارج تُنشر.

### اختيار المستخدم

- يختار المستخدم المستندات التي يستخدمها بالنظر إلى الرخصة المعلنة وإمكانية بقاء Issuer.
- التعريفات ذات الرخص المفرطة التقييد أو Issuer الذي بقاؤه غير مضمون لا تُستخدم.
- المراجع التي يجب حفظها طويلاً تستخدم مستندات منشورة على geul.org.

## التوقيع

- التوقيع إلزامي في المستند المنشور. يوضع في HEAD بـ [SIGNATURE](/ar/grammar/meta/verification/signature/). المستند الذي لا توقيع له مستند GEUL صحيح أيضاً، ويُوقَّع المستند السري والداخلي كذلك إن أمكن.
- المُوقَّع هو **تجزئة المحتوى** للمستند ([المستند](/ar/grammar/document/#تجزئة-المحتوى)). ولا يُوقَّع BODY وحده.
  - في HEAD قواعد تفسير. فتغيير هدف `IMPORT-DOC` يجعل BODY نفسه يشير إلى هدف آخر.
  - وإن لم يُوقَّع `LICENSE` و`PARENT` أمكن تزوير الرخصة والتاريخ.
- يمكن وضع عدة توقيعات في مستند واحد. وكلها توقّع تجزئة المحتوى نفسها، فلا تتغير تجزئة المحتوى بإضافة توقيع.
- التحقق من مفتاح التوقيع:
  - Issuer ذو 1 أو 2 أو 4 WORD: المفتاح المسجَّل في geul.org (نشر مفاتيح التحقق أدناه).
  - Issuer ذو 16 WORD: `ISSUER-KEY` في المستند نفسه. ويجب أن يساوي Issuer ID المحسوب من ذلك المفتاح العام معرّف الموقِّع.
- يخفّض القارئ الثقة إن لم يوجد توقيع، ويخفّضها أكثر إن وُجد توقيع فشل التحقق منه، لأنه دليل على تلاعب أو انتحال.
- توقيع المستند يضعه Issuer ذلك المستند، وتوقيع قائمة الإصدارات تضعه جهة النشر التي خصصت معرّف الإصدار ([عنوان النشر وقائمة الإصدارات](/ar/grammar/publishing/#جهة-التوقيع)).

## نشر مفاتيح التحقق

- تنشر geul.org مفاتيح التحقق من توقيع Issuer المسجَّلين (1 و2 و4 WORD).
- تصدر قائمة المفاتيح مستنداً منشوراً في GEUL Issuer (`0x0000`). وهو CC0 وتوقّعه geul.org.
  - العناصر: Issuer، ومعرّف خوارزمية التوقيع، والمفتاح العام، ووقت بدء الصلاحية، ووقت الإلغاء وسببه.
- لا تُحذف المفاتيح الملغاة. وتُفحص التوقيعات القديمة بالمفتاح الذي كان صالحاً وقت التوقيع.
- يتم تبديل المفتاح بتوقيع المفتاح الجديد بالمفتاح القديم ثم تسجيله. وللطرف المتحقق أن يتأكد من استمرارية المفتاح دون أن يثق بـ geul.org.
- تُحفظ سجلات تغيير المفاتيح في سجل لا يقبل إلا الإضافة (على نهج Certificate Transparency وGo sumdb). وتعديل التاريخ ينكشف.
- إذا ضاع المفتاح وتعذّر التوقيع بالمفتاح القديم فإن geul.org تعيد التحقق من الهوية وتسجّل مفتاحاً جديداً. ويمر Issuer ذو 2 WORD بإثبات ملكية النطاق من جديد. وفي هذه الحالة يجب الوثوق بـ geul.org، ويُسجَّل السبب في السجل.
- لا ينطبق على Issuer ذي 16 WORD. لأن Issuer ID يُحسب من المفتاح العام فيُتحقق بـ `ISSUER-KEY` داخل المستند وحده.

## الاستيراد

لا يستورد IMPORT إلا المستندات.

```
IMPORT-DOC                      DOC-POINTER(Issuer + معرّف المستند + معرّف الإصدار) + IMPORT ID
EXTERNAL-POINTER-1/2/4/8WORD    IMPORT ID + LOCAL ID
EXTERNAL-ISSUER-1/2/4/16WORD    Issuer + معرّف المستند + LOCAL ID (دون IMPORT)
ISSUER-POINTER                  Issuer (Issuer نفسه)
DOC-POINTER                     Issuer + معرّف المستند + معرّف الإصدار (2 WORD، و0 تعني الأحدث)
```

- يمكن الإشارة إلى Issuer بأي عرض ومستنداته بتصريح إشاري دون IMPORT. `ISSUER-POINTER` لـ Issuer نفسه، وDOC-POINTER للمستند نفسه، وEXTERNAL-ISSUER-* لـ LOCAL في المستند. التصريح الإشاري يتبع أحدث إصدار، ولتثبيت الإصدار يُستخدم `IMPORT-DOC` (معرّف الإصدار) و`EXTERNAL-POINTER-*`.
- يكتب Reference في المتن IMPORT ID + معرّف الهدف فقط بدل المسار الكامل (Issuer + المستند + معرّف الهدف).
- عرض IMPORT ID يتحدد بالطول في `IMPORT-DOC` وبـ Codec في `EXTERNAL-POINTER-*`. ولا يصح إلا داخل ذلك المستند ([IMPORT-DOC](/ar/grammar/meta/import/import-doc/)).
- الاستيراد دون معرّف إصدار يتبع أحدث إصدار. وإذا كُتب معرّف إصدار ثُبّت عليه. والمستند المنشور يكتب معرّف الإصدار.

## الرخصة

- المستندات المنشورة على geul.org ومستندات GEUL Issuer (`0x0000`) هي CC0.
- رخصة مستند النشر الخاص يحددها Issuer. ولا تفرض GEUL شيئاً.
- لا تنسخ مخرجات GEUL الأساسية محتوى مستندات Issuer غير CC0.

## مسائل مفتوحة

- هل يُسمح بنشر Issuer ذي 4 WORD و16 WORD على geul.org.
- طريقة إثبات ملكية النطاق (DNS TXT `_geul.<النطاق>` وHTTP `.well-known`)، وهل تُربط بصمة مفتاح التوقيع بقيمة الإثبات.
- التصدي لاختطاف النطاق عند استرداد المفتاح الضائع. إذا سُجِّل مفتاح جديد بإعادة إثبات النطاق وحده فقد يستولي المختطِف على Issuer. يُنظر في التحقق من جهة الاتصال المسجَّلة، وفترة سماح واعتراض بالمفتاح القديم، وتطبيق نتيجة نزاع النطاق.
- صيغة سجلات مستند فهرس تعريف المصطلحات (معرّف المستند `0`) (Edge الذي يسرد مستندات تعريف المصطلحات).
- القيمة الافتراضية لخوارزمية التوقيع (يوصى بـ Ed25519).
