URI هو Value يحمل بايتات ASCII بنحو URI في RFC 3986 (URI مطلق يتضمن scheme). يستعمل زوج الرمزين الزوجي/الفردي 0x074L/0x075L.

| البند | القيمة |
|---|---|
| الاسم | `URI` (حزمة زوجي/فردي. اسم كل رمز في جدول الأعضاء أدناه) |
| TAG ID | `0x074L`·`0x075L` |
| القسم | 3 `0011` (Value)، الإزاحة C داخل القسم = 20~21 |
| Kind | Value · العائلة: TEXT |
| وصف الفهرس | بايتات ASCII لقاعدة `URI` في RFC 3986. بايتات زوجية·فردية |

## الأعضاء {#구성원}

تتناول هذه الصفحة رمزين من زوج زوجي/فردي معاً. الرمز الزوجي للقيم ذات عدد البايتات الزوجي، والرمز الفردي لذات العدد الفردي ([السجل وTAG WORD](../record.md#가변-길이-바이트열)). مستند الـ Codec واحد لكل رمز. حقول المستندين متطابقة، ولا يختلفان إلا في هدف DECLARE والاسم (BIND).

| TAG ID | الاسم | عدد البايتات | Codec ID | مستند المواصفة | TAG WORD |
|---|---|---|---|---|---|
| `0x074L` | `URI-EVEN` | زوجي | `0x00000740` | `0x00000000/codecs/0x00000740/` | `0000 0111 0100 LLLL` |
| `0x075L` | `URI-ODD` | فردي | `0x00000750` | `0x00000000/codecs/0x00000750/` | `0000 0111 0101 LLLL` |

## الحقول (مستند المواصفة) {#필드-규격-문서}

ترتيب FIELD داخل المستند هو ترتيب حقول Payload ([مستند مواصفة Codec](../codec-spec.md)).

| الترتيب | الحقل (BIND) | FIELD | العرض | الصيغة المستقبِلة (CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `bytes` | #2 | قيمة خام للباقي (`0xFFFF`) |  |  |

URI هو Value يحمل بايتات ASCII بنحو RFC 3986 `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]`. ولأنه يتضمن scheme فلا يحتاج تفسيره إلى base URI.

## التخطيط {#레이아웃}

- الرمز: رمز مباشر لـ Value هو `0x074L` (بايتات زوجية) و`0x075L` (بايتات فردية). العائلة TEXT.
- يُحدَّد عدد البايتات بأدنى بت في Codec وبعدد WORD في Payload. هو `2 × عدد WORD في Payload − أدنى بت`، ولا يوجد Byte Count ([Value](_index.md)).

```
TAG WORD          0000 0111 010P LLLL      Codec 0x074L/0x075L
[Length ممتد TAG] عندما يبلغ المجموع 15 WORD فأكثر
Payload WORD 1st ... Nth          URI bytes / final zero padding
```

## التفسير والصلاحية {#해석과-유효성}

- يجب أن تطابق سلسلة البايتات نحو RFC 3986 `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]`. ويجوز أن تتضمن query وfragment.
- الرموز النهائية (terminal) في نحو URI هي محارف US-ASCII. تُخزَّن محارف ASCII المسموح بها كما هي، وعند ترميز octet بـ percent-encoding تُستعمل الصيغة `pct-encoded = "%" HEXDIG HEXDIG`. ولا يجوز وضع محارف غير ASCII مباشرة كبايتات حرفية.
- يجب أن تتضمن `scheme` و`:`. أما المراجع النسبية فتستعمل [URI-RELATIVE-REF](ietf.geul.org/uri-relative-ref.md) (رقما Codec في IETF هما `0x00008000`·`0x00008001`).
- قاعدة URI في RFC 3986 لا تسمح بسلسلة فارغة. فسجل 0 بايت غير صالح.
- في WORD الواحد يأتي البايت الأعلى أولاً. وإذا كان عدد البايتات فردياً (الرمز الفردي) وجب أن يكون البايت الأدنى غير المستعمل في آخر WORD هو `00`.
- عدد WORD في Payload هو `ceil(عدد البايتات/2)`. يُرفض الرمز الفردي إذا لم يكن البايت الأدنى في آخر WORD هو `00`.

## المرجع المعياري {#표준-근거}

- يتبع `URI` ونحو محارف URI وpercent-encoding المرجع [RFC 3986, Uniform Resource Identifier (URI): Generic Syntax](https://www.rfc-editor.org/rfc/rfc3986).
- زوج الرمزين الزوجي/الفردي وzero padding وترتيب GEUL TAG/Length وWORD ذي 16 بت هي قواعد framing لهذه الصيغة.

## الطول {#길이}

- المجموع هو عدد WORD في TAG واحد، وTAG Length الممتد (إن وُجد)، وPayload. حتى 14 WORD يُستعمل الطول المباشر، ومن 15 WORD فأكثر يُستعمل الطول الممتد `1110`·`1111`، ويدخل TAG الممتد في المجموع ([Length](../record.md)).

## مثال {#예시}

- `https://example.com/` هو 20 بايت ASCII (زوجي) فهو `URI-EVEN` (`0x074L`).
- Payload هو 10 WORD: `6874 7470 733A 2F2F 6578 616D 706C 652E 636F 6D2F`.
- TAG بـ 1 WORD مع Payload بـ 10 WORD يعطي مجموعاً من 11 WORD فـ `LLLL=1010`. فالكل `074A 6874 7470 733A 2F2F 6578 616D 706C 652E 636F 6D2F`.

## GEUL Archive URI {#geul-archive-uri}

`archive.geul.org` مستودع محتوى ثابت لا يتغير، تصوَّر ليُحال منه في GEUL إلى المحتويات الكبيرة كالملفات الثنائية والمستندات الخارجية، ولم يبدأ تشغيله بعد. صيغة العنوان الموصى بها هي `https://archive.geul.org/sha256/{digest}`. يجب أن يكون لسلسلة البايتات نفسها URI نفسه، ولا يجوز بعد النشر تغيير بايتات URI نفسه.

Value من نوع URI يدل على موقع المحتوى الخارجي أو سلسلة عنوانه فحسب، ولا يضمن تطابق الهدف نفسه ولا ثباته. يمكن الإحالة بـ archive URI إلى الملفات الثنائية والنصوص التي تتجاوز أقصى مدى لـ Value المضمَّن. ويجب أن تسجل بيانات تعريف الكائن المخزَّن البنود التالية.

- URI الأصلي ووقت الجمع
- SHA-256 وByte Length
- MIME type
- معرّف الترخيص وإصداره
- المؤلف والمصدر والإشعارات
- URI سند الترخيص، ونسخة من السند وقت الجمع إن لزم

يُحكم على إمكان الجمع بتأكيد صريح لإذن إعادة التوزيع، لا بإمكان الوصول المجاني. ويجب الالتزام بشروط الترخيص المنطبقة كذكر المؤلف وعدم التجارية وعدم التعديل ومشاركة المثل. تُسجَّل في المستندات والمحتويات تراخيص صريحة كـ Creative Commons، وللبرمجيات يُستعمل SPDX License ID متى أمكن.

وحتى لو توقف التقديم لمسألة حقوق أو تصحيح فلا يجوز وضع بايتات مختلفة في URI قائم. يعيد ذلك URI حجر قبر (tombstone) يتضمن سبب التوقف ووقته، ويجب حفظ digest الأصلي وسجل التدقيق. غير أنه إذا منع التزام قانوني حفظ سجل التدقيق فللالتزام الأولوية.

يوفر archive URI موقع الوصول وdigest المحتوى معاً. وقاعدة content-address والثبات هذه سياسة ملف GEUL Archive، ولا يرتبط النحو العام لـ Value من نوع URI بـ `archive.geul.org`.

## نص مستند المواصفة {#규격-문서-원문}

هذا مستند المواصفة `0x00000000/codecs/0x00000740/latest.geul` كما يُقرأ بـ `geul show` (الأرقام السداسية عشرية بأحرف كبيرة).

```
SPEC-VERSION 0x0001
DOC-ID 0x0426000000000000074000000000
BODY
#1 DECLARE 0x0740
#2 FIELD #1 rest
#3 BIND #1 "URI-EVEN"
#4 BIND #2 "bytes"
```

ما سبق مستند Codec للرمز `URI-EVEN` (`0x074L`). أما مستند Codec للعضو الآخر (`URI-ODD`) فلا يختلف إلا في Codec ID داخل DOC-ID، وهدف DECLARE، والاسم المربوط في `#1` (BIND).
