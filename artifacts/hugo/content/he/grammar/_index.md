GEUL (General Encoding Unified Language) היא שפה מלאכותית ופורמט בינארי שנועדו להחלפת מידע בין בני אדם ל-AI ללא עמימות.

המסמכים האלה מגדירים את הדקדוק של GEUL v1. הגרסה הנוכחית היא טיוטה שטרם פורסמה, והיא עשויה להשתנות. המפרט מפורסם תחת [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/).

## במבט אחד {#한눈에-보기}

- כל הנתונים הם רצף של **WORD בן 16 ביט**. הכתיבה היא ב-big endian.
- יחידת הנתונים היא **רשומה**. רשומה מתחילה ב-TAG WORD אחד, וה-TAG WORD קובע את סוג הרשומה ואת אורכה.
- יש ארבעה סוגי רשומות (**Kind**).

| Kind | תפקיד | דוגמה |
|---|---|---|
| Reference | מצביע על יעד | Q42 ב-Wikidata, #7 בתוך המסמך הזה |
| Value | מכיל את הערך עצמו | תאריך, כמות, טקסט עם שפה |
| Edge | קושר רשומות אחרות ומתאר | "Q42 הוא אדם", "השם האנגלי של Q42 הוא Douglas Adams" |
| Meta | מדבר על המסמך | גרסת המפרט, ID של המסמך, מחבר, חתימה |

- הרשומות נכללות במסמך **אחד**. כמו ב-HTML, המסמך מתחלק ל-HEAD (Meta, וכן SOURCE, המקור של המסמך כולו, וה-QUALIFIER שלו) ול-BODY (Reference, Value, Edge).
- המסמך מונפק על ידי **Issuer** (הגורם המנפיק), וכל גרסה שלו מקובעת בעזרת hash תוכן. גרסה שפורסמה אינה משתנה.

## עקרונות התכנון {#설계-원칙}

1. **אפשר לדלג בלי ספר Codec.** סוג הרשומה ואורכה נמצאים ב-16 הביטים של ה-TAG WORD. גם מפענח שאינו מכיר את דרך הפירוש (ספר ה-Codec) יכול למנות רשומות ולדלג עליהן.
2. **מתעדים היגד, לא עובדה.** המסמך רושם ב-Meta וב-Edge של ראיות מי אמר את ההיגד, מתי, ומאיפה הוא נובע.
3. **הזיהוי נעשה ב-Reference.** מצביעים באמצעות ID ולא באמצעות שם. השם מצורף באמצעות Edge.
4. **מה שפורסם אינו משתנה.** תיקונים יוצאים כגרסה חדשה. ID בתוך מסמך מצביע על אותו יעד לאורך הגרסאות.
5. **משאירים ריק.** רוב מרחב הביטים נשמר לעתיד. קוד ישיר אינו ניתן לשחזור, ולכן מקצים רק את מה שתדירותו אומתה.

## מה אפשר לדעת בלי ספר Codec {#코덱북-없이-알-수-있는-것}

| מידע | בלי ספר Codec | בסיס |
|---|---|---|
| Kind | יודעים | טווח הקטע `w >> 9` של ה-TAG WORD (Reference 0~2, Value 3·4, Edge 5~13, Meta 14·15) |
| האורך הכולל של הרשומה, מיקום הרשומה הבאה | יודעים | Length ב-TAG WORD |
| מספר Codec | יודעים | ה-TAG WORD (בפורמט Issuer, ה-Issuer ומספר ה-Codec שב-TAG ההרחבה) |
| משפחה, מחלקה | יודעים חלקית | רק משפחת הקוד הישיר של Edge ידועה מהביטים. קוד ישיר של Value, משפחה בפורמט Issuer ומחלקת Meta אינם ידועים מהביטים. בפורמט Issuer ידועים ה-Issuer ומספר ה-Codec. מחלקת האימות של Meta ידועה לפי `C >= 5` בקטע 15 (`w >= 0x1E50`) |
| ה-Edge Id של Edge | יודעים | הרכיב הראשון של Edge (קטעים 5~13) הוא תמיד Reference מסוג LOCAL |
| סמן מקום (לא נרשם, לא ידוע, אין) | יודעים | ערך ה-WORD הוא `0x0000`, `0x0010`, `0x0020` (Reference, C < 3, L 0). [סמן מקום](slot-marker.md) |
| Quantifier | יודעים | לפי היסט `C` בתוך הקטע: בקטע 0 אם `5 <= C < 30`, ובקטע 1 אם `C < 30`, אז `C % 5` |
| אורך ה-TAG לפי Codec, מיקום תחילת ה-Payload | לא יודעים | ספר Codec |
| פירוש ה-Payload, תפקידי רכיבי ה-Edge | לא יודעים | ספר Codec |

- מפענח בלי ספר Codec יכול לדלג על רשומות ולמנות אותן לפי Kind ו-Codec, אך אינו יכול לעקוב אחר מבנה הגרף.
- כל מפענח חייב לטפל במחלקות מבנה, הצהרה ו-IMPORT של Meta. ה-Codec האלה שייכים לספר ה-Codec הליבתי של GEUL, והמפענח מכיר אותם מטבלת מספרים מובנית ([Meta](meta/_index.md)).

ספר ה-Codec מפורסם כמסמך GEUL ([מסמך מפרט Codec](codec-spec.md)). לכן מפענח צריך רק להוריד ולקרוא את מסמך המפרט הדרוש.

## מבנה האזורים {#영역-구조}

הביטים העליונים של ה-TAG WORD מחלקים את המרחב לאזורים.

| Prefix | אזור | שיעור | הגדרה |
|---|---|---|---|
| `1` | עתיד רחוק | 50% | Reserved (עתיד רחוק). אין להשתמש |
| `01` | עתיד | 25% | Reserved (עתיד קרוב). אין להשתמש |
| `001` | תקן | 12.5% | דקדוק שאומץ רשמית ומופעל |
| `000` | חופשי והצעות | 12.5% | הדקדוק הנוכחי. כשהוא מאומץ, הפריסה נשארת כפי שהיא ורק ה-Prefix עובר ל-`001` |

כל הדקדוק הנוכחי נמצא באזור `000`. כל ה-TAG WORD במפרט הזה מתחילים ב-`000`.

- מפענח v1 דוחה TAG WORD שה-Prefix שלו אינו `000`. את האזורים האחרים תקבע גרסה מאוחרת יותר.
- אזור `000` הוא מרחב הצעות. כרגע לא חלים בו רישום או הגנה.
