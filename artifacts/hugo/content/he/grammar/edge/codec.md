CODEC היא Edge תיאורית שמציינת Kind ו-Codec אחד שמקבל [FIELD](/he/grammar/edge/field/) אחד. Codec `0x1E`.

כשם ש-[ENUM](/he/grammar/edge/enum/) מקצה משמעות לערך קוד אחד של שדה גולמי, כך CODEC מקצה לשדה פורמט אחד. כל Edge מציינת פורמט אחד, ולכן אפשר לציין כמה. הפריסה מוטמעת במפענח ([מסמך מפרט Codec](/he/grammar/codec-spec/)).

## פריסה

```
TAG WORD          0001 0LLL L001 1110
[Length extension TAG]
Edge Id           רשומת LOCAL Reference
שדה               רשומת LOCAL Reference שמצביעה על Edge מסוג FIELD
יעד               WORD אחד. 000K KLLL LCCC CCCC (LLLL = 0000 מדויק, 1111 תו כללי)
```

## WORD היעד

- משאירים את מקומות ה-Kind (`KK`) וה-Codec (`CCCCCCC`) של ה-TAG WORD כמות שהם. שלושת הביטים העליונים הם 0. `LLLL` הוא `0000` (מדויק) או `1111` (תו כללי), וכל ערך אחר הוא invalid.
- יעד מדויק (`LLLL = 0000`) שווה למזהה מסמך מפרט ה-Codec (למשל: LOCAL `0x0008`, COORDINATE-EARTH `0x0804`, UTF8-LANGUAGE-TEXT `0x084A`). לכן היעד מצביע ישירות על מסמך מפרט ה-Codec הזה.
- גם זוג קודים זוגי-אי-זוגי (טקסט, רצף בייטים) מצוין בקוד מדויק. כדי לקבל גם זוגי וגם אי-זוגי, מציבים את שניהם. אין כלל שמפרש זוגות כזוג (יש קודים סמוכים שאינם זוג, כמו NUMERIC `0x04`/`0x05`).

### תו כללי (`LLLL = 1111`)

- ה-Kind חייב להיות זהה, ו**קבוצת ביטים של Codec שערכה 0 מתאימה לכל דבר**. ב-Reference, `CCCC` (Codec) ו-`QQQ` (Quantifier) הן קבוצות נפרדות, ובשאר ה-Kind כל 7 הביטים הם קבוצה אחת.

| יעד | משמעות |
|---|---|
| `0780` | כל Reference |
| `07A0` | WIKIDATA-QID, בלי קשר ל-Quantifier |
| `0781` | כל Codec של Reference, Quantifier Generic (`001`) |
| `0F80` | כל Value |
| `1780`, `1F80` | כל Edge, כל Meta |

- תו כללי שאין לו מה להתאים הוא invalid. ב-Value, ב-Edge וב-Meta ה-Codec חייב להיות 0, וב-Reference אחת הקבוצות `CCCC` או `QQQ` חייבת להיות 0. ב-Reference, `CCCC = 0000` (סמן מקום) הוא Codec שמור, ולכן **אינו מתאים לאף תו כללי** (`0780` אינו מקבל ABSENT, UNKNOWN-VALUE או NO-VALUE). מנגד, ב-Kind ש-Codec 0 מוקצה בו, כמו Value `0x00` (BOOL) ו-Edge `0x00` (REFERENCE-NODE), התו הכללי כולל אותו (כדי לקבל BOOL בלבד, משתמשים ב-`LLLL = 0000`).
- תו כללי אינו מצביע על מסמך מפרט.
- אין ביטוי שמקבע רק קבוצה אחת שאינה 0 ומקבע גם את הקבוצה שהיא 0, כמו "כל Reference של Identified בלבד". רשימה כזו מונה יעדים מדויקים.
- 7 הביטים של ה-Codec ב-Reference כוללים את ה-Quantifier (`QQQ`). היעד מציין גם את ה-Quantifier במדויק. כדי לקבל כמה Quantifier, מציבים כמה CODEC.

### סמני מקום (יעד `0000`~`0002`)

[סמן מקום](/he/grammar/reference/slot-marker/) הוא קבוצה של רשומות בנות WORD אחד ב-Codec `0000` השמור של Reference. שלושת הביטים התחתונים הם מספר הסמן (אינו Quantifier).

| יעד | סמן | משמעות |
|---|---|---|
| `0000` | ABSENT | לא נכתב. השדה הוא שדה רשות |
| `0001` | UNKNOWN-VALUE | לא ידוע. מקבל טענה שיש ערך |
| `0002` | NO-VALUE | אין. מקבל טענה שאין ערך |
| `0003`~`0007` | שמור | |

- **כלל קבלה:** סמן תקף רק אם אותו WORD מופיע ברשימת ה-CODEC של השדה כיעד מדויק. תו כללי ושדה רשומה ללא CODEC ("כל רשומה") אינם מקבלים סמן. סמן במקום של רשומת HEAD או BODY או במקום של Edge Id הוא invalid.
- רשימה שיש בה רק יעדי סמן (תמיד סמן) היא invalid (הכללה של הכלל על רשימה שיש בה רק `0000`). משתמשים בו יחד עם תו כללי או יעד מדויק (`0780` + `0000` = כל Reference או השמטה).
- בשדה גולמי אי אפשר להציב יעד סמן. לערך גולמי אין TAG והרוחב קבוע, ולכן אין בו מקום לסמן בן WORD אחד.
- משמעות הסמן נקבעת במפרט ה-Codec שמקבל אותו.

### שדה רשות (יעד `0000`)

- אם ברשימת ה-CODEC של שדה רשומה יש יעד `0000`, השדה הוא **שדה רשות**. כשמשמיטים אותו, כותבים במקומו WORD אחד `0x0000`. רשומה זו בת WORD אחד היא סמן המקום ABSENT (לא נכתב).
- `0x0000` הוא Codec `0000` של Reference (שמור), מספר סמן `000`, `LLLL = 0000` (סה"כ WORD אחד). הוא אינו מתנגש ברשומות אחרות, וגם מפענח שאינו מכיר את המפרט מדלג עליו כרשומה בת WORD אחד.
- גם שדה רשות תופס את מקומו תמיד. כשמשמיטים אותו חייבים לכתוב `0x0000` ולא להשאיר את המקום ריק (גם אם הוא שדה אחורי). לכן יש לרשומה ייצוג אחד בלבד, והפירוק נקבע לפי מיקום בלבד. אין אילוצים על מיקום שדות הרשות, על מספרם או על חפיפת רשימות עם שדות אחרים.
- ABSENT תקף רק במקום של שדה רשות. `0x0000` במקום של רשומת HEAD או BODY, במקום של שדה חובה או במקום של Edge Id הוא invalid.
- השמטה אינה "אין ערך" אלא "לא נכתב". היא אינה טוענת דבר על העולם. "אין ערך" נכתב כ-NO-VALUE (`0002`). מה פירוש ההשמטה (למשל: אם אין יעד ל-TAG, זו הגרסה הזו) נקבע במפרט של כל פורמט.

## פירוש ותקינות

- השדה הוא Edge מסוג FIELD באותו מסמך. לא מציבים אותו יעד פעמיים בשדה אחד.
- **שדה רשומה (רוחב 0)**: אם אין CODEC, השדה מקבל כל רשומה למעט סמני מקום. אם יש אחד או יותר, זו רשימה סגורה. רשומת השדה חייבת להיות אחד מ-Kind ו-Codec שברשימה (ב-Reference כולל Quantifier), ואחרת הרשומה אינה עומדת במפרט. זה שונה מ-ENUM שהיא רשימה פתוחה.
- **שדה גולמי (רוחב n ≥ 1, או השאר `0xFFFF`)**: מציבים רק יעד מדויק אחד (תו כללי אסור). הערך הגולמי הוא ה-Payload של אותו Value ללא ה-TAG. ה-Kind וה-Codec נקבעים ב-CODEC, וה-Length נקבע ברוחב ה-FIELD. בקוד זוגי-אי-זוגי, הקוד שצוין קובע אם מספר הבייטים זוגי או אי-זוגי. אם הערך הגולמי אינו עומד בכללי אותו Value (כולל האורך), הרשומה אינה עומדת במפרט.
- סמני מקום נבדקים רק כיעדים מדויקים ברשימה. אם `0x0000` מופיע במקום של שדה רשות (יעד `0000`), זו השמטה. רשומות אחרות נבדקות מול הרשימה בלי יעדי הסמנים.
- בשדה גולמי אפשר להציב CODEC וגם ENUM יחד. CODEC הוא הפורמט, ו-ENUM הוא שמות ערכי הקוד (למשל: rank כ-UNSIGNED-INTEGER, ו-0, 1, 2 כ-ENUM).
- אפשר לתת ל-Edge Id של CODEC שם באמצעות BIND, אך אין חובה.
- שדה "Reference או Value" נכתב בשני CODEC (`0780`, `0F80`).

## אורך

```
סה"כ = 1 + N_len + N_id + N_field + 1 WORD   (אם Edge Id והשדה הם LOCAL ID בן WORD אחד: 6 WORD)
```

## דוגמה

במסמך המפרט של LABEL, `geul.org/label`, שדה ה-Object (FIELD #3) מקבל UTF8-LANGUAGE-TEXT (זוגי ואי-זוגי) ו-LOCAL. Edge Id 7~9.

```
129E 0088 0007 0088 0003 084A
129E 0088 0008 0088 0003 084B
129E 0088 0009 0088 0003 0008
```

- TAG `129E` (Edge, Codec `0x1E`, `LLLL = 0101`, 6 WORD), Edge Id `0088 0007`, שדה `0088 0003`, יעד `084A`.
