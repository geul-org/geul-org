Meta הוא רשומה על המסמך, לא על תוכן על העולם. מלבד רשומות מבנה המסמך (DOC, BODY, END), כולן מוצבות ב-HEAD של המסמך. ב-HEAD מופיעים, מלבד Meta, גם ה-Edge של ראיות [SOURCE](../edge/0x0C0L-source.md#문서-전체의-출처) של המסמך כולו וה-QUALIFIER שלו.

## פריסה {#레이아웃}

```
TAG WORD          000K KKKC CCCC LLLL      קטעים 14 ו-15 (0x1C0L~0x1FFL)
[TAG הרחבה של Length]
Payload           ערך גולמי, או רשומות Value ו-Reference מובנות
```

- ל-Meta אין פורמט Issuer. Meta הוא מפרט משותף שכל ה-Issuer מצייתים לו, ורק GEUL מגדיר אותו.
- `LLLL` הוא מספר ה-WORD הכולל, כולל ה-TAG WORD, פחות 1. Codec שאינו בטבלה הוא Reserved.

## פורמט ה-Payload {#payload-형식}

| פורמט | מתי | דוגמה |
|---|---|---|
| ערך גולמי | כשהפורמט נקבע באופן יחיד. אינו נשען על Codec של רשומה אחרת | אורך של `DOC-*`, `SPEC-VERSION`, `ISSUER-KEY` |
| Value מובנה | כשבוחרים מבין כמה פורמטים. ה-TAG של ה-Value מודיע את הפורמט | `PROFILE`, `EFFECTIVE-*`, זמן, hash תוכן |
| Reference מובנה | כשמצביעים על פריט כמו אדם, ארגון, כלי או מסמך | `DOC-ID`, `AUTHOR`, `CO-AUTHOR`, `RECORDED-BY`, `SIGNED-OFF`, החותם של `SIGNATURE` |
| אין | סימן של WORD אחד | `BODY`, `END` |

- רשומה מובנית אינה רשומה עצמאית והיא שייכת ל-Meta שלה. כל אחת מוצאת את הגבול שלה לפי ה-Length שלה, והמקום שבו נקראה הרשומה האחרונה חייב להתיישר בדיוק עם סוף ה-Meta.
- אילו Meta אפשר להציב רק אחד במסמך ואילו אפשר כמה נקבע ב”מספר” של מסמך ה-Codec של כל אחד.

## מחלקות {#클래스}

מספרי Meta רצים ברציפות מ-`0x1C0L` בלי Reserved. ביטי המספר אינם מציינים את המחלקה. את המחלקה יודעים מטבלת הטווחים שלהלן.

| מחלקה | קוד ישיר | מה היא עוסקת בו |
|---|---|---|
| מבנה | `0x1C0L~0x1C4L` | גבולות המסמך ואורכו |
| הצהרה | `0x1C5L~0x1CAL` | הצהרות פירוש |
| מוצא | `0x1CBL~0x1D0L` | מי, מתי, מאיפה |
| שושלת | `0x1D1L~0x1DDL` | ממה ואיך הגיע |
| מדיניות | `0x1DEL~0x1E3L` | איך מטפלים בו |
| IMPORT | `0x1E4L` | מייבא מסמך חיצוני |
| אימות | `0x1E5L~0x1E9L` | האם אפשר לסמוך עליו |
| Reserved (לאימות בלבד) | `0x1EAL~0x1FFL` | |

- מחלקת האימות היא רשומות בקטע 15 עם `C >= 5`, כלומר `w >= 0x1E50`. בלי ספר Codec אפשר לזהות בכך את מחלקת האימות ולהוציא אותה מ-hash התוכן.
- ה-Reserved האחורי `0x1EAL~0x1FFL` הוא לאימות בלבד. Meta חדש שאינו אימות אי אפשר להציב לפני האימות, ואם מציבים אותו ב-Reserved האחורי הוא יוצא מ-hash התוכן.
- מחלקות המבנה, ההצהרה ו-IMPORT אינן נקראות לפי ביטים. המפענח מכיר אותן מטבלת המספרים המובנית.
- **Meta הנחוץ לפירוש**: מבנה, הצהרה, IMPORT. אם מוחקים אותם אי אפשר לקרוא את הרשומות או שהפירוש משתנה. כל מפענח חייב לטפל בהם. ה-Codec האלה שייכים ל**ספר ה-Codec הליבתי של GEUL**.
- **Meta שאינו משנה את הפירוש**: מוצא, שושלת, אימות, מדיניות. גם אם מוחקים אותם תוכן ההיגדים נשאר. רק חומר ההערכה של האמון והטיפול נעלם.
- הראיות נכתבות לא ב-Meta אלא ב-Edge של ראיות [SOURCE](../edge/0x0C0L-source.md) וב-QUALIFIER. הראיות של רשומה בודדת ב-BODY, והמקור של המסמך כולו ב-HEAD כ-SOURCE עם Target `0` ([מסמך](../document.md#head와-body)).

## מבנה {#구조}

מחלקת המבנה של Meta (Codec ‏`0x1C0L~0x1C4L`) קובעת את גבולות המסמך ואורכו. יחידת הנתונים של GEUL היא מסמך אחד.

```
DOC-*                  ← תחילת HEAD
  Meta של הצהרה, מוצא, שושלת, אימות, מדיניות ו-IMPORT
  SOURCE של המסמך כולו וה-QUALIFIER שלו
BODY                   ← תחילת BODY
  Reference, Value, Edge
END                    ← סוגר את המסמך
```

- כל מסמך נפתח ב-`DOC-1WORD/2WORD/4WORD` שמציין את האורך הכולל. המפענח יכול לדלג על המסמך כולו בבת אחת לפי האורך הזה.
- `BODY` ו-`END` הן רשומות של WORD אחד בלי Payload. `END` הוא חובה.
- מסמכים אינם מקוננים. מסמך אחר מוצבע באמצעות IMPORT.
- אם ה-HEAD (Meta, ה-SOURCE של המסמך כולו וה-QUALIFIER שלו) ריק, משמיטים את `BODY`. `BODY` יכול להופיע רק פעם אחת בכל מסמך.

מבנה המסמך המלא נמצא ב[מסמך](../document.md).

| Codec | שם | משמעות |
|---|---|---|
| `0x1C0L~0x1C2L` | [DOC-1WORD / 2WORD / 4WORD](0x1C0L-doc-1word.md) | פותח מסמך בציון האורך הכולל |
| `0x1C3L` | [BODY](0x1C3L-body.md) | מסיים את ה-HEAD ופותח את ה-BODY |
| `0x1C4L` | [END](0x1C4L-end.md) | סוגר את המסמך |

הכללים המפורטים נמצאים ב[מסמך](../document.md).

## הצהרה {#정의}

מחלקת ההצהרה של Meta (Codec ‏`0x1C5L~0x1CAL`) היא הצהרות פירוש. הצהרה משנה את כללי הפירוש, ולכן כל מפענח חייב לטפל בה. היקף ההצהרה הוא המסמך שלה.

- `SPEC-VERSION` קובע איך קוראים את שאר הרשומות, ולכן מציבים בו מספר שלם בלבד, בלי Value מובנה. GEUL v1 היא `0x0001` (הרשומה `1C51 0001`).
- `DOC-ID` הוא `DOC-POINTER` (Issuer, מזהה מסמך, גרסה `0`) שמצביע על המסמך עצמו. במסמך Codec זה `CODEC-POINTER` (Issuer, Codec ID, גרסה `0`). אם אין, זה מסמך בלי שם שאפשר להצביע עליו רק ב-hash התוכן.
- אין כתובת לפי שם מסמך. את הכותרת שאדם קורא מצמידים כ-`LABEL` של היגד ([כתובת פרסום ורשימת גרסאות](../publishing.md#문서-이름)).

| Codec | שם | משמעות |
|---|---|---|
| `0x1C5L` | [SPEC-VERSION](0x1C5L-spec-version.md) | גרסת המפרט שהמסמך עוקב אחריה. מספר שלם אחד |
| `0x1C6L` | [PROFILE](0x1C6L-profile.md) | הפרופיל שהוחל |
| `0x1C7L` | [DOC-ID](0x1C7L-doc-id.md) | המזהה של המסמך הזה. DOC-POINTER (גרסה 0) שמצביע על עצמו. במסמך Codec: CODEC-POINTER (גרסה 0) |
| `0x1C8L` | [EFFECTIVE-FROM](0x1C8L-effective-from.md) | מועד כניסתה לתוקף של הגרסה הזו. אם אין, מועד הפרסום |
| `0x1C9L` | [EFFECTIVE-UNTIL](0x1C9L-effective-until.md) | סוף תקופת התוקף של הגרסה הזו (חוק לזמן קצוב). אם אין, עד שהגרסה הבאה נכנסת לתוקף |
| `0x1CAL` | [DEFAULT-LANGUAGE](0x1CAL-default-language.md) | שפת ברירת מחדל |

- אין כתובת לפי שם מסמך ([כתובת פרסום ורשימת גרסאות](../publishing.md#문서-이름)). את הכותרת שאדם קורא מצמידים כ-LABEL ב-BODY.

## מוצא {#출처}

מחלקת המוצא של Meta (Codec ‏`0x1CBL~0x1D0L`) רושמת מי יצר ותיעד את המסמך ומתי.

- הכותב והמתעד ומועדיהם נשענים על מודל ה-author וה-committer של git (`AUTHOR` ו-`CREATED-AT`, `RECORDED-BY` ו-`RECORDED-AT`).
- מחיקת המוצא אינה משנה את תוכן ההיגדים. רק חומר ההערכה של האמון נעלם.
- חומר המקור אינו במחלקה הזו. מקור המסמך כולו נכתב ב-HEAD, ומקור של רשומה בודדת ב-BODY, ב-Edge של ראיות [SOURCE](../edge/0x0C0L-source.md). טווח ההתאמה בנוסח המקורי, מועד ההשגה ו-hash הנוסח המקורי הם QUALIFIER שמוצמדים ל-SOURCE הזה (עמוד P304, סעיף P958, תאריך גישה P813, checksum P4092).
- אם מציבים תכונות של המקור (טווח בנוסח המקורי, מועד ההשגה) כ-Meta, כשיש כמה מקורות אי אפשר לקבוע של איזה מקור הן. לכן הן נכתבות כ-QUALIFIER שה-Target שלו הוא ה-SOURCE.

| Codec | שם | משמעות |
|---|---|---|
| `0x1CBL` | [AUTHOR](0x1CBL-author.md) | כותב (Reference) |
| `0x1CCL` | [CO-AUTHOR](0x1CCL-co-author.md) | כותב שותף |
| `0x1CDL` | [CREATED-AT](0x1CDL-created-at.md) | מועד כתיבה |
| `0x1CEL` | [MODIFIED-AT](0x1CEL-modified-at.md) | מועד עריכה |
| `0x1CFL` | [RECORDED-BY](0x1CFL-recorded-by.md) | הגורם המתעד |
| `0x1D0L` | [RECORDED-AT](0x1D0L-recorded-at.md) | מועד התיעוד |

- חומר המקור נכתב לא ב-Meta אלא ב-Edge של ראיות [SOURCE](../edge/0x0C0L-source.md#문서-전체의-출처) שב-HEAD (Target `0`), וטווח הנוסח המקורי, מועד ההשגה ו-hash הנוסח המקורי נכתבים כ-QUALIFIER שמוצמדים ל-SOURCE הזה.

## שושלת {#계보}

מחלקת השושלת של Meta (Codec ‏`0x1D1L~0x1DDL`) רושמת ממה ואיך הגיע המסמך. השושלת נשענת על מודל ה-commit של git, והיחידה המקבילה ל-commit היא המסמך.

- **hash התוכן** מצביע על תוכן עותק אחד של המסמך (git commit id). זה SHA-256 מהרשומה הפותחת (`DOC-*`) ועד רגע לפני `END`, ורשומות מחלקת האימות (בקטע 15 עם `C >= 5`, `w >= 0x1E50`) מוצאות מהחישוב.
- **מזהה הגרסה** הוא מספר שלם של 2 WORD שממספרים מ-1 בסדר הפרסום בתוך מסמך בעל שם. `0` פירושו שלא נרשמה גרסה.
- Meta של שושלת מצביע על גרסה לפי hash התוכן. גם `PARENT` שבתוך המסמך נכלל ב-hash, ולכן hash התוכן הופך לשרשרת hash שקושרת את כל ההיסטוריה.
- ההיסטוריה אינה נמחקת. תיקון יוצא כגרסה חדשה. מצביע משתנה כמו branch אינו מוצב במסמך.
- `DELTA-BASE` ו-`DELTA-REMOVE` הם הפורמט לאחסון גרסה כ-diff ביחס לגרסת בסיס. גרסה מוגדרת תמיד כ-snapshot.

כללי התיקון נמצאים ב[מסמך](../document.md).

השושלת נשענת על מודל ה-commit של git. היחידה המקבילה ל-commit היא המסמך.

|---|---|---|
| `0x1D1L` | [PARENT](0x1D1L-parent.md) | hash התוכן של הגרסה הקודמת. אם כמה, זה מיזוג |
| `0x1D2L` | [DERIVED-FROM](0x1D2L-derived-from.md) | נגזר מחומר משושלת אחרת |
| `0x1D3L` | [GENERATED-BY](0x1D3L-generated-by.md) | גורם יוצר (אדם, מודל, מנוע כללים) |

| `0x1D5L` | [CHERRY-PICKED-FROM](0x1D5L-cherry-picked-from.md) | הגרסה המקורית של השינוי שנלקח |
| `0x1D6L` | [REVERTS](0x1D6L-reverts.md) | הגרסה שהשינוי בה בוטל |

- ההיסטוריה אינה נמחקת. תיקון יוצא כגרסה חדשה.
- מצביע משתנה כמו branch אינו מוצב במסמך. המאגר והאינדקס מנהלים אותו.

## אימות {#검증}

מחלקת האימות של Meta (Codec ‏`0x1E5L~0x1E9L`) רושמת חומר להערכה אם אפשר לסמוך על המסמך. המפתח הציבורי של Issuer שהונפק עצמית, חתימה, אישור זכות תרומה, מידת אמינות ותוצאת פסק דין של המסמך כולו.

- מחלקת האימות יוצאת מחישוב hash התוכן. לכן גם אם מציבים את החתימה בתוך המסמך, וגם אם מוסיפים כמה חתימות, hash התוכן אינו משתנה (באותה דרך כמו `gpgsig` של git).
- מחלקת האימות היא רשומות בקטע 15 עם `C >= 5`, כלומר `w >= 0x1E50`, ולכן אפשר לחשב את ה-hash בלי ספר Codec. גם ה-Reserved האחורי `0x1EAL~0x1FFL` הוא לאימות בלבד ולכן יוצא מה-hash.
- פסק דין ברמת צומת או רשומה הוא תפקידו של [TOULMIN](../toulmin/_index.md) ב-Edge ‏`VERDICT` (`0x118L`).

| Codec | שם | משמעות |
|---|---|---|
| `0x1E5L` | [ISSUER-KEY](0x1E5L-issuer-key.md) | אלגוריתם החתימה והמפתח הציבורי של Issuer שהונפק עצמית |
| `0x1E6L` | [SIGNATURE](0x1E6L-signature.md) | חתימה על hash התוכן. אלגוריתם, חותם, חתימה |
| `0x1E7L` | [SIGNED-OFF](0x1E7L-signed-off.md) | אישור זכות תרומה |
| `0x1E8L` | [CONFIDENCE](0x1E8L-confidence.md) | מידת אמינות |
| `0x1E9L` | [VERDICT](0x1E9L-verdict.md) | תוצאת פסק הדין של המסמך כולו (Pass, Review, Fail) |

- מחלקת האימות יוצאת מחישוב hash התוכן. לכן גם אם מציבים את החתימה בתוך המסמך, וגם אם מוסיפים כמה חתימות, hash התוכן אינו משתנה.

## מדיניות {#정책}

מחלקת המדיניות של Meta (Codec ‏`0x1DEL~0x1E3L`) קובעת איך מטפלים במסמך. רישיון, היקף חשיפה, דרגת מידע אישי, תקופת שמירה, הסכמה והגבלת שימוש.

- מדיניות אינה משנה את הפירוש, אלא קובעת את אופן הטיפול.

- מדיניות אינה משנה את הפירוש, אלא קובעת את אופן הטיפול.

## IMPORT {#import}

מחלקת ה-IMPORT של Meta (Codec ‏`0x1E4L`) מייבאת מסמך חיצוני באמצעות IMPORT ID. ה-Codec הוא `IMPORT-DOC` (`0x1E4L`) אחד.

- IMPORT מייבא רק מסמכים. פריט בתוך המסמך המיובא מוצבע ב-BODY על ידי ה-Reference ‏`EXTERNAL-POINTER-*` (IMPORT ID, LOCAL ID) ([Reference](../reference/_index.md)).
- אם נרשם מזהה גרסה, הקישור הוא לנוסח הזה; אם `0`, הקישור הוא לנוסח האחרון בזמן הפירוש. מסמך מפורסם רושם גרסה.
- ה-HEAD של המסמך המיובא אינו מיובא. רשומות Reference ו-Value אינן מיובאות אלא מועתקות.

```
TAG WORD          0001 1110 0100 LLLL      IMPORT-DOC (0x1E4L)
[TAG הרחבה של Length]
מסמך              רשומת DOC-POINTER (Issuer, מזהה מסמך, מזהה גרסה). במסמך Codec: CODEC-POINTER
IMPORT ID         השאר. מספר שלם ברוחב הקצר ביותר
```

- משתמשים רק ב-[IMPORT-DOC](0x1E4L-import-doc.md) (`0x1E4L`). IMPORT מייבא רק מסמכים. פריט בתוך המסמך המיובא מוצבע ב-BODY על ידי `EXTERNAL-POINTER-*` (IMPORT ID, LOCAL ID).
- אם נרשם מזהה גרסה, הקישור הוא לנוסח הזה; אם `0`, הקישור הוא לנוסח האחרון בזמן הפירוש. מסמך מפורסם רושם גרסה.
- אין להקצות אותו IMPORT ID פעמיים באותו מסמך.
- ה-HEAD של המסמך המיובא אינו מיובא. הפריטים של אותו מסמך מפורשים לפי ההצהרות של אותו מסמך.

דוגמה: ייבוא הגרסה האחרונה של המסמך `0x0000000000000002` של Issuer ‏`0x00000002` כ-IMPORT ID 1.

```
1E4A 0418 0000 0002 0000 0000 0000 0002 0000 0000 0001
```
