## חברים {#구성원}

דף זה עוסק בשני קודים של זוג זוגי/אי-זוגי יחד. הקוד הזוגי הוא ערך שמספר הבייטים שלו זוגי, והקוד האי-זוגי הוא ערך שמספר הבייטים שלו אי-זוגי ([רשומה ו-TAG WORD](../record.md#가변-길이-바이트열)). מסמך Codec אחד לכל קוד. השדות בשני מסמכי ה-Codec זהים, ורק יעד ה-DECLARE והשם (BIND) שונים.

| TAG ID | שם | מספר בייטים | Codec ID | מסמך מפרט | TAG WORD |
|---|---|---|---|---|---|
| `0x074L` | `URI-EVEN` | זוגי | `0x00000740` | `0x00000000/codecs/0x00000740/` | `0000 0111 0100 LLLL` |
| `0x075L` | `URI-ODD` | אי-זוגי | `0x00000750` | `0x00000000/codecs/0x00000750/` | `0000 0111 0101 LLLL` |

## שדות (מסמך מפרט) {#필드-규격-문서}

סדר ה-FIELD במסמך הוא סדר שדות ה-Payload ([מסמך המפרט של Codec](../codec-spec.md)).

URI הוא Value הנושא רצף בייטים ASCII בדקדוק `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]` של RFC 3986. מכיוון שהוא כולל scheme, פירושו אינו דורש base URI.

## פריסה {#레이아웃}

- קוד: קוד ישיר של Value ‏`0x074L` (בייטים זוגיים) ו-`0x075L` (בייטים אי-זוגיים). משפחה TEXT.
- מספר הבייטים נקבע לפי הסיבית הנמוכה ביותר של ה-Codec ומספר ה-Payload WORD. הוא `2 × מספר Payload WORD − הסיבית הנמוכה ביותר`, ואין Byte Count ([Value](_index.md)).

```
TAG WORD          0000 0111 010P LLLL      Codec 0x074L/0x075L
[Length TAG הרחבה] כשהסך הכול 15 WORD ומעלה
Payload WORD 1st ... Nth          URI bytes / final zero padding
```

## פירוש ותוקף {#해석과-유효성}

- רצף הבייטים חייב להתאים לדקדוק `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]` של RFC 3986. הוא יכול לכלול query ו-fragment.
- ה-terminal של דקדוק URI הם תווי US-ASCII. תווי ASCII מותרים נשמרים כפי שהם, וכשמבצעים percent-encoding של octet משתמשים בצורה `pct-encoded = "%" HEXDIG HEXDIG`. אסור להכניס ישירות תווים שאינם ASCII כבייטים literal.
- חובה לכלול `scheme` ו-`:`. להפניה יחסית משתמשים ב-[URI-RELATIVE-REF](ietf.geul.org/uri-relative-ref.md) (מספרי Codec של IETF ‏`0x00008000`·`0x00008001`).
- ה-production ‏URI של RFC 3986 אינו מתיר מחרוזת ריקה. רשומה של 0 בייטים אינה תקפה.
- בתוך WORD הבייט העליון בא ראשון. אם מספר הבייטים אי-זוגי (קוד אי-זוגי), הבייט התחתון שאינו בשימוש ב-WORD האחרון חייב להיות `00`.
- מספר ה-Payload WORD הוא `ceil(מספר בייטים/2)`. אם הקוד אי-זוגי והבייט התחתון של ה-WORD האחרון אינו `00`, דוחים.

## בסיס בתקנים {#표준-근거}

- הדקדוק של `URI`, תווי URI ו-percent-encoding נקבע לפי [RFC 3986, Uniform Resource Identifier (URI): Generic Syntax](https://www.rfc-editor.org/rfc/rfc3986).
- זוג הקודים זוגי/אי-זוגי, zero padding, ‏TAG/Length של GEUL ופריסת WORD של 16 סיביות הם כללי ה-framing של פורמט זה.

## אורך {#길이}

- הסך הכול הוא מספר ה-WORD של TAG אחד, ה-Length TAG של ההרחבה (אם יש) וה-Payload. עד 14 WORD משתמשים באורך ישיר, ומ-15 WORD ומעלה באורך מורחב `1110`·`1111`, וה-TAG של ההרחבה נכלל גם הוא בסך הכול ([Length](../record.md)).

## דוגמה {#예시}

- `https://example.com/` הוא 20 בייטים של ASCII (זוגי), ולכן `URI-EVEN` ‏(`0x074L`).
- ה-Payload הוא 10 WORD: ‏`6874 7470 733A 2F2F 6578 616D 706C 652E 636F 6D2F`.
- TAG של WORD אחד ועוד Payload של 10 WORD נותנים סך הכול 11 WORD, ולכן `LLLL=1010`. השלם הוא `074A 6874 7470 733A 2F2F 6578 616D 706C 652E 636F 6D2F`.

## GEUL Archive URI {#geul-archive-uri}

‏`archive.geul.org` הוא מאגר תוכן בלתי משתנה שנועד ב-GEUL להפניה לתוכן גדול, כמו בינאריים ומסמכים חיצוניים, ועדיין אינו מופעל. פורמט הכתובת המומלץ הוא `https://archive.geul.org/sha256/{digest}`. לאותו רצף בייטים חייב להיות אותו URI, ולאחר הפרסום אסור לשנות את הבייטים של אותו URI.

Value מסוג URI רק מייצג את מיקומו או מחרוזת הכתובת של תוכן חיצוני, ואינו מבטיח את זהות היעד עצמו או את אי-שינויו. בינאריים וטקסט החורגים מהטווח המרבי של Value שורתי אפשר להפנות אליהם באמצעות archive URI. במטא-נתונים של האובייקט השמור יש לרשום את הפריטים הבאים.

- URI המקור ומועד האיסוף
- SHA-256 ו-Byte Length
- MIME type
- license identifier וגרסה
- יוצר, מקור והודעות
- URI של בסיס הרישיון, ואם צריך, העתק של הבסיס בעת האיסוף

הכרעה אם אפשר לאסוף תלויה בכך שהרשאת ההפצה מחדש מאושרת במפורש, ולא בכך שהגישה חינמית. יש לקיים את תנאי הרישיון החלים, כגון ייחוס, אי-מסחריות, איסור שינוי ושיתוף זהה. במסמכים ובתוכן רושמים רישיון מפורש כמו Creative Commons, ובתוכנה משתמשים במידת האפשר ב-SPDX License ID.

גם אם הפסקת האספקה נובעת מבעיית זכויות או מתיקון, אסור להכניס בייטים אחרים ל-URI קיים. אותו URI מחזיר tombstone הנושא את סיבת ההפסקה ומועדה, ויש לשמר את ה-digest המקורי ואת רשומת הביקורת. אולם אם חובה משפטית אוסרת לשמר את רשומת הביקורת, החובה הזו גוברת.

archive URI מספק יחד את מיקום הגישה ואת ה-digest של התוכן. כללי כתובת-התוכן ואי-השינוי הללו הם מדיניות של פרופיל GEUL Archive, והדקדוק הכללי של Value מסוג URI אינו תלוי ב-`archive.geul.org`.

## הטקסט המקורי של מסמך המפרט {#규격-문서-원문}

זהו מסמך המפרט `0x00000000/codecs/0x00000740/latest.geul` כפי שהוא נקרא באמצעות `geul show` (ספרות הקסדצימליות באותיות גדולות).

```
SPEC-VERSION 0x0001
DOC-ID 0x0426000000000000074000000000
BODY
#1 DECLARE 0x0740
#2 FIELD #1 rest
#3 BIND #1 "URI-EVEN"
#4 BIND #2 "bytes"
```

למעלה מסמך ה-Codec של `URI-EVEN` (‏`0x074L`). במסמך ה-Codec של חבר אחר (`URI-ODD`) שונים רק ה-Codec ID ב-DOC-ID, יעד ה-DECLARE והשם הקשור ב-`#1` (BIND).
