GEUL データの単位は、ドキュメント(DOC)一つだ。ファイル一つ(`.geul`、メディアタイプ `application/vnd.geul`)がドキュメント一つになる。

## 構造

```
DOC-*            ← ドキュメントを開く (全体の長さ)
  Meta …         ← HEAD: ドキュメントに関するレコード
  SOURCE …       ←   (ドキュメント全体の出典とその QUALIFIER)
BODY             ← HEAD を終えて BODY を開く
  Reference, Value, Edge …
END              ← ドキュメントを閉じる
```

| レコード | TAG | 意味 |
|---|---|---|
| DOC-1WORD | `1880` + 1 WORD | 全体の長さを 1 WORD で指定してドキュメントを開く |
| DOC-2WORD | `1901` + 2 WORD | 全体の長さを 2 WORD で |
| DOC-4WORD | `1A02` + 4 WORD | 全体の長さを 4 WORD で |
| BODY | `180E` | 1 WORD。HEAD を終えて BODY を始める |
| END | `180F` | 1 WORD。ドキュメントを閉じる |

- DOC-* の値は、開くレコードの先頭から END の末尾までの全 WORD 数だ。値が収まる最も狭い幅を使う。
- END は必須だ。END の位置が DOC-* の長さと合わなければ拒否する。END なしで入力が終わったら、切れたドキュメントだ。
- デコーダは DOC-* の長さで、ドキュメント全体を一度に読み飛ばせる。
- 長さを知らないまま開く方法はない。終わりを事前に知れないリアルタイムデータは、長さの分かる単位に区切って複数のドキュメントで送る。
- HEAD が空なら BODY を省略する。BODY レコードのないドキュメントは、すべて BODY だ。BODY は一度だけ置く。HEAD にレコード(Meta または HEAD Edge)が一つでもあれば BODY を置く。
- ドキュメントは入れ子にしない。他のドキュメントは [IMPORT](/ja/grammar/meta/) や指示 Reference で指す。

## HEAD と BODY

- HEAD には Meta と **HEAD Edge** の二つだけを置く。どちらも、それを収める**ドキュメント**についての記述だ。
  - Meta: ドキュメントの構造・定義・出典・系譜・検証・ポリシー・IMPORT。
  - HEAD Edge: ドキュメント全体の原典を書く根拠 Edge [SOURCE](/ja/grammar/edge/source/#ドキュメント全体の出典)(Target `0`)と、その SOURCE を Target とする [QUALIFIER](/ja/grammar/edge/qualifier/)(原文ハッシュ、受信時刻、原文範囲など)。QUALIFIER はその SOURCE の後ろに置く。
- BODY には Reference、Value、Edge だけを置く。個々のレコードの出典は BODY 内の根拠 Edge [SOURCE](/ja/grammar/edge/source/)で、信頼度のような他の根拠はそのレコードに付く QUALIFIER で書く。Target `0` の SOURCE と、HEAD の SOURCE を Target とする QUALIFIER は、BODY に置けない。
- デコーダは HEAD を先頭から読みながら分ける。Meta は HEAD だ。Target `0` の SOURCE は HEAD で、その Edge Id を記憶する。記憶した SOURCE を Target とする QUALIFIER は HEAD だ。それ以外のレコードが来たとき、HEAD が空なら BODY が省略されたもの(そのレコードから BODY)で、そうでなければ BODY の欠落で invalid だ。
- **Edge Id は HEAD と BODY が一つの番号空間を使う。** ドキュメント内で一意で、BODY の Edge と同じく [NEXT-LOCAL-ID](/ja/grammar/meta/lineage/next-local-id/) から受け取る。HEAD Edge の Origin が LOCAL なら、その定義は BODY に置く(LOCAL はドキュメント全体が範囲)。
- Meta は Payload の中に Value レコードを含められる。含まれた Value は独立したレコードではなく、その Meta の一部だ。
- 宣言(Meta の定義クラス)の範囲は、そのドキュメントだ。

## 基本宣言

二つの宣言は、どちらも多くて一つだ。どのドキュメントに必ず必要かは、下の条件で決まる。

| Meta | 意味 | 必要なドキュメント |
|---|---|---|
| [SPEC-VERSION](/ja/grammar/meta/declaration/spec-version/) | 従う仕様の版。残りのレコードをどう読むかを決める。知らない版なら拒否または警告する。v1 ドキュメントの値は `0x0001` だ | 公表ドキュメント。なければデコーダが知っている版で読む |
| [DOC-ID](/ja/grammar/meta/declaration/doc-id/) | ドキュメント自身の識別子。ドキュメントの外からこのドキュメントとその中の対象を指すには必要だ | `.well-known/geul/` 配下で名前が `0x` で始まるドキュメント(バージョンドキュメント、規格ドキュメント)。バージョン一覧・名前索引には置かない |

- `SPEC-VERSION` は、どの版のデコーダでも読めるよう整数一つだけを持つ(v1 は `1890 0001`)。Value コードに頼らない。
- `DOC-ID` は自分自身を指す DOC-POINTER(Issuer、ドキュメント ID、バージョン `0`)だ。ドキュメント ID は 4 WORD だ。
- `DOC-ID` のないドキュメントは名前のないドキュメントだ。コンテンツハッシュでのみ指せる。

## コンテンツハッシュ

ドキュメント一式は**コンテンツハッシュ**で指す(git のコミット ID と同じ役割)。

- 開くレコード(DOC-*)から END の直前までの SHA-256 だ。16 WORD。
- 検証クラスの Meta(署名など)は計算から除く。そのため署名をドキュメント内に置いても循環が生じない。
- 計算するとき、DOC-* の長さは検証レコードを除いた長さに置き換え、幅もその長さに合う最も狭い幅に置き換える。そのため署名を付ける前と後でコンテンツハッシュが同じになる。
- コンテンツハッシュはドキュメントに記録せず、計算する。他のバージョンを指すときだけ値として書く(`PARENT` など)。
- ドキュメント内の `PARENT` も計算に入るので、コンテンツハッシュは履歴全体をつなぐハッシュチェーンになる。
- ドキュメントの外で後から付けた Meta(別ストアの注釈など)は、コンテンツハッシュを変えない(git notes と同じ)。
- ドキュメントはバイナリが正本だ。コンテンツハッシュと署名はバイナリでのみ計算する。

## バージョン

名前のあるドキュメント(`DOC-ID` のあるドキュメント)はバージョンを持つ。

- **バージョン ID** は、ドキュメント一つの中で公表順に 1 から振る 2 WORD の整数だ。`0` は「バージョンを書かない」で、最新バージョンとして扱う。
- バージョン ID は、公表元が公表するときに割り当てる。バージョン ID とコンテンツハッシュの対応は、公表元が署名したバージョン一覧に置く([公表アドレスとバージョン一覧](/ja/grammar/publishing/#バージョン一覧))。
- 同じ内容を再び公表しない。すでにあるコンテンツハッシュなら、そのバージョン ID を返す。
- 2 WORD を使い切ったら、新しいドキュメント ID で出す。
- v2 以降のバージョンは、HEAD に `PARENT`(直前バージョンのコンテンツハッシュ)を書く。コンテンツハッシュに入るので、バージョンはハッシュチェーンでつながる。最初のバージョンには置かない。

## 改訂

GEUL ドキュメントは法令のように改訂される。

- **バージョンは不変だ。** 公表したバージョンは変更も削除もしない。例外は法的削除と職権削除だけだ([TOMBSTONE](/ja/grammar/edge/publication/))。
- 履歴は消さない。直した内容は新しいバージョンとして出し、元のバージョンを上書きしない(旧法の保存)。書き直したバージョンは [REPLACES](/ja/grammar/meta/lineage/replaces/) で元のバージョンにつなぐ。
- branch、HEAD、reflog のように変わるポインタは、ドキュメントに置かない。ドキュメントの外(ストア・インデックス)で管理する。
- 新しいバージョンは、定義を新設・改訂・削除できる。以前のバージョンとの互換は約束しない。同じ用語の定義が変わることも改訂だ(例: 民法「成年」20歳 → 19歳、刑法の強制性交等罪の客体「婦女」→「人」)。
- **LOCAL ID はバージョンを越える同一性だ**(条文番号のように)。同じ LOCAL ID は、バージョンが違っても同じ対象を指す。
  - 新設: 新しい LOCAL ID を受け取る。ID に順序の意味はないので、「第X条の2」のような差し込みは要らない。新しい番号はバージョン一覧の `NEXT-LOCAL-ID` から受け取る(auto increment)。
  - 改訂: 同じ LOCAL ID の内容を変える。
  - 削除: その LOCAL ID を新しいバージョンから除く。**削除した ID は再利用しない。**
  - 移動・分割・統合: 新しい LOCAL ID を受け取り、新しいレコードに QUALIFIER P1365(replaces、値は旧 LOCAL ID)を付けて旧 ID につなぐ。旧 ID は再利用しないので、以前のバージョンのそのレコードを指す。
- 原典資料からドキュメントを再生成するツールもこの規則を守る。直前のバージョンと同じ記述には同じ LOCAL ID を与え、変わったか新しく生じた記述にだけ新しい番号を与える。番号を毎回 1 から振り直してはならない。
- 引用は版を特定する。バージョンを固定した引用はそのバージョンに、最新(バージョン `0`)の引用は解釈時点の現行バージョンに結びつく。過去の事件を扱うドキュメントは、その時点で施行中だったバージョンを固定して引用する。
- 公表と施行は別だ。公表時刻はバージョン一覧が、施行期間はドキュメントが書く。
  - [EFFECTIVE-FROM](/ja/grammar/meta/declaration/effective-from/)・[EFFECTIVE-UNTIL](/ja/grammar/meta/declaration/effective-until/): バージョン全体の施行期間
  - 条文 Edge の QUALIFIER P580(開始)・P582(終了): 条文ごとに施行日が異なるとき
- **時点 T に施行中の版は、施行日が T 以下で最も高いバージョンだ。** 条文ごとの P580・P582 QUALIFIER があれば、それが優先する。有効期間(`EFFECTIVE-UNTIL`)を過ぎた版は施行中ではない。
- 経過規定(「従前の規定による」)、行為時法と被告人に有利な新法の選択のように、どの版を適用するかを決める規則は、判定([TOULMIN](/ja/grammar/edge/toulmin/))が担う。施行情報はその材料だ。
- 解釈例・判例が用語の解釈を狭めたり広げたりするのは、ドキュメントの改訂ではなく判定規則だ。解釈を立法で定めた場合(例: 労働基準法「1週」の定義新設)は改訂だ。
- Codec と形式番号のバイナリ(wire)レイアウトは改訂しない。形式番号でエンコードされたレコードは、コードブックのバージョンを固定せずに読めるからだ。レイアウトを変えるには新しい番号を割り当てる。削除した形式番号は他の形式に再利用しない。

## diff 保存

バージョンは常にドキュメント全体(スナップショット)で定義する。diff は、そのスナップショットを少なく保存・転送する形式にすぎない。

- `DOC-ID` があり BODY がすべて Edge であるドキュメントだけが diff にできる。バージョン管理をしない `versions.geul`・`documents.geul`・`issuers.geul` と、名前のないドキュメントは diff にしない。
- diff ドキュメントは通常の GEUL ドキュメントで、HEAD に [DELTA-BASE](/ja/grammar/meta/lineage/delta-base/)(基準バージョン ID)を置く。
- 削除は [DELTA-REMOVE](/ja/grammar/meta/lineage/delta-remove/)(除く LOCAL ID の一覧)で、追加と改訂は BODY の Edge で書く。追加・改訂の標識は別にない。Edge Id が基準にあれば改訂、なければ追加だ。
- スナップショットの復元は決定的でなければならない(ハッシュを合わせるため)。
  1. 基準バージョンのスナップショットを復元する。基準も diff なら再帰で復元する。
  2. HEAD は、diff の HEAD から `DELTA-BASE`・`DELTA-REMOVE` を除いたものにまるごと置き換える。HEAD Edge も一緒に変わる(`DELTA-REMOVE` には書かない)。
  3. BODY は基準の順序を保つ。`DELTA-REMOVE` の ID は除き、diff BODY の Edge Id が基準にあれば、その位置で置き換える。
  4. 基準にない Edge Id は、diff に出た順に末尾へ付ける。
  5. 結果のコンテンツハッシュが、バージョン一覧のこのバージョンのハッシュと同じでなければならない。異なれば invalid だ。
- 削除した LOCAL ID を diff で再利用したら invalid だ。抜けた HEAD Edge の Edge Id も再利用しない。
- コンテンツハッシュ、バージョン一覧、署名は、すべて復元したスナップショットが基準だ。
