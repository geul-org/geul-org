GEUL は文字列 URL ではなく、ID(Issuer、ドキュメント ID、バージョン ID)でドキュメントを指す。アドレスは ID から決まる。このページは、エンコーダ・デコーダ・リゾルバが互いに噛み合って動作するために必要な公表規則を定める。Issuer の等級と公開方式は、[Issuer と公表](/ja/grammar/issuer/)が定める。

## ID 表記

アドレスに使う ID は hex で書く。

- プレフィックスは小文字の `0x`、hex の数字も小文字だ。
- 桁数は幅 × 4 に固定する。先頭の 0 を省略せず、桁数がそのまま幅だ。
- Issuer ID は、値が収まる最短幅で書く。`0x00000005` のような広げた表記はない(`0x0005`)。

| 対象 | 幅 | 桁数 | 例 |
|---|---|---|---|
| Issuer | 1 WORD | 4 | `0x0001` |
| Issuer | 2 WORD | 8 | `0x00010000` |
| Issuer | 4 WORD | 16 | `0x0000000100000000` |
| Issuer | 16 WORD | 64 | `0x` + 64桁 |
| ドキュメント ID | 4 WORD | 16 | `0x0000000000000000` |
| バージョン ID | 2 WORD | 8 | `0x00000003` |
| コンテンツハッシュ | 16 WORD | 64 | `0x` + 64桁 |

- 正規形でない要求(`0X`、大文字、0 の省略)は、正規形のアドレスへ `301` リダイレクトする。キャッシュキーと署名対象が一つに決まる。
- バージョン ID の規則(1 から、`0` は最新、公表元が割り当て、使い切ったら新しいドキュメント ID)は、[ドキュメント](/ja/grammar/document/#バージョン)が定める。

## 公表アドレス

```
/.well-known/geul/<Issuer>/<ドキュメント ID>.geul              最新バージョン。302 で正本アドレスへ送る (可変)
/.well-known/geul/<Issuer>/<ドキュメント ID>/<バージョン ID>.geul    ドキュメント一式 (不変、正本アドレス)
/.well-known/geul/<Issuer>/<ドキュメント ID>/versions.geul     バージョン一覧ドキュメント (可変、署名)
/.well-known/geul/h/<コンテンツハッシュ>.geul                   コンテンツハッシュで取得 (不変)
```

例: `/.well-known/geul/0x0001/0x0000000000000000.geul`

- パスは RFC 8615 の `.well-known` に従う。geul.org と非公開の公表が同じパスを使い、ドメインだけが異なる。登録するサフィックスは `geul` 一つだ。
- ドキュメントの内容は、不変アドレスからのみ出る。最新バージョンのアドレスは内容を返さず、`302` でそのバージョンの正本アドレスへ送る。
- 一つのバージョンの正本アドレスは `/<Issuer>/<ドキュメント ID>/<バージョン ID>.geul` だ。同じ内容を返す他のアドレスは、`Link: rel=canonical` で正本アドレスを指す。
- 不変アドレスは永久キャッシュと CDN に置ける。受け取った側は、バージョン一覧(またはロック記録)のコンテンツハッシュで検証する。
- ID は常に `0x` で始まる。そのため予約名(`h`、`keys`、`issuers.geul`、`documents.geul`、`versions.geul`)や人が付けた名前は、`add`、`cafe` のように hex だけの単語でも ID と重ならない。
- 位置(どのサーバーから受け取るか)は、ドキュメントの内容に入れない。入れるとアドレスが変わったときにコンテンツハッシュが変わる。位置は、ドキュメントを受け取る側の設定が決める。

### 形式の指定

- 拡張子があれば、形式を指定したことになる。`.geul` はバイナリ(`application/vnd.geul`)だ。
- 拡張子がなければ `Accept` ヘッダに従う。ブラウザには HTML ビューを、ツールにはバイナリを返す。例: `/<Issuer>/<ドキュメント ID>/<バージョン ID>`
- ドキュメントはバイナリが正本だ。コンテンツハッシュと署名はバイナリでのみ計算する。

### ドメイン名

ドメイン所有の証明を経た Issuer は、アドレスの `<Issuer>` の位置に、ID の代わりにそのドメインを使える。

```
/.well-known/geul/<ドメイン>/<ドキュメント ID>.geul              → 302 → /<Issuer>/<ドキュメント ID>.geul
/.well-known/geul/<ドメイン>/<ドキュメント ID>/<バージョン ID>.geul    → 302 → /<Issuer>/<ドキュメント ID>/<バージョン ID>.geul
/.well-known/geul/<ドメイン>/<ドキュメント ID>/                  → 302 → /<Issuer>/<ドキュメント ID>/
```

例: `/.well-known/geul/geul.org/0x0000000000001018/0x00000001.geul`

- ドメインアドレスは内容を返さず、`302` で ID アドレスへ送る。正本アドレス、キャッシュキー、署名対象は ID アドレスだ。対応が変わりうるので、恒久リダイレクトは使わない。
- ドメインは小文字で書き、国際化ドメインは IDNA(punycode)の形で書く。末尾の `.` は付けない。正規形でなければ、正規形へ `301` リダイレクトする。
- ドメインには `.` があるので、`0x` で始まる ID や予約名と重ならない。
- リゾルバは、ドメインアドレスを受け取ったら、Issuer 名前索引で対応を確認し、ID に変えてロック記録に残す。
- 登録簿のない 16 WORD Issuer と、geul.org に届かない隔離ネットワーク環境は、ドメイン名を使えない。ID アドレスを使う。

### Issuer 名

Issuer 名前索引は `/.well-known/geul/issuers.geul` 一つのドキュメントだ。

```
BODY
  BIND   Subject = ISSUER-POINTER(Issuer)   名前 = "geul.org"
  …
```

- Subject は [ISSUER-POINTER](/ja/grammar/reference/issuer-pointer/)(Issuer 自身)で、名前は [BIND](/ja/grammar/edge/bind/) で結びつける。
- 名前は、ドメイン所有の証明を経たドメインだ。小文字で、国際化ドメインは IDNA(punycode)で書く。名前一つは Issuer 一つにだけ結びつく。
- 人が読む Issuer の表示名(言語別)は、同じ Subject に記述 [LABEL](/ja/grammar/edge/label/) で付ける。
- geul.org(GEUL Issuer)が署名し、変わったときは書き足し、直さない(バージョン一覧と同じチェーン規則)。
- 予約名 `issuers.geul` は `.` があってドメインの形をしている。同じ名前のドメインができても、このパスは Issuer 名前索引のまま残る。

### ドキュメント名

ドキュメント ID の代わりに、ドキュメント名でもアドレスを使える。`<Issuer>` の位置には、ID かドメイン名を使う。

```
/.well-known/geul/<Issuer|ドメイン>/<ドキュメント名>.geul              → 302 → /<Issuer>/<ドキュメント ID>.geul
/.well-known/geul/<Issuer|ドメイン>/<ドキュメント名>/<バージョン ID>.geul    → 302 → /<Issuer>/<ドキュメント ID>/<バージョン ID>.geul
/.well-known/geul/<Issuer|ドメイン>/<ドキュメント名>/                  → 302 → /<Issuer>/<ドキュメント ID>/
```

例: `/.well-known/geul/geul.org/publication/0x00000001.geul` → `/0x0000/0x0000000000001018/0x00000001.geul`

**ドキュメント名は、Issuer の名前索引 `/<Issuer>/documents.geul` が BIND で結びつける。** リゾルバは、名前をこのインデックスでドキュメント ID に対応させる。

```
BODY
  BIND   Subject = DOC-POINTER(Issuer, ドキュメント ID, バージョン 0)   名前 = "publication"
  …
```

- Subject は [DOC-POINTER](/ja/grammar/reference/doc-pointer/)(Issuer、ドキュメント ID、バージョン `0`)だ。名前はバージョンではなくドキュメントに結びつく。
- Subject の Issuer は、インデックスを置いた Issuer と同じでなければならない。他の Issuer のドキュメントは無視する。
- 名前は、公表されたドキュメントにだけ結びつける。
- ドキュメント名は小文字 ASCII のスラッグだ: `a-z`、`0-9`、`-`。先頭と末尾は `-` ではなく、`0x` で始まらない。そのためドキュメント ID(`0x…`)や予約名(`h`、`versions.geul` など)と重ならない([BIND](/ja/grammar/edge/bind/))。
- 一つの Issuer 内で、名前一つはドキュメント一つにだけ結びつき、一度結びつけた名前は他のドキュメントに再利用しない。名前を変えるときは新しい BIND を書き足す。旧名は同じドキュメントへ送り続ける。同じ名前が複数回出たら、最後の BIND が代表だ。
- ドキュメントの中には、自分の名前を書かない。正本アドレス、キャッシュキー、署名対象は ID アドレスだ。IMPORT とドキュメント内の引用は ID だけで行う。
- 人が読むタイトル(言語別)は名前ではない。記述 `LABEL` で付ける。
- バージョン一覧ドキュメントにも、同じドキュメント名の BIND を置ける([PUBLICATION](/ja/grammar/edge/publication/#ドキュメント名))。置けば、名前索引と同じでなければならない。リゾルバは名前索引だけを読む。

### 削除されたドキュメント

- 法的削除・職権削除されたバージョンのアドレスは、`410 Gone` と墓標(バージョン ID、コンテンツハッシュ、削除日、事由カテゴリ)を返す。
- バージョン一覧には、[TOMBSTONE](/ja/grammar/edge/publication/) レコードとして残る。

## 層

GEUL は、出典・メタ・一覧まで GEUL ドキュメントで表現する。それを読むのに必要な最小限はデコーダに内蔵して、循環を断ち切る。各層は下の層にだけ依拠する。

| 層 | 内容 | 依拠するもの |
|---|---|---|
| 0 層 | デコーダ内蔵の規則: フレーミング、コンテンツハッシュ、署名検証、バージョン一覧レコードの Codec(`PUBLICATION`・`DEPRECATION`・`TOMBSTONE`)、Codec 規格の語彙(`DECLARE`・`FIELD`・`ENUM`・`CODEC`)、[プレースホルダ](/ja/grammar/reference/slot-marker/)(`0x0000`~`0x0002`)、ドキュメントの外で受け取る信頼鍵 | なし。参照しない |
| 1 層 | バージョン一覧ドキュメント | 0 層 |
| 2 層 | 通常のドキュメント、コードブック、Codec 規格ドキュメント、Issuer 検証鍵ドキュメント | 1 層で探し、0 層で検証する |

- どの層も、自分の層や上の層に依拠しない。
- GEUL で表現することと、GEUL で解釈しないと読めないことを区別する。0 層は GEUL で表現できても、解釈に参照を必要としない。
- 判定の意味のように、TOULMIN ドキュメントで変えられない固定された核も、この位置に置く([TOULMIN](/ja/grammar/edge/toulmin/#メタ認知と自己改訂))。

## バージョン一覧

公表元は、ドキュメントごとにバージョン一覧ドキュメントを一つずつ書き継ぐ(`/<Issuer>/<ドキュメント ID>/versions.geul`)。レコード形式とドキュメント構造は、[PUBLICATION](/ja/grammar/edge/publication/)が定める。

```
DOC-*
  SPEC-VERSION
  PARENT          直前の一覧ドキュメントのコンテンツハッシュ
  RECORDED-AT     この一覧を出した時刻
  NEXT-LOCAL-ID   次に割り当てる LOCAL ID
  SIGNATURE       公表元の署名
BODY
  PUBLICATION     #1  ドキュメント@1  コンテンツハッシュ
  PUBLICATION     #2  ドキュメント@2  コンテンツハッシュ
  DEPRECATION     #3  ドキュメント@1
  …
END
```

| Edge | 意味 |
|---|---|
| PUBLICATION | ドキュメントの一バージョンとそのコンテンツハッシュを公表する |
| DEPRECATION | 公表したバージョンに使用中止の勧告を表示する。引き続き解釈される |
| TOMBSTONE | 公表したバージョンを削除する(法的・職権削除)。事由カテゴリを書く |

- レコードは追加だけを行う。直したり、消したり、順序を変えたりしない。deprecate・削除もレコードを書き足す。新しい一覧は、直前の一覧の BODY をそのまま前に置いてレコードを書き足し、一覧同士は `PARENT` のハッシュチェーンでつながる。
- 公表記録を直さないという意味で、ドキュメント内容の改訂([ドキュメント](/ja/grammar/document/#改訂))とは異なる。バージョンの現在の状態は、レコードを順に適用して計算する。
- バージョン ID は、1 から欠番なく昇順だ。同じ内容を再び公表しない。
- 最新バージョンは、廃止勧告でも削除でもない最も高いバージョンだ。
- レコードには時刻を入れない。そのレコードが最初に載った一覧の `RECORDED-AT` が公表時刻だ。
- 一覧ドキュメントには `DOC-ID` を置かない。レコードのドキュメント ID が、何の一覧かを語る。
- 一覧ドキュメントは IMPORT を置かず、0 層の Codec だけを使う。
- 一覧ドキュメントは他の一覧に載せない(一覧の一覧はない)。過去の一覧はコンテンツハッシュ(`h/<コンテンツハッシュ>.geul`)でのみ指し、履歴は `PARENT` チェーンでつなぐ。
- 可変なアドレスは、最新の一覧アドレス(`/<Issuer>/<ドキュメント ID>/versions.geul`)一つだけだ。可変ポインタはドキュメントで作れないので、受け取った一覧の署名・`RECORDED-AT`・`PARENT` で検証する。

### 署名主体

| 署名 | 主体 | 対象 |
|---|---|---|
| ドキュメント署名 | そのドキュメントの Issuer | ドキュメントのコンテンツハッシュ ([Issuer と公表](/ja/grammar/issuer/#署名)) |
| 一覧署名 | バージョン ID を割り当てた公表元 | 一覧ドキュメントのコンテンツハッシュ |

- geul.org の公表は geul.org(GEUL Issuer)が、非公開の公表はその Issuer が、バージョン ID を割り当てて一覧に署名する。
- 著者は内容を、公表元は番号と順序を責任とする。

### 検証

- 署名はコンテンツハッシュから除かれるので、消してもハッシュはそのままだ。そのため「署名があれば確認する」ではなく、「定められた鍵の署名がなければならない」で検証する。要求する鍵は、リゾルバの信頼設定とロック記録が決める。
- リゾルバは、最後に見た一覧のコンテンツハッシュをロック記録に残す。新しく受け取った一覧の `PARENT` チェーンにそのハッシュがなければ拒否する(巻き戻し・分岐の防止)。
- ミラーと隔離ネットワーク環境は、一覧ドキュメントのチェーンを一緒にコピーする。公開鍵さえあれば、オフラインで検証できる。
- 受け取ったドキュメントは、どの出所から来ても、コンテンツハッシュで検証する。出所を信頼する必要はない。

## 依存関係の解決

- ドキュメントは、HEAD の [IMPORT-DOC](/ja/grammar/meta/import/import-doc/) で依存ドキュメントを書く。
- 新しいバージョンは、以前のバージョンとの互換を約束しない。そのためグラフ全体で、一つのドキュメントのバージョンを一つに統合しない(最小バージョン選択を使わない)。
- 各 `IMPORT-DOC` は、自分が固定した版に結びつく。同じドキュメントの複数の版が、一つのグラフに共存できる(旧法を引用した判決と現行法を引用した判決)。参照は(ドキュメント、バージョン、LOCAL ID)で解く。
- 最新(バージョン `0`)の取り込みは、解釈時点の最新の版に結びつく。時点を定めて解釈すれば、その時点で施行中の版に結びつく([ドキュメント](/ja/grammar/document/#改訂))。
- バージョン ID で固定した取り込みは再現される(バージョン ID の内容は不変で、ロック記録で検証する)。

## メディアタイプ

- GEUL ドキュメントのメディアタイプは `application/vnd.geul` だ。拡張子は `.geul` だ。
- 標準ツリーの `application/geul` に移しても、`application/vnd.geul` を引き続き受け付ける。

## 未解決の問題

- 1・2・4・16 WORD Issuer のドキュメントのうち、どこまで geul.org が直接提供し、どこから登録簿のアドレスへ送るか。そのときのステータスコード(正本 308、最新 302・307)。
- 非公開の公表・16 WORD Issuer・隔離ネットワーク環境で、バージョン ID が分岐したとき(同じバージョン ID で異なる内容)の扱い。
- テキスト表現の定義とコンテンツネゴシエーション(`Accept` によるバイナリ、テキスト、HTML ビュー)。
- ドキュメント名インデックス `documents.geul` とバージョン一覧の BIND の関係(一つに統合するか)、インデックスの署名。
- `issuers.geul` の HEAD 構成と署名・チェーン形式。ドメインのない Issuer(1・4 WORD)の名前規則、名前紛争の処理と長さの上限。
- 1 WORD Issuer も、任意でドメイン証明を経てドメイン名を使えるようにするか。
- 一覧が大きくなったときに、全体チェーンの代わりに Merkle ログ(包含・一貫性証明)へ移す時点と形式。
- 位置提供 Issuer を HEAD に書く Meta。
