## フィールド (規格ドキュメント) {#필드-규격-문서}

FIELD のドキュメント内の順序が Payload のフィールド順序である([Codec 規格ドキュメント](../codec-spec.md))。Edge の Edge Id は FIELD で宣言しない。

| 順序 | フィールド(BIND) | FIELD | 幅 | 受け取る形式(CODEC) | ENUM |
|---|---|---|---|---|---|
| 1 | `field` | #2 | レコード | `0050` LOCAL |  |
| 2 | `target` | #4 | 生値 1 WORD |  |  |

CODEC は、[FIELD](0x0BCL-field.md) 一つが受け取る Kind・Codec 一つを指定する叙述 Edge である。Codec `0x0BEL`。

[ENUM](0x0BDL-enum.md) が生値フィールドのコード値一つに意味を付けるように、CODEC はフィールドの形式を一つ付ける。Edge 一つにつき一つなので、複数を指定できる。レイアウトはデコーダに内蔵する([Codec 規格ドキュメント](../codec-spec.md))。

## レイアウト {#레이아웃}

```
TAG WORD          0000 1011 1110 LLLL
[Length 拡張 TAG]
Edge Id           LOCAL Reference レコード
フィールド        FIELD Edge を指す LOCAL Reference レコード
対象              1 WORD。000K KKKC CCCC LLLL (LLLL = 0000 正確、1111 ワイルドカード)
```

## 対象 WORD {#대상-word}

- TAG WORD の Codec の位置(セクション `KKKK` と `CCCCC`)をそのまま置く。上位 3 ビットは 0 である。`LLLL` は `0000`(正確)または `1111`(ワイルドカード)であり、それ以外の値は invalid である。
- 正確な対象(`LLLL = 0000`)を 32 ビットで書いた値が、その Codec の Codec ID である(例: LOCAL `0x0050` → `0x00000050`、COORDINATE-EARTH `0x0640`、UTF8-LANGUAGE-TEXT `0x0780`)。そのため、対象がそのままその Codec 規格ドキュメントを指す([Codec 規格ドキュメント](../codec-spec.md))。
- 偶奇のコードのペア(テキスト・バイト列)も正確なコードで指定する。偶数・奇数の両方を受け取るには二つとも置く。ペアをまとめて解釈する規則は置かない(NUMERIC `0x064L`/`0x065L` のように、ペアではない隣接コードがある)。

### ワイルドカード (`LLLL = 1111`) {#와일드카드-llll--1111}

- `LLLL = 1111` なら、`C` の値に関係なく、対象 WORD のセクション `KKKK`(32 マス)全体を受け取る。同じセクション内であれば `C` がどの値でも意味は同じである。対象のセクションとレコードのセクションが同じかどうかだけを見る。セクションをまたいでは受け取らない。
- `LLLL = 1111` なら、セクションの最初のマス(`C = 0`)を推奨する。推奨であり強制ではない。同じセクションの別の `C` でも有効である。
- Kind が複数のセクションにまたがる場合は、セクションごとに CODEC を列挙する。

| 対象 | 意味 |
|---|---|
| `000F`·`020F`·`040F` | 任意の Reference (セクション 0~2、REFERENCE-ISSUER を含む) |
| `060F`·`080F` | 任意の Value (セクション 3・4、VALUE-ISSUER を含む) |
| `0A0F`·`0C0F`·`0E0F`·`100F`·`120F`·`140F`·`160F`·`180F`·`1A0F` | 任意の Edge (セクション 5~13、EDGE-ISSUER を含む) |
| `1C0F`·`1E0F` | 任意の Meta (セクション 14・15) |

- Reference のプレースホルダ(`0x000L~0x002L`)は `LLLL = 1111` と一致しない(`000F` は ABSENT・UNKNOWN-VALUE・NO-VALUE を受け取らない)。一方、Value `0x060L`(BOOL)・Edge `0x0A0L`(REFERENCE-NODE)のように、セクションの最初のマスが割り当て済みのセクションも、`LLLL = 1111` がそれを含む(BOOL だけを受け取るには `LLLL = 0000` の `0600`)。
- `LLLL = 1111` の対象は規格ドキュメントを指さない。
- 量化を問わない、またはまとまりは、CODEC の列挙(`LLLL = 0000`)でのみ書く。例: WIKIDATA-QID の量化を問わない指定は `0140`、`0150`、`0160`、`0170`、`0180` の五つである。
- Reference の 5Q 体系のコードには量化が含まれている。対象は量化まで正確に指定する。複数の Quantifier を受け取るには CODEC を複数置く。REFERENCE-ISSUER の量化は Issuer ドキュメントが定める。

### プレースホルダ (対象 `0000`、`0010`、`0020`) {#자리-표지-대상-0000-0010-0020}

[プレースホルダ](../slot-marker.md)は、Reference セクション 0 の最初の三マス `0x000L~0x002L` に割り当てた 1 WORD レコードのまとまりである。量化はない。

| 対象 | プレースホルダ | 意味 |
|---|---|---|
| `0000` | ABSENT | 記さない。そのフィールドは省略可能なフィールドである |
| `0010` | UNKNOWN-VALUE | 不明。値があるという断言を受け取る |
| `0020` | NO-VALUE | 無。値がないという断言を受け取る |

- **受け入れ規則:** プレースホルダは、そのフィールドの CODEC 一覧に同じ WORD が正確な対象としてある場合にのみ有効である。ワイルドカードと、CODEC のないレコードフィールド(「任意のレコード」)は、プレースホルダを受け取らない。HEAD・BODY のレコードの位置、Edge Id の位置のプレースホルダは invalid である。
- プレースホルダの対象だけがある一覧(常にプレースホルダ)は invalid である(`0000` だけがある一覧の規則の一般化)。`LLLL = 1111` の対象や正確な対象と一緒に使う(`000F`·`020F`·`040F` + `0000` = 任意の Reference または省略)。
- 生値フィールドにはプレースホルダの対象を置けない。生値は TAG がなく幅が決まっているので、1 WORD のプレースホルダが入る場所がない。
- プレースホルダの意味は、それを受け取る Codec 規格が定める。

### 省略可能なフィールド (対象 `0000`) {#선택-필드-대상-0000}

- レコードフィールドの CODEC 一覧に対象 `0000` を置くと、そのフィールドは**省略可能なフィールド**になる。省略するときは、その位置に WORD `0x0000` 1 WORD を書く。この 1 WORD のレコードがプレースホルダ ABSENT(記さない)である。
- `0x0000` は Reference、Codec `0x000L`(Reserved)、`LLLL = 0000`(全体 1 WORD)である。ほかのレコードと重ならず、規格を知らないデコーダも 1 WORD のレコードとして読み飛ばす。
- 省略可能なフィールドも位置は常に占める。省略するときは必ず `0x0000` を書き、位置を空けない(後ろのフィールドでも同じ)。そのため、レコード一つの表記は一つだけであり、分解は位置だけで定まる。省略可能なフィールドの位置と個数、ほかのフィールドと一覧が重なるかどうかに制約はない。
- ABSENT は省略可能なフィールドの位置でのみ有効である。HEAD・BODY のレコードの位置、必須フィールドの位置、Edge Id の位置の `0x0000` は invalid である。
- 省略は「値がない」ではなく「記さない」である。世界について何も断言しない。「値がない」は NO-VALUE(`0020`)で書く。省略が何を意味するか(例: TAG の対象がなければこのバージョン)は、各形式の仕様が定める。

## 解釈と有効性 {#해석과-유효성}

- フィールドは同じドキュメントの FIELD Edge である。一つのフィールドに同じ対象を二度置かない。
- **レコードフィールド(幅 0)**: CODEC がなければ、プレースホルダを除く任意のレコードを受け取る。一つ以上あれば閉じた一覧である。そのフィールドのレコードは、Kind・Codec(Reference は Quantifier を含む)が一覧のいずれかでなければならず、そうでなければそのレコードは規格に従っていない。ENUM が開いた一覧であることとは異なる。
- **生値フィールド(幅 n ≥ 1、または残り `0xFFFF`)**: CODEC は正確な対象を一つだけ置く(ワイルドカード不可)。その生値は、TAG を除いたその Value の Payload である。Kind・Codec は CODEC が、Length は FIELD の幅が与える。偶奇のコードは、指定したコードがバイト数の偶奇を定める。生値がその Value の規則(長さを含む)に従わなければ、そのレコードは規格に従っていない。
- プレースホルダは、一覧の正確な対象としてのみ照合する。省略可能なフィールド(対象 `0000`)の位置に `0x0000` が来れば省略である。それ以外のレコードは、プレースホルダの対象を除いた一覧で照合する。
- 生値フィールドに CODEC と ENUM を一緒に置ける。CODEC は形式、ENUM はコード値の名前である(例: rank を UNSIGNED-INTEGER とし、0・1・2 を ENUM とする)。
- CODEC の Edge Id に BIND で名前を付けられるが、必須ではない。
- 「Reference または Value」のフィールドは CODEC 5 個(`000F`、`020F`、`040F`、`060F`、`080F`)で書く。

## 長さ {#길이}

```
全体 = 1 + N_len + N_id + N_field + 1 WORD   (Edge Id・フィールドが LOCAL 1 WORD ID なら 6 WORD)
```

## 例 {#예시}

LABEL 規格ドキュメント `0x00000000/codecs/0x00000A40/` で、Object フィールド(FIELD #3)が UTF8-LANGUAGE-TEXT(偶数・奇数)と LOCAL を受け取る。Edge Id 7~9。

```
0BE5 0051 0007 0051 0003 0780
0BE5 0051 0008 0051 0003 0790
0BE5 0051 0009 0051 0003 0050
```

- TAG `0BE5`(Edge、Codec `0x0BEL`、`LLLL = 0101`、6 WORD)、Edge Id `0051 0007`、フィールド `0051 0003`、対象 `0780`。
