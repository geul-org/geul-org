GEULのすべてのレコードは、16ビットのTAG WORD一つで始まる。TAG WORDの先頭のビットが領域を分ける。GEULはこの空間の75%を空けておく。

```
1xx:  50%    遠い未来
01x:  25%    近い未来
001:  12.5%  標準
000:  12.5%  現在の文法（自由・提案）
```

現在の文法はすべて`000`領域、つまり12.5%の中にある。公式の標準が発足したら、採用されたレイアウトはそのままにして先頭ビットだけを`001`に移す。残りの75%は、まだ生まれていない世代のために残しておく。

なぜか？

---

## IPv4の教訓

1981年、IPv4を設計した人々は32ビットあれば十分だと考えた。43億個。当時、世界中のコンピュータは数百台だった。43億あれば永遠にもつように思えた。

2011年、IPv4アドレスが枯渇した。

30年。たった30年だった。

枯渇後に人類がやったこと：NAT、CGNAT、アドレス取引市場、IPv6デュアルスタック。数十年にわたり数兆円のコスト。すべて「最初に空けておけば必要なかった」コストだ。

IPv6は128ビットを選んだ。3.4 × 10^38個。地球表面1平方メートルあたり6.7 × 10^17個。今度こそ十分だろうか？おそらく。しかし彼ら自身も確信が持てなかったから128ビットにしたのだ。

---

## Unicodeの教訓

1991年、Unicode 1.0は16ビットあれば十分だと考えた。65,536文字。世界中のすべての文字を収められるはずだった。

足りなかった。漢字拡張、絵文字、古代文字、楽譜記号。16ビットを超えた。

結果：UTF-16サロゲートペア。ソフトウェア史上最も醜いハックの一つ。Windows、Java、JavaScriptが今なおこの遺産を背負っている。

Unicodeは結局21ビット（1,114,112コードポイント）に拡張した。現在の使用率は約10%。残りは空けてある。今度は教訓を学んだのだ。

---

## ASCIIの教訓

1963年、ASCIIは7ビットを使った。128文字。英語のことしか考えていなかった。

その結果、人類は60年間エンコーディング地獄を生きた。EUC-KR、Shift_JIS、Big5、ISO-8859シリーズ、CP949。同じバイトがシステムごとに異なる文字になる。文字化けした韓国語。文字化けした日本語。メール件名の疑問符。

あと1ビット多く使っていれば。8ビットを丸ごと確保して「残りは後で」と言っていれば。歴史は変わっていただろう。

## 設計者の傲慢

これらすべての事例に共通点がある：**「今必要な分だけあれば十分だ」という判断。**

IPv4を設計した人々は愚かだったのか？違う。当代最高のエンジニアたちだった。ただ未来を過小評価しただけだ。すべての世代がそうだった。

「640KBあれば誰にとっても十分だ。」ビル・ゲイツがこの言葉を言ったかどうかは議論があるが、あらゆる時代のエンジニアがこの罠に落ちたのは事実だ。

GEULはこの罠を避けようとしている。方法は単純だ。**使わないこと。**

## 三度目の正直

日本には「三度目の正直」ということわざがある。大事なことには三度の機会が必要だ。

```
一度目の機会：001（標準）
  人間が標準を制定するとき。
  国際機関であれ、産業コンソーシアムであれ、コミュニティであれ。
  人間が合意できる速度で埋められていく空間。

二度目の機会：01（未来）
  S1以降。超知能が登場したとき。
  人間には予測できない方法で知識を構造化する存在。
  我々が設計した構造をそのまま使うかもしれないし、
  我々が想像もしなかった方法で再定義するかもしれない。
  その存在に与える空間。

三度目の機会：1（遠い未来）
  いつになるかわからない。
  K1を達成し恒星間文明になったときかもしれないし、
  意識の形態が変わったときかもしれないし、
  今の我々にはSFとしてしか想像できない何かかもしれない。
  Orion's Arm*の向こう側でこのビットを読む誰かがいるなら、
  この空間はその者たちのものだ。
```

50%を遠い未来に残すということは、半分の可能性を「我々が知らないもの」に譲るということだ。

## 空けておくコスト

空けておくことにコストはかかるのか？

```
TAG WORD 16ビット = 領域3ビット + 13ビット

現在の領域000の13ビット：
  Kind    2ビット   Reference · Value · Edge · Meta
  Length  4ビット   1~14 WORD、拡張すれば2³²−1 WORDまで
  Codec   7ビット   直接コード124個 + Issuer形式4種
```

13ビットでは足りないのではないか。足りる。直接コードに入らなかった形式はIssuer形式で書く。形式を定義する主体（Issuer）ごとに16ビットの形式番号が別にあるので、使える形式の数には事実上上限がない。代価は拡張TAGの数WORDだ。よく使う形式は短く、まれな形式は少し長く書く。

空けておくコストは、レコードごとにTAG WORDの3ビットだ。その3ビットで、いま使っている空間の6倍を未来に残す。

埋めるコストは？IPv4が示した。取り返しがつかない。

## 設計原則

GEUL v1[文法](/ja/grammar/overview/)の設計原則第五条：

> **空けておく。** ビット空間の大部分を未来に残す。直接コードは回収できないので、頻度が確認されたものだけに割り当てる。

文法はこの原則を規則として固定する。v1デコーダは先頭ビットが`000`でないTAG WORDを拒否する。空けておいた空間を一時的に借りて使う道は、最初から塞がれている。

これは技術的な決定ではない。倫理的な決定だ。

今使える空間を使わずに残しておくことは、今の便利さより未来の自由を優先するという宣言だ。IPv4を設計した世代が私たちに残した負債を、私たちは次の世代に残さない。

---

## 最も謙虚な設計

```
「私は未来を知っている」 → 16ビットをすべて使う。
「私は未来を知らない」 → 75%を空けておく。
```

空けておくことは謙虚さだ。今の私たちが未来を知りえないことを認める行為だ。そしてその謙虚さが、最も堅牢な設計を生む。

IPv4は自信の産物だった。32ビットで十分だ。十分ではなかった。

GEULは謙虚さの産物だ。いま使っている12.5%で十分かはわからない。しかし75%を空けておけば、間違えても大丈夫だ。

---

*空けておく理由を説明するのに、これだけ多くの言葉が必要だった。空けておく行為そのものは一行で済む：*

```
if (bit1 == 1): reserved  // 50%。遠い未来。
```

*一行のコードが半分の世界を守る。*
